# 002：让分页列表读到新增并持久保存的订阅

状态：待实施；本次只建立任务。

## 本次要做什么

- **本次想实现什么：** 建立可本地启动的第一条可用流程：分页查看 → 弹窗新增 → 真实保存 → 重新读取并展示。
- **想要什么：** 浏览器页面、Python API 与现有 JSON 位置连通，刷新及重启保留数据；同时提供基本页面导航和只读设置页。
- **不想要什么：** 本项不做详情和编辑，交给 003；不以样例数据替代保存链路，不扩展可编辑设置。共通排除范围见 [Spec](../specs/subscription-management.md#本次要做什么)。
- **依据：** [现状与工作决定](../specs/subscription-management.md#现状与工作决定)、[整体技术方案](../specs/subscription-management.md#整体技术方案)、[界面职责](../specs/subscription-management.md#界面与待制作设计)。

## 局部方案

建立最小本地启动入口、同源静态页面与 API，补齐存储模块的读取及原子写入，贯通列表读取和新增调用；本项负责共同请求校验、错误映射和表单基础，供 003 复用。公共字段、错误、分页及写入行为直接执行 Spec，不在本任务另设合同。

列表中的详情导航位置按设计保留，实际可用行为由 003 交付；本项完成不代表全期完成。设置页面按 Spec 只展示实际配置。更新项目 README 的启动说明与 UTC 配置描述，消除已记录的文档冲突；不要改动原始需求。

## 关联与依赖

- [001](001-desktop-design.md) 提供界面设计，只有界面定稿依赖该交付；共同契约、服务、存储和普通启动配置可先推进。
- 本项先建立共享服务、存储、根导航与表单基础；[003](003-detail-edit.md) 复用并扩展，交接时给出实际入口与运行说明，不新建平行数据源。

## 预期结果

负责 [Spec 完成标准](../specs/subscription-management.md#完成标准) **C1–C7、C11，以及 C12 的新增分支**：可分页读取真实记录；新增后第一页可见、刷新及重启仍保留；校验、损坏文件、写入失败及结果不明有正确反馈。界面与 API 的提交结果一致，设置展示当前真实配置。

将已完成范围和剩余事项交给整体负责人；必要验证随本期整体交付收尾，不另立逐层测试任务或预填验证结果。
