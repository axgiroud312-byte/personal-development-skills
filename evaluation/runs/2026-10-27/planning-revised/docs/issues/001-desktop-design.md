# 001：交付紧凑中文桌面原型与设计依据

状态：待实施；本次只建立任务。

## 本次要做什么

- **本次想实现什么：** 形成后续实现可直接引用的完整桌面交互与视觉依据。
- **想要什么：** 覆盖列表、详情/编辑、设置、新增弹窗及关键状态，突出金额与续订日期；交付可审阅原型和实际采用的 Token/组件规则来源。
- **不想要什么：** 不接入真实 API、不实现应用；共通排除范围见 [Spec 本次要做什么](../specs/subscription-management.md#本次要做什么)。
- **依据：** [界面与待制作设计](../specs/subscription-management.md#界面与待制作设计)、[共同字段契约](../specs/subscription-management.md#共同字段契约)、[错误约定](../specs/subscription-management.md#错误约定)。

## 局部方案

让原型串起新增、查看详情、编辑和返回原列表位置，覆盖空集合、分页、加载、字段错误、保存失败与结果不明等已有约定状态。样例数据只用于设计演示，不标为已持久化结果。

项目尚未提供设计产物路径或格式；当前只约定产物类型，制作时沿用届时项目或可用制作技能的交付约定。不要为本任务另造一套原型文件名或 Token 格式；完成后将真实来源链接补入 Spec，再供实现任务引用。

## 关联与依赖

没有前置实现依赖。002 的 API 与存储部分可并行推进；002、003 的界面定稿使用本项成果。字段或业务规则发现问题时先更新 Spec，不能在原型中暗改合同。

## 预期结果

审阅者可沿原型走完 [Spec 界面流程](../specs/subscription-management.md#界面与待制作设计)，辨认每个关键状态的提示与恢复动作，并定位实际 Token/组件规则来源。002、003 接手时有可访问的设计链接和明确页面状态；原型交付不代表 [完成标准](../specs/subscription-management.md#完成标准) 中真实保存行为已验收。
