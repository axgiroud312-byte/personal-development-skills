# 订阅查看、新增与编辑规格

状态：方案已整理，尚未实施。范围：本地单人使用的近期交付。

## 本次要做什么

- **本次想实现什么：** 在桌面上查看、新增和编辑自己的订阅，清楚看到金额与下次续订日期；新增或修改后重新读取真实数据，刷新仍保留。
- **想要什么：** 紧凑中文界面，包含分页列表、详情、设置和新增弹窗；详情可返回原列表位置；表单、API、存储使用一致的字段及错误含义。
- **不想要什么：** 手机端、账号、收费、日历同步、第三方订阅抓取、技术栈替换，以及当前范围之外的归档、删除、自动扣款、续订周期推算和通知。
- **依据：** [本次需求](../request.md)、[项目 README](../../README.md)、[现有存储常量](../../src/store.py)。需求决定目标，代码用于判断已存在的实现。

## 业务对象与规则

唯一持久业务对象是**订阅条目**，均归本机唯一使用者所有；本期没有用户、组织或权限关系。服务创建稳定 ID，名称可以重复。生命周期只有“新增并保存”和“编辑同一条目”；查看与分页不改变数据。

`renewal_date` 表示使用者填写的下一次续订日期。允许填写过去的日期，以便保留尚未更新的实际记录；系统不替使用者宣告已经续订，不由金额或日期生成付款记录。金额为非负数，零金额允许保存。

归档整体属于后续范围。“归档后是否仍允许编辑历史条目”尚未决定，也没有此前聊天确认的规则。本期不添加归档状态或归档入口；这一选择只影响未来归档能力，不阻塞当前查看、新增和编辑。

## 整体技术方案

### 模块与数据流

页面负责交互、表单输入和结果展示；本地 API 负责规范化、权威校验及响应；存储模块负责从项目内 JSON 文件读取、更新与安全替换。页面和 API 由同一个本地服务提供，不需要跨域设置或独立前端服务器。

新增与编辑沿用一条流程：表单准备字段 → API 规范化并校验 → 存储写入完成 → 返回已保存条目 → 页面重新读取相关列表或详情。保存失败时不返回成功、不关闭表单、不在列表插入伪记录。若写入已经成功但后续读取失败，应分别提示“保存成功”和“读取失败，可重试读取”，避免引导用户再次创建同一条记录。

服务负责所有写入并串行处理读改写，避免两个请求覆盖彼此；本期不支持多个进程同时编辑同一文件或运行时外部编辑该文件。提交期间禁用重复提交，响应不明时保留输入并先提供重新读取核对入口，不自动重发新增请求。

### 共同字段契约

以下是表单领域值、API 条目和持久记录的唯一公共定义。界面标签可以是中文，但请求、存储和错误的 `field` 使用表内名称；输入时的金额文本仅为界面呈现，不另立一套 API 字段。

| 字段 | 类型、来源与规则 | 表单、API 和存储的衔接 |
| --- | --- | --- |
| `id` | 服务生成的 UUID 字符串，创建后不变 | 列表和详情使用同一 ID；创建、编辑请求体均不含该字段，编辑由 URL 指定 ID。 |
| `name` | 字符串，去除首尾空白后 1–100 个字符 | 前后端按同一规则处理，保存规范化后的值；不要求唯一。 |
| `amount_cents` | 非负整数，最大 `9007199254740991`，保证 JavaScript 整数精度 | 按既有“分”字段，以该条目币种的百分之一为单位。界面金额最多两位小数，用十进制字符串换算为整数，避免浮点乘法取整；超精度输入报错，不静默舍入。 |
| `currency` | 三位大写英文字母，默认 `CNY`；输入去空白并转大写 | 编辑可修改，金额旁明确显示币种。本期仅校验代码格式，不提供汇率换算、跨币种汇总或特殊币种小数位适配。 |
| `renewal_date` | 真实存在的公历日期，格式 `YYYY-MM-DD` | 请求和 JSON 保存相同字符串，界面按日历日期显示；不附加时间或 UTC 偏移。 |

四个可编辑字段在创建和完整更新时均必填；前端为新表单填入默认币种，API 不以缺失字段替代用户输入。除 `id` 外不新增系统字段。API 拒绝未知字段，避免“已提交但未保存”的错觉。

API 校验是最终依据。前端的输入校验与 API 使用同一规则及错误代码；服务端返回的字段错误直接映射到对应输入。字段顺序沿用 `src/store.py` 中的 `FIELDS`，实现时不得再建立含义不同的请求或存储模型。

### API 与分页

响应采用 JSON。下表中的 `subscription` 指上节完整条目，错误统一使用下一节的结构。

| 方法与路径 | 输入 | 成功结果 |
| --- | --- | --- |
| `GET /api/subscriptions?page=1` | `page` 为正整数，缺省为 1；每页固定 20 条 | `200`，`{items, total, page, page_size: 20}`。 |
| `GET /api/subscriptions/{id}` | 稳定 ID | `200`，`{subscription}`。 |
| `POST /api/subscriptions` | 四个可编辑字段 | 写入完成后 `201`，`{subscription}`。 |
| `PUT /api/subscriptions/{id}` | 四个可编辑字段的完整更新 | 写入完成后 `200`，`{subscription}`，保留原 ID。 |
| `GET /api/settings` | 无 | `200`，`{time_zone: "UTC", storage_mode: "local"}`，来自当前实际配置。 |

列表顺序采用文件中的稳定条目顺序：新增插入开头，编辑保持原位置，不添加排序字段。新增成功后读取第一页，确保新记录可见。有效但超过末页的 `page` 归一到末页；空集合返回 `items: []`、`total: 0`、`page: 1`。翻页和刷新均从 API 获取数据，不将原型样例当作正式数据。

列表页码保留在 URL 中，进入详情时携带返回位置；从详情返回恢复该页码并重新读取。直接访问详情而没有返回位置时，回到第一页。编辑成功后重新读取详情；回列表时按原页码读取更新后的记录。

### 错误约定

统一结构为 `{error: {code, message, field?}}`。`message` 是可直接显示的中文说明，`code` 是稳定含义；字段校验错误必须带上述字段名。前端按 `code` 和 `field` 处理，不解析提示文本来判断错误。

| 错误代码 | HTTP 状态 | 含义与页面行为 |
| --- | --- | --- |
| `INVALID_REQUEST` | 400 | JSON 无法解析、请求体不是对象或出现未知字段；显示请求问题，保留输入。 |
| `INVALID_FIELD` | 422 | 缺失或不符合共同字段契约；标出对应字段并保留其余输入。 |
| `INVALID_PAGINATION` | 400 | 页码不是正整数；提示并提供回到第一页的操作。 |
| `NOT_FOUND` | 404 | 查看或编辑的 ID 不存在；明确提示记录不存在并可返回列表，不伪装保存成功。 |
| `STORE_READ_FAILED` | 500 | 文件不可读、JSON 损坏或记录结构无效；显示加载失败并可重试，禁止当作空集合覆盖。 |
| `STORE_WRITE_FAILED` | 500 | 新增或编辑未完成持久化；保留原记录和表单输入，允许修复后重试。 |

连接中断或响应无法读取属于客户端可观察的请求结果不明，不能捏造为 API 的“保存失败”。读取操作可直接重试；写入操作按“模块与数据流”中的核对行为处理。

### JSON 读写与兼容

当前没有可迁移的数据文件，采用 UTF-8 JSON 数组，每项恰含共同字段契约中的五个字段。缺少文件表示空集合，首次有效新增时创建目录和文件；存在但损坏、含重复 ID 或结构不符的文件属于读取失败，不能静默清空、修复或转换。

每次更新先读取有效数据，在内存完成修改，再写同目录临时文件并原子替换正式文件。只有替换完成才报告成功；替换前失败应保持原文件，清理本次临时文件。不会用浏览器本地存储作为正式数据源。进程重启后的读取必须来自这一文件；本期不承诺断电级恢复或外部并发写入。

### 界面与待制作设计

界面使用中文、紧凑的桌面布局，金额始终连同币种显示，续订日期在列表与详情中容易定位。近期页面职责如下：

- **列表：** 展示条目核心信息、页码和翻页操作；提供进入详情与打开新增弹窗的入口，并覆盖加载、空集合和读取失败状态。
- **新增弹窗：** 编辑共同契约中的四个输入，支持取消、校验提示、提交中和失败后保留输入；成功后关闭并读取第一页。
- **详情与编辑：** 展示同一条目的完整内容；在详情内进入编辑状态，取消恢复读取值，保存后呈现真实保存结果；返回列表保留页码。
- **设置：** 作为独立可访问页面，首期只读展示当前时区与本地存储方式，并提供返回列表的导航。未指定可编辑设置项，本期不增加时区切换、存储迁移或偏好系统；不放无效开关。

需要后续交付的设计产物是**可审阅的桌面完整原型**以及**实际采用的 Token/组件规则来源**，覆盖上述页面与关键状态。当前项目未给出可引用的设计交付路径或格式，本方案只约定产物类型，不另造原型文件名或 Token 格式；制作时沿用项目届时已定或可用制作技能的交付约定，交付后在此补实际链接。所有设计产物当前均未制作。

## 完成标准

| 编号 | 场景与条件 | 操作 | 预期可观察结果 |
| --- | --- | --- | --- |
| C1 | 首次启动，无数据文件 | 打开列表及设置页 | 列表显示真实空状态；设置显示实际 UTC 和本地存储方式；可在页面间导航。 |
| C2 | 有效新增 | 在弹窗填写四个字段并提交 | 真实写入成功后关闭弹窗，重新读取第一页并看到新记录；金额、币种、日期与提交值一致。 |
| C3 | 新增后刷新或重启 | 刷新页面，再重启本地服务读取 | 同一 ID 的记录仍存在，数据来自项目内 JSON 文件。 |
| C4 | 至少 21 条记录 | 前后翻页、刷新、访问超过末页的有效页码 | 每页最多 20 条，稳定顺序、总数与实际页码正确，无重复或遗漏；末页按分页约定归一。 |
| C5 | 表单或请求不合法 | 提交空名称、过精度金额、无效日期或无效页码 | 按共同错误约定显示准确错误；字段错误保留输入，存储不被修改。 |
| C6 | 文件不可读或损坏 | 读取列表或尝试提交 | 显示 `STORE_READ_FAILED`，不伪装空列表，不覆盖原文件；恢复后可重新读取。 |
| C7 | 写入失败或结果不明 | 触发无法写入，或提交响应中断 | 已知写入失败按 `STORE_WRITE_FAILED` 保留原数据与输入；结果不明则提供重新读取核对，不自动重发或宣告成功。 |
| C8 | 从非第一页进入详情 | 查看条目并返回 | 详情 ID 与选中条目一致，金额、币种和日期完整；返回原页码并读取最新数据。直接访问详情也可回第一页。 |
| C9 | 编辑已存在条目 | 修改字段并保存，再刷新和返回列表 | ID 与列表位置保持不变，详情、列表和文件一致，刷新或重启后修改仍保留。取消编辑不写入。 |
| C10 | 编辑输入错误或记录不存在 | 保存不合法修改，或访问/修改不存在的 ID | 分别显示字段错误或 `NOT_FOUND`；失败不损坏原数据，输入保留或提供返回列表的可用出口。 |
| C11 | 日期及展示边界 | 保存过去日期、不同币种代码及零金额 | 合法值可保存，金额含币种，日期不被时区移动或自动推进；中文界面按交付设计紧凑呈现。 |
| C12 | 保存成功后的重读失败 | 已保存响应成功，随后列表或详情读取失败 | 明确区分保存成功与读取失败，可重试读取；不要求用户再次创建或保存相同内容。 |
