# Issue 002：实现现有 JSON 路径的可靠持久化

- 状态：待开始
- 优先级：P0
- 依赖：[001](001-contract-and-decisions.md)
- 关联：[技术方案第 5–6 节](../technical-plan.md)

## 问题与目标

`src/store.py` 只有路径与字段常量，不能真正保存订阅。本任务在现有 `data/subscriptions.json` 位置实现读取、新增和更新，保证成功响应对应实际写入。

## 工作范围

1. 按定稿契约解析相对于项目根目录的存储路径，并统一有效时区。
2. 明确首次缺文件的空集合行为，以及首次有效写入时创建目录和文件的行为。
3. 实现完整记录加载、按 ID 查询、新增和更新；新增生成唯一 ID；更新保持 ID 和列表位置。
4. 校验已有文件结构和记录；损坏 JSON、重复 ID 或字段缺失返回存储错误，不清空原文件。实施时若已有真实数据，先检查兼容性。
5. 同一服务实例串行处理写入；在同目录写临时文件并原子替换；失败保留原文件并向上层报告明确错误。
6. 新增记录按定稿顺序插入，不新增归档、删除或历史版本字段。

## 验收条件

- [ ] 从不同工作目录启动仍指向同一项目数据文件。
- [ ] 首次空环境可新增；再次加载和重启进程后仍得到同一 ID 与数据。
- [ ] 更新单条记录不改变 ID，不改变其他记录，也不改变既定位置。
- [ ] 非法数据不能落库；读取损坏文件与读取空集合的结果可区分。
- [ ] 模拟写入失败后，原文件仍可读取；调用者收到失败而不是成功。
- [ ] 同一服务实例内连续或并发新增不会互相覆盖，ID 不重复。

## 验证建议

使用临时测试目录覆盖新建、重读、更新、损坏文件和失败写入。验证不得直接修改真实用户数据；只为持久化风险编写必要的定向测试。

## 不包括

数据库、自动备份系统、多进程同时写入支持、归档、删除和数据迁移工具。
