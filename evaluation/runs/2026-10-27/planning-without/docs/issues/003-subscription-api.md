# Issue 003：提供本地订阅查询、新增和编辑 API

- 状态：待开始
- 优先级：P0
- 依赖：[001](001-contract-and-decisions.md)、[002](002-json-persistence.md)
- 关联：[技术方案第 4–5 节](../technical-plan.md)

## 问题与目标

当前没有 API。建立界面访问数据的唯一应用边界，让列表、详情与保存共享权威校验和错误含义，并连接真实 JSON 存储。

## 工作范围

1. 按定稿传输方式实现列表、详情、新增、编辑四个操作；HTTP 方式可采用方案中的接口路径。
2. 列表返回稳定分页数据与总数；校验页码和每页数量，定义越界与空集合行为。
3. 新增拒绝客户端指定 ID；编辑只允许四个业务字段，拒绝空更新、未知字段和修改 ID；对合并后的完整记录校验。
4. 保存操作等待存储成功后才返回成功记录；将校验、记录不存在和存储错误映射为统一协议。
5. 本地服务仅面向本机使用，提供与选定桌面入口兼容的启动和调用方式。

## 验收条件

- [ ] 四个操作使用真实持久化层，未用固定示例或内存假数据替代。
- [ ] 新增后能通过独立列表和详情读取同一 ID；编辑后读取到更新值。
- [ ] 多页数据的总数、切片与顺序正确；空集合、越界页和非法参数符合契约。
- [ ] 直接调用接口提交非法金额、日期、币种或未知字段不能绕过校验。
- [ ] 不存在 ID 返回 `NOT_FOUND`；读写失败不返回成功，不泄漏内部异常为用户提示。
- [ ] 记录字段与文件字段一致；分页元数据和错误对象不会落入订阅记录。

## 验证建议

针对四个操作各验证一条真实成功链路，再验证关键错误映射；与 002 共用隔离数据，避免重复测试存储内部实现。

## 不包括

账号鉴权、云服务、公网部署、删除、归档、日历同步和批量操作接口。
