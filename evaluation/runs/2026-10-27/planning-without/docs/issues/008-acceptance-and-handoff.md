## 问题与目标

需要证明“能看到界面”和“数据确实保存”已组成完整链路。对本期最重要的真实保存、刷新重读、编辑和返回分页场景进行验收，并写明实际启动方式。

## 工作范围

1. 在隔离数据目录执行本地端到端验收，记录使用的时区、支持币种和启动方式。
2. 验证新增 → JSON 落盘 → 列表重读 → 刷新 → 重启服务；再验证详情编辑 → 重新读取 → 返回原页 → 重启。
3. 用超过一页的数据覆盖分页、空集合、越界页、详情直达和返回行为。
4. 定向覆盖金额/日期校验、损坏存储、写入失败和保存后读取失败，复用已有测试结果，不为低风险布局补造大量测试。
5. 更新 README，说明依赖、启动命令、有效时区、项目根目录下的存储位置、单服务实例限制和本期能力边界。
6. 在 `docs` 中记录验收结果及尚存限制；只有有证据通过的条件才勾选完成。

## 验收条件

- [ ] 新增和编辑结果在刷新及服务重启后均保留；前端、API 和文件内容一致。
- [ ] 时区已统一，日期不发生 UTC 换算导致的前后一天偏移。
- [ ] 分页顺序和总数正确，详情返回保留原页码，新增后读取第一页可见新记录。
- [ ] 错误场景不显示虚假成功、不覆盖损坏数据；用户能分辨“未保存”和“已保存但未刷新”。
- [ ] 列表、详情、设置和新增弹窗都可达，中文金额与日期清楚。
- [ ] README 与实际运行行为一致；有简明可复现的验收记录。
- [ ] 没有实现归档、删除、手机端、账号或其他排除功能。

## 不包括

远端发布、创建远端 Issue、正式分发安装包（除非 001 明确纳入）、性能压测、全平台兼容测试或后续功能扩展。
