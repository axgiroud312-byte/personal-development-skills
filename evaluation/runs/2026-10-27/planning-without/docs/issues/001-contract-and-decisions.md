## 问题与目标

项目只有 Python 常量，没有前端、API 或读写实现。README 与代码的时区冲突，桌面载体和金额精度也未确定。先形成可执行的一份契约，避免表单、API、文件各自定义字段或错误。

## 工作范围

1. 记录时区冲突及最终取值；建议采用 README 的 `Asia/Shanghai`，同时明确日期是 `YYYY-MM-DD` 日历日期。
2. 确认桌面交付载体、本地服务的启动方式和最小必要依赖；保留现有 Python 与 JSON 方向，不进行无关技术栈更换。
3. 确定支持币种、两位小数限制、是否允许零金额、金额和名称长度上限。若需要不同币种精度，先说明与 `amount_cents` 的契约冲突并定稿，不能静默混用单位。
4. 冻结五个字段、只读 ID、必填项、金额转换、日期校验、编辑合并规则及存储顶层结构。
5. 定稿列表分页与稳定顺序、接口成功结果、统一错误码和中文字段提示。
6. 确认设置页本期仅展示有效配置，还是确有可修改项；没有明确项时按展示页规划。

## 交付物

在项目 `docs` 中补充确定后的契约及决策记录，并同步更新技术方案中已解决的待定项。记录依据和未决项，不能把建议写成用户历史确认。
