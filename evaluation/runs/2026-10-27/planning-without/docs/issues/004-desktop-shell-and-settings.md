# Issue 004：建立桌面入口、页面路由与设置页

- 状态：待开始
- 优先级：P1
- 依赖：[001](001-contract-and-decisions.md)
- 关联：[技术方案第 2–4、7 节](../technical-plan.md)

## 问题与目标

当前没有正式界面。按已确认的桌面载体建立可启动入口，让列表、详情和设置页面都有明确路由与访问方式，为后续功能接入提供基础。

## 工作范围

1. 使用 001 确认的依赖和启动方式建立桌面入口，不自行替换技术栈或增加另一套后端。
2. 建立列表、按 ID 的详情、设置三个页面及导航；详情直达和刷新可恢复目标记录。
3. 定义列表页码在 URL 或等价导航状态中的保存方式，为详情返回保留页码。
4. 设置页展示真实有效时区和 `data/subscriptions.json` 的存储说明；若 001 未确认可修改项，不新增可写设置。
5. 建立供后续页面使用的 API 调用及统一错误提示入口；以桌面中文、紧凑和金额/日期可读为后续设计约束。

## 验收条件

- [ ] 按说明可启动桌面入口，列表、详情和设置路由可达。
- [ ] 直接打开或刷新详情不会依赖先前列表的内存数据。
- [ ] 导航能够携带并恢复列表页码；无来源页码时有确定的第一页回退。
- [ ] 设置页显示的时区与实际运行配置一致，存储说明与真实路径规则一致。
- [ ] 未增加手机端版本、账号、收费功能或未经确认的设置项。

## 不包括

本次规划阶段的视觉稿、原型、列表数据功能、新增和编辑业务逻辑。启动本 Issue 实施时再进行必要的界面设计。
