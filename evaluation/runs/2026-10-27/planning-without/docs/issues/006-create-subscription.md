# Issue 006：实现新增弹窗与保存后列表重读

- 状态：待开始
- 优先级：P1
- 依赖：[003](003-subscription-api.md)、[004](004-desktop-shell-and-settings.md)、[005](005-list-and-pagination.md)
- 关联：[技术方案第 4.2、5、7、9 节](../technical-plan.md)

## 问题与目标

通过新增弹窗填写订阅并真正保存。成功后列表必须再次读取并显示新记录，不能仅在前端临时追加数据。

## 工作范围

1. 弹窗编辑 `name`、`amount_cents`、`currency`、`renewal_date`；金额控件显示值按契约转换，ID 由服务生成。
2. 用统一字段名与规则做预校验，并将服务端字段错误映射回对应控件。
3. 提交等待期间防止重复点击；失败保留输入，可修改或重试；关闭未保存表单时避免无意丢失输入。
4. 收到持久化成功响应后关闭弹窗，切到第一页并重新请求列表，确认服务返回的新记录可见。
5. 分开处理保存失败与保存后列表重读失败；响应丢失时提示结果待核对，先重读后决定是否再次提交。

## 验收条件

- [ ] 合法提交生成唯一记录，API 返回的 ID 与 JSON 中记录一致。
- [ ] 从任意列表页新增后，都能通过第一页的新请求看到新记录。
- [ ] 刷新页面和重启服务后记录仍在，金额和日期没有转换偏差。
- [ ] 无效字段给出一致的中文错误；无效记录未写入文件。
- [ ] 写入失败不提示成功、不清空表单；连续点击同一次提交不产生多条请求。
- [ ] 保存成功但刷新失败提示“已保存”及重新加载入口，不让用户误以为需再新增。

## 不包括

批量导入、第三方平台抓取、自动识别、复杂幂等协议和归档操作。
