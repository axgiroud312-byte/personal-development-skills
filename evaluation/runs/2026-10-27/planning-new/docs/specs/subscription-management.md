## 场景与业务规则

### 业务对象与生命周期

唯一业务对象是 Subscription。它归当前本地使用者所有；没有账户、组织、共享或跨设备归属。每个对象通过不可变的 id 标识，新增后可查看和编辑；编辑保留同一个 id。本期没有归档、删除、恢复等状态转换。

renewal_date 表示使用者填写的“下一次续订日期”，为公历日期，不是收费成功记录，也不表示系统会自动扣费。由于现有字段没有订阅周期，本期由使用者维护该日期，不从月费、年费或上次付款日推算。已过日期仍可查看和编辑，不自动跳至下一期。

| 规则或选择 | 依据／确认情况 | 影响范围 |
| --- | --- | --- |
| 单人、本地保存、查看／新增／编辑 | 需求明确 | 本轮所有功能 |
| 下一次续订日期由使用者填写，保持纯日期语义 | 依据现有 renewal_date 字段拟定的最小近期行为 | 表单、接口、展示与存储；不新增周期能力 |
| 金额用整数分保存，界面显示两位小数及币种代码 | amount_cents 已存在；两位小数为本方案工作约定 | 不使用浮点数直接计算分，不做货币换算 |
| 允许零金额，不允许负数 | 本方案建议的输入规则，需求未专门确认金额边界 | 避免预先排除免费订阅；若业务另有要求，修改同一公共校验即可，不影响查看流程 |
| 时区先沿用代码中的 UTC | 代码与 README 冲突，未获改成 Asia/Shanghai 的确认 | 设置只读展示 UTC；纯日期不做时区转换，查看／新增／编辑不因此阻塞 |
| 归档后是否允许编辑历史条目 | 用户明确未决定，且以前聊天没有确认 | 仅影响未来归档能力，不为本期增加状态字段、权限或阻塞条件 |

币种的完整支持范围与非两位小数币种规则尚未确认。本期只约定现有 amount_cents 的两位小数表示与显式币种代码，不宣称支持完整的国际货币小数位规则；如实施需要此类币种，应先补充金额规则。

### 用户流程

1. 启动后读取真实 JSON，进入列表。列表显示名称、币种与金额、续订日期，提供分页和详情入口。没有数据时显示空状态，仍可新增。
2. 从列表进入详情查看同一个 id 的数据；返回列表时恢复来源页码。直接打开详情时，返回入口默认指向列表第 1 页。
3. 点击新增打开弹窗，填写字段并提交。校验失败保留内容；写入失败不关闭表单、不显示成功。提交中防止重复点击。
4. 新增真实落盘后，关闭弹窗，重新请求列表第 1 页，使新记录可见。列表按存储顺序倒序读取，新记录排在前面；不额外添加 created_at 字段。
5. 在详情页切换到编辑表单。取消恢复已保存值；保存成功后保持 id 和列表位置不变，详情显示服务端返回的新值，返回列表时重新读取该页。
6. 进入设置页查看当前时区与本地数据位置，并可返回列表。设置项的可写范围未提出，本期按只读最小页规划，不新增时区切换、存储迁移或其他设置能力。

## 整体技术方案

### 模块与数据流

桌面界面负责路由、弹窗、分页、表单状态和中文提示；本地 API／调用适配层负责统一请求与响应；业务层负责字段校验、生成 id 和记录操作；JSON 存储层负责真实读取、完整写入及故障保护。

读取流程：界面请求 → 本地接口 → 校验查询／id → 读取 JSON → 排序与分页／查找记录 → 返回数据 → 界面展示。

写入流程：表单展示值转换为公共字段 → 本地接口权威校验 → 业务层生成或定位 id → 串行执行读取、修改、完整写入 → 写入完成后返回已保存对象 → 界面更新详情或重新读取列表。

这些是职责边界，不要求拆成多个进程、服务或独立部署。保留 Python 与 data/subscriptions.json，不引入数据库、云端保存或登录体系。逻辑接口既可通过已有本地桥接暴露，也可映射为本地 HTTP；由于项目尚无承载证据，本轮不指定 Electron、Tauri、Web 框架或新的依赖组合。

运行载体确认任务应先查明既定启动方式与约束，并在本节登记结论。若确实没有既定载体，需要提出最小兼容选择并取得相应范围决定；不能借“补启动环境”替用户决定更换技术栈。该缺口阻塞具体 UI／通信接线，不阻塞公共契约、独立的 Python 数据逻辑或 HTML 原型规划。

### 公共数据契约

下表是本期拟定的唯一公共字段契约。表单字段标识、接口字段和存储字段保持一致；金额文本只是 amount_cents 的展示与输入转换，不另设 price、amount 等持久字段。

| 字段 | 存储／接口类型 | 近期约束与展示 |
| --- | --- | --- |
| id | string | 服务端生成非空唯一标识，建议使用 UUID；只读且不可修改，不由新增表单提交 |
| name | string | 必填，去除首尾空白后非空；保存规范化结果 |
| amount_cents | integer | 必填，非负整数；例如 4990 显示为 49.90；金额文本多于两位小数时拒绝，不静默舍入 |
| currency | string | 必填，去除空白后规范化为 3 位大写字母代码；界面显示如 CNY 49.90，不只显示含义不明确的符号 |
| renewal_date | string | 必填，严格合法的 YYYY-MM-DD 日期；例如 2026-12-01；禁止无效日期，不转成 UTC 时间戳 |

创建和更新均提交 name、amount_cents、currency、renewal_date 四个可写字段。更新使用完整字段集，不引入部分更新语义。请求中的 id 或其他未知字段被拒绝；响应与存储记录包含全部五个字段。API 是权威校验方，表单可按同一规则提前提示，但不得产生另一套错误含义。

JSON 顶层数组是**拟定格式**，并非从现有样例推断出的事实。数组按新增顺序保存；编辑原位替换同 id 记录，新增追加到末尾；列表按数组倒序分页。这使新增后重新读取第一页即可看到新记录，也避免编辑导致列表无故跳页。

文件不存在时，读取视为无记录，不在读取时创建文件；第一次成功新增时创建所需目录和文件。JSON 损坏、结构不合规、记录 id 重复或已有记录不符合公共契约时，报告存储数据错误，保留原文件，禁止用空数组覆盖。若后来发现需要兼容的历史结构，先记录差异并补充迁移决定。

启动入口应明确把 data/subscriptions.json 解析到当前项目目录，读写共用同一解析结果，避免不同工作目录产生另一份数据。保存先写完整临时文件，再替换目标文件；同一运行实例的修改串行执行，避免同时新增或编辑造成丢失。写入失败保持已有文件可用，不能提前返回成功。本期不承诺多个应用实例或外部编辑器同时改文件的合并能力。

### 逻辑接口与错误契约

路径是拟定的接口命名，HTTP 状态仅在采用 HTTP 承载时适用；本地桥接应保持相同的数据与错误结构。

| 操作 | 输入 | 成功结果 |
| --- | --- | --- |
| GET /api/subscriptions | page 默认为 1；page_size 默认为 20，均为整数，page ≥ 1，1 ≤ page_size ≤ 100 | 200；对象包含 items、page、page_size、total。越界但合法的页码返回空 items 和真实 total |
| GET /api/subscriptions/:id | 记录 id | 200；返回完整 Subscription 对象 |
| POST /api/subscriptions | 四个可写字段 | 201；真实写入完成后返回包含新 id 的 Subscription |
| PUT /api/subscriptions/:id | id 与完整的四个可写字段 | 200；写入完成后返回同 id 的 Subscription；不存在时不能隐式创建 |
| GET /api/settings | 无 | 200；返回 time_zone 与 storage_path，只读展示实际生效值；storage_path 对应同一个项目内 JSON 文件 |

错误统一为对象 error，内含 code、message，以及可选 fields。fields 的键使用公共字段名，值使用下列稳定错误码；中文 message 用于解释，调用方不能靠匹配中文文本判断错误类型。

| 错误码 | 含义／HTTP 映射 | 界面与数据结果 |
| --- | --- | --- |
| VALIDATION_ERROR | 字段不合法，422；fields 使用 REQUIRED、INVALID_AMOUNT、INVALID_CURRENCY、INVALID_DATE 或 UNKNOWN_FIELD | 对应字段提示，保留表单内容，不写文件 |
| INVALID_PAGINATION | 分页参数不合法，400 | 提示参数异常并允许回到默认列表，不读取为成功空页 |
| NOT_FOUND | id 不存在，404 | 详情显示记录不存在并提供返回入口；编辑不创建新记录 |
| STORE_READ_FAILED | 文件存在但无法读取，500 | 展示读取失败及重试入口，不能伪装为空列表 |
| STORE_DATA_INVALID | JSON／记录格式不合法，500 | 提示数据文件需要处理，保留文件并阻止写操作 |
| STORE_WRITE_FAILED | 写入或替换失败，500 | 明确保存失败，保持旧文件与表单输入 |

传输失败在界面层单独提示。若已收到写入成功响应，但后续列表读取失败，应明确显示“已保存，列表刷新失败”，重试的是 GET；不能再次 POST 来刷新列表。若提交响应丢失导致结果不明，保留输入并先允许重新读取确认，不能宣称保存成功或自动重发新增请求。

### 界面与设计依据

本期包含列表、详情、设置三个页面及新增弹窗；编辑在详情页进行。列表固定使用每页 20 条的初始界面，保留上一页、下一页、总条数与当前页；不额外增加搜索、筛选、排序控件。合法但超出最后一页时，界面依据 total 回到最后一个有效页；空列表页码为 1。

界面要求为紧凑中文桌面布局，金额和续订日期优先清楚；涵盖加载、空列表、读取错误、字段错误、提交中、保存失败和保存成功但刷新失败状态。详情返回需要保留来源页码；路由或导航状态的具体写法由已确认的运行载体决定。

原型、Token 和组件源码均尚不存在。[设计任务](../issues/PLAN-002.md) 未来应交付 docs/design/subscriptions.html，并在 HTML 原型完成后提取 docs/design/tokens.json；这些路径是计划产物，本次没有创建。组件源码与实际共享 Token 源码位置在运行载体确定后登记到本节，视觉数值以共享源码为准，不复制到每份 Issue。
