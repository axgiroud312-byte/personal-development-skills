# PLAN-005：在详情编辑同一订阅并保持列表与保存数据一致

状态：待开始；本轮未开发或运行。

## 本次要做什么

- **本次想实现什么：** 使用者能在详情修改已存在订阅，保存后详情、列表和 JSON 保持一致，也能取消未保存修改。
- **想要什么：** 更新原 id；字段和错误语义复用新增；成功后刷新显示；返回列表保留来源页码。
- **不想要什么：** 用新增替代更新、修改 id、引入归档状态、限制尚未定义的历史编辑权限或自动推算续订日期。
- **依据：** [Spec](../specs/subscription-management.md)、[查看任务](PLAN-003.md)、[新增与写入能力](PLAN-004.md)。视觉依赖 [PLAN-002](PLAN-002.md) 的未来原型与 Token。

## 局部方案

详情通过 GET /api/subscriptions/:id 取得完整记录。进入编辑时以已保存值初始化 name、amount_cents、currency、renewal_date；id 只读。金额继续按同一个精确转换规则显示与输入，日期保留纯日期。

取消编辑恢复上次读取／保存的值，不调用更新接口、不修改 JSON。返回列表保留来源页码；未保存编辑的离开行为采用已完成原型的明确交互，不以返回动作触发隐式保存。

保存调用 PUT /api/subscriptions/:id，提交完整四个可写字段。复用 PLAN-004 的公共校验、错误结构和串行完整写入能力。在写入前定位目标 id；不存在返回 NOT_FOUND，不能创建新记录。更新原数组位置，保持 id、记录数量和列表顺序不变。

写入完成后返回完整更新对象，HTTP 承载为 200。详情采用该返回值退出编辑，清除未保存状态。返回列表时重新 GET 来源页，不只修改一个客户端缓存字段。金额和日期的格式化与列表保持一致。

VALIDATION_ERROR 附相同字段错误码，保留输入；STORE_READ_FAILED、STORE_DATA_INVALID 或 STORE_WRITE_FAILED 保持原文件并允许恢复；NOT_FOUND 明确提示原记录不存在并提供返回入口。未确定保存结果时不能假定失败后重新创建。详情保存已成功而列表重读失败时，提示“已保存，列表刷新失败”，只重试读取。

归档尚未定义，因此本任务不加入 archived、status、历史锁定或其他编辑权限分支；“日期已过去”不等于“已归档”，不得据此拒绝当前记录编辑。

- **所属目标：** 编辑已有订阅并保持真实数据一致。
- **前置条件：** [PLAN-003](PLAN-003.md) 的详情、列表和返回页码；[PLAN-004](PLAN-004.md) 首次建立的公共校验与完整写入；[PLAN-002](PLAN-002.md) 的编辑交互依据。
- **当前可推进部分：** 后续可以先依据公共契约细化编辑行为；写入实现待 PLAN-004 的共享路径稳定后接入。
- **共享修改：** 复用原有校验与写入模块，不复制第二套错误语义；新增与编辑按顺序落地，避免存储模块冲突。
