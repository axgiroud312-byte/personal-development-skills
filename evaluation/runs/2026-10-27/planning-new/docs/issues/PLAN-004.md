# PLAN-004：通过弹窗新增订阅并在列表读到持久记录

状态：待开始；本轮未开发或运行。

## 本次要做什么

- **本次想实现什么：** 打通新增弹窗、公共校验、本地写入和列表重读，使提交后的订阅在刷新及重启后仍然存在。
- **想要什么：** 只有真正保存后才显示成功；保存后第一页显示新记录；表单与 API 的字段和错误含义相同。
- **不想要什么：** 假提交、仅修改内存列表、引入数据库、归档、订阅周期计算或额外账户能力。
- **依据：** [Spec 的公共契约、接口与完成标准](../specs/subscription-management.md)、[查看任务](PLAN-003.md)。视觉依赖 [PLAN-002](PLAN-002.md) 的未来原型和 Token；当前尚不存在。

## 局部方案

### 表单与接口

列表提供新增弹窗，字段标识沿用 name、amount_cents、currency、renewal_date。界面允许用 49.90 形式输入金额，再精确转换为 4990；超过两位小数拒绝，不舍入、不以浮点乘法产生不确定的分值。币种去空白并转大写，日期使用合法 YYYY-MM-DD；全部约束以 Spec 为准。

POST /api/subscriptions 只接收四个可写字段。服务端权威校验，拒绝 id 和未知字段；错误为 VALIDATION_ERROR，并以相同字段名返回 REQUIRED、INVALID_AMOUNT、INVALID_CURRENCY、INVALID_DATE 或 UNKNOWN_FIELD。前端提示同义字段错误，输入保留。

服务端生成唯一 id，将完整记录追加到数组末尾，返回完整 Subscription；HTTP 承载时成功为 201。请求提交中禁用重复提交，关闭前未保存输入的处理按设计依据，不静默显示已保存。

### 可靠写入与变更后重读

以项目目录为数据路径基准，复用 PLAN-003 的读取和存储结构校验。数据文件不存在时，首次有效新增创建目录与文件；已有数据损坏或重复 id 时阻止写入，不能当作空数据覆盖。

同一运行实例串行执行读—改—写；先写完整临时内容，再替换正式文件，失败保留旧文件。只有替换完成后才返回成功。接口、表单和列表共同区分 STORE_READ_FAILED、STORE_DATA_INVALID、STORE_WRITE_FAILED；建立的写入能力供编辑任务复用。

写入成功后关闭弹窗，重新请求 GET /api/subscriptions 的第 1 页，采用 API 返回数据更新列表。按既定倒序规则，新记录显示在第一页，total 增加一；不以客户端虚构对象代替真实读取。

若保存成功而重读失败，明确显示“已保存，列表刷新失败”，重试 GET，不再次 POST。若响应丢失导致保存结果不明，保留输入并允许先重读确认；不自动重发新增，不宣称一定没有写入。

## 预期结果

| 前提／输入 | 操作 | 应有表现 |
| --- | --- | --- |
| 名称“视频订阅”、CNY、49.90、2026-12-01 | 提交新增 | 文件出现带唯一 id 的记录，amount_cents 为 4990；成功响应后列表 GET 可见新记录 |
| 当前停在列表第 2 页 | 新增一条有效记录 | 成功后读取第 1 页并显示新记录，总数增加一 |
| 合法新增已经成功 | 刷新或重新启动 | 仍能从同一 JSON 读取同 id 和相同字段 |
| 空名称、12.345 金额或 2026-02-30 日期 | 提交 | 对应字段报错、保留输入，文件不改变 |
| 初次使用、文件不存在 | 有效提交 | 创建同一路径的有效 JSON，列表能够读取 |
| 文件写入／替换失败 | 提交 | 反馈保存失败，原文件保留，表单不丢失内容 |
| 现有 JSON 损坏 | 提交 | STORE_DATA_INVALID，原内容保留，不用新数组覆盖 |
| 已保存但列表重读失败 | 点击重试 | 只重试读取，不重复新增 |
| 提交仍在进行 | 连续点击保存 | 同一界面只发起一次在途提交 |
