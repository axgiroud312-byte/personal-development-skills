# PLAN-003：从真实 JSON 分页查看订阅并贯通详情与设置

状态：待开始；本轮未开发或运行。

## 本次要做什么

- **本次想实现什么：** 完成第一条真实读取流程，使使用者能够从列表找到订阅、查看详情、回到来源页，并查看本地设置。
- **想要什么：** JSON → 本地接口 → 桌面列表／详情／设置贯通；列表分页；金额、币种和下一续订日期明确。
- **不想要什么：** 只做静态页面、把模拟数据当成真实接入、增加搜索／筛选／汇率、实现新增或编辑保存。
- **依据：** [Spec](../specs/subscription-management.md)、[现有字段声明](../../src/store.py)。设计依赖 [PLAN-002](PLAN-002.md)，当前原型、Token 与组件源码均缺失。

## 局部方案

### 本地读取与接口

沿用五字段 Subscription 契约和项目内 data/subscriptions.json。文件不存在返回空集合且不新建文件；文件不可读返回 STORE_READ_FAILED；JSON 或记录不合法返回 STORE_DATA_INVALID，不能将异常转成空列表。

接通以下逻辑接口，具体承载按 PLAN-001 的结论：

- GET /api/subscriptions：page 默认 1、page_size 默认 20；按数组存储顺序倒序分页，返回 items、page、page_size、total。page 必须为正整数，page_size 为 1 至 100 的整数，非法参数返回 INVALID_PAGINATION。合法越界页返回空 items 与真实 total。
- GET /api/subscriptions/:id：返回完整同 id 记录；不存在返回 NOT_FOUND。
- GET /api/settings：返回实际 time_zone 与 storage_path，初始 time_zone 沿用代码 UTC，不读取 README 作为配置。

校验与错误对象引用 Spec；接口与界面只使用同一份字段解释。金额按分转换成两位小数并显示币种；renewal_date 按原 YYYY-MM-DD 日期展示，不转换时间戳。

### 桌面流程

实现列表、详情、只读设置的导航。列表每页 20 条，显示总数与当前页、上一页／下一页；没有更多记录时禁用相应翻页操作。若请求页超出最后一页，依据 total 跳到最后一个有效页并重新读取；总数为零时保留第 1 页。

详情保留来源页码，返回时恢复该页；直接打开详情时返回第 1 页。详情数据不存在时显示明确提示与返回入口。设置展示实际 UTC 和 JSON 位置，可返回列表；本期不提供修改设置的控件。

加载、空列表和读取失败分别展示。失败保留重试入口，不显示虚假的“无订阅”。设计使用 PLAN-002 未来交付的 HTML 与提取后的 Token；运行入口及组件源码路径确定后补充到 Spec，不先假设已有组件库。

实施交付时将 README 的时区说明与实际沿用的 UTC 对齐，并补充真实启动方式。当前规划轮不修改 README 或代码。
