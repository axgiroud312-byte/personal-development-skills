## 局部方案

当前已知代码只声明 UTC 时区、相对 JSON 路径与五个字段，未提供前端依赖、应用入口或启动命令。后续实施开始前核对项目是否补充了已有载体证据；有则复用，没有则明确记录“暂无既定 UI 载体”，提出保留 Python／JSON 的最小承载选择及其影响，由具有范围决定权的人确认新增依赖方向。

结论直接补到 Spec 的整体技术方案，不为调查另建空报告。需要记录：

- 桌面界面的实际运行载体及依据，前端与 Python 通过本地桥接还是 HTTP 通信。
- 如何实现 Spec 中的逻辑接口及统一错误结构，不以承载差异另造字段名。
- 启动时如何确定项目目录，使所有读取、写入与设置展示指向同一份 data/subscriptions.json。
- 正式实施时的最小启动方式与已有强制检查；没有证据的条目写明未知，不编造。
- UTC 为当前代码值，README 的 Asia/Shanghai 是已知冲突，不能静默宣称已改时区。

本任务仅形成决定和依据，产物是更新后的 Spec。安装、页面代码和 API 接入由后续功能任务完成。
