# PLAN-002：补齐订阅三页面与表单流程的设计依据

状态：待开始；本轮未制作原型、Token 或组件。

## 本次要做什么

- **本次想实现什么：** 为列表、详情、设置、新增弹窗和详情编辑提供可交接的桌面中文设计依据，避免实施时各自猜测视觉和交互规则。
- **想要什么：** 紧凑布局；金额与续订日期清楚；关键成功、失败和返回路径完整。
- **不想要什么：** 手机端设计、归档交互、账户体系、收费流程、可写设置或真实 API／存储实现。
- **依据：** [Spec 的用户流程、公共契约与界面要求](../specs/subscription-management.md)。现有项目没有可引用的原型、Token 或组件源。

## 局部方案

未来先完成可查看的 HTML 原型 docs/design/subscriptions.html，再从该原型提取 docs/design/tokens.json。当前这两个文件均不存在。原型完成即可交付设计成果；其样例数据与交互反馈必须标明为模拟，不宣称真实保存。

原型覆盖：

- 列表：名称、显式币种与两位小数金额、续订日期；默认每页 20 条；页码、总数、上一页／下一页；空态、加载与读取失败状态。
- 详情：展示记录、进入编辑、返回来源列表页；未知 id 的提示与返回入口。
- 新增弹窗：使用 name、amount_cents、currency、renewal_date 对应字段；金额输入转换只属于展示层；提交中避免重复点击，字段错误与写入失败保留输入。
- 编辑：详情页编辑与取消；成功后显示保存值；失败不丢失输入。
- 设置：只读显示实际时区与数据位置，并能回到列表，不设计未经明确要求的设置写入。
- 写入成功但列表刷新失败：区分“已保存”与“未刷新”，重试只刷新列表。

字段名称与错误语义引用 Spec，不另写一份不同的公共契约。需要显示的中文标签由设计明确，数据键仍保持公共字段。设计不得增加订阅周期、自动计算续订日或归档状态。

Token 只从完成的 HTML 原型提取；运行载体确认后登记实际共享 Token 与组件源码位置，后续 Issue 引用这些来源。当前不编造已经存在的组件库或视觉数值。

## 预期结果

| 前提／输入 | 操作 | 应有表现 |
| --- | --- | --- |
| 列表超过一页 | 在原型中切页、进详情再返回 | 返回路径与来源页码清楚，金额和日期不因紧凑布局难以辨认 |
| 打开新增／编辑 | 浏览正常、非法输入、提交中、失败状态 | 字段提示可对应公共字段，错误时输入保留，真实保存与模拟明确区分 |
| 写入已成功但列表读取失败 | 查看该状态 | 提示已保存、允许重读，不引导再次新增 |
| HTML 原型确认完成 | 提取 Token 并登记来源 | Token 能追溯到原型，组件来源与后续接线依赖明确 |
