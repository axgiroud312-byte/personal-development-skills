# 订阅查看、新增与编辑技术方案

状态：近期范围已整理；仅交付方案与本地任务，设计和实现均未开始。原始依据：[本次需求](../request.md)、[README](../../README.md)、[现有代码](../../src/store.py)。任务入口：[本地 Issue 索引](../issues/README.md)。

## 1. 目标与范围

为单人自用的桌面订阅工具建立一条真实的数据流程：查看分页列表 → 打开详情并返回列表 → 新增或编辑 → 保存成功后重新读取 → 刷新后数据仍在。中文界面应紧凑，金额与下次续订日期清楚可见；新增使用弹窗，另有详情和设置页面。

近期包含统一字段与错误含义、本地 JSON 保存、列表分页、详情读取、新增、编辑、设置页面的已知信息展示。前端、API 和持久化层使用同一订阅契约。

本次规划不扩展手机端、账号、收费、日历同步、第三方抓取或技术栈迁移。归档是待定后续范围，不增加归档字段、接口、按钮或历史条目编辑限制。周期推算、自动顺延续订日期和原生安装包未有已确认要求，不能作为当前已承诺能力。

## 3. 业务对象与共同契约

### 3.1 订阅对象

订阅属于当前本地使用者；本期没有账户、成员关系或所有者字段。生命周期只有创建、读取和编辑，不删除、不归档。名称不作为标识，也不新增名称唯一限制；身份始终由 `id` 决定。

以下是本次选定的技术契约，不是对现有行为的描述：

| 字段 | 类型与含义 | 输入与约束 |
| --- | --- | --- |
| `id` | 字符串，稳定的本地记录标识 | 创建时由服务生成 UUID；编辑时不可变。客户端不能通过请求正文指定或更换它。 |
| `name` | 字符串，订阅名称 | 去除首尾空白后非空。 |
| `amount_cents` | JSON 整数，金额的百分之一单位 | 非负，允许 0；不得使用布尔值、浮点数或字符串代替，且须在 JavaScript 安全整数范围内。 |
| `currency` | 字符串，金额所属货币代码 | 规范化为三个大写英文字母；不默认人民币、不换汇、不计算跨币种总额。格式校验不代表承诺支持所有货币的不同小数位制式。 |
| `renewal_date` | `YYYY-MM-DD` 字符串，用户维护的下次续订日期 | 必须为实际存在的日期；不携带时分秒。可保存过去日期，不根据当前日期或猜测的周期自动改写。 |

继续使用 `amount_cents` 意味着本期统一按两位小数表示金额。前端用同名字段绑定金额输入和错误，通过十进制字符串精确转换为整数，显示为货币代码加两位小数金额；不另设 `price`、`amount` 等并行业务字段。若以后需要零位或三位小数货币，须先调整金额契约，不能在某一层偷偷改变换算比例。

日期是日历日期，不是时间戳。保存、API 返回与界面展示保持同一天，不经浏览器本地时区或 UTC 转换后偏移。`TIME_ZONE` 当前仍为 UTC；本期不增加时区写入或时区切换能力。

### 3.2 公共校验与错误

服务端是最终校验入口，基于 `FIELDS` 约束实体字段，并提供统一的校验与错误映射。前端可做即时反馈，但使用相同字段名，提交后以 API 的错误为准；仓储层不得为同一失败另造一个相反的业务含义。

创建及完整编辑正文均包含 `name`、`amount_cents`、`currency`、`renewal_date` 四个字段。缺少必填字段、错误类型、无效值或多余字段均拒绝；更新通过 URL 中的 `id` 定位，不能隐式新增记录。

成功正文统一为 `{ "data": ... }`。失败正文统一为 `{ "error": { "code": "...", "message": "中文说明", "field_errors": {} } }`。字段错误的键使用契约中的字段名，分页错误使用 `page` 或 `page_size`；整体错误可保持 `field_errors` 为空。前端依 `code` 和字段名处理，不通过匹配中文文案判断错误类型。

| `code` | HTTP 状态 | 含义与界面结果 |
| --- | --- | --- |
| `validation_error` | 400 | 请求正文、字段或分页参数不合法；显示字段或整体错误，保留用户输入，不改数据。 |
| `not_found` | 404 | 指定记录不存在；详情或编辑提示记录不存在，并提供返回列表入口，不创建替代记录。 |
| `storage_unavailable` | 503 | 本地文件无法读取或保存；给出可重试提示，不显示保存成功。 |
| `storage_invalid` | 500 | 已有文件不是合法 JSON 或不符合实体结构；提示数据不可读取，保留原文件，不把它当空列表覆盖。 |
| `internal_error` | 500 | 未预期的服务错误；显示整体失败信息，不能伪装成字段错误或成功。 |

请求未获得完整响应时属于客户端连接状态，不虚构为某种已确定的服务端错误。尤其提交超时时，界面保留输入并说明保存状态未确认，提示重新读取核对；不自动重发新增请求。

## 4. 整体技术方案

### 4.1 模块职责与数据流

1. **桌面界面**负责路由、列表页码、表单显示和提交状态，使用 API 读写真实数据；不以浏览器缓存作为另一份持久化存储。
2. **API 与应用服务**负责分页参数、共同校验、标识生成、统一返回及错误映射，将操作交给仓储。
3. **本地仓储**沿用 `src/store.py` 中的路径及字段约定，负责读取、按标识查找、追加和完整更新；写入成功后才向上层报告成功。

读取路径：界面 → API → 仓储 → JSON 文件 → 同一实体契约返回界面。提交路径：表单 → API 校验 → 仓储持久写入 → 成功响应 → 界面重新请求列表或详情。设置页从服务读取真实常量，不在前端另写一套时区。

保持现有 Python 代码和本地保存方式。项目未提供前端或 HTTP 框架依据，因此此方案定义模块边界和接口，不把 React、Vue、Electron、Tauri 或任何服务框架擅自确立为既有选择。运行入口的证据缺口见 U2；领域、仓储与界面设计要求可以先推进。

### 4.2 本地保存与恢复

- 文件内容拟采用顶层订阅数组，每个对象恰好包含五个实体字段。当前没有数据文件可核验，该格式是新约定，不是已验证的历史格式。
- 服务从项目根目录启动并使用现有 `STORE_PATH`。最终启动入口须固定或显式解析项目根，避免从不同工作目录启动后写到第二个 `data/subscriptions.json`。
- 文件不存在时列表为空；第一次成功保存时创建必要目录和文件。空内容、解析错误、重复 `id` 或非法对象不能等同于文件不存在。
- 新记录追加到持久数组，编辑保留原位置和 `id`。列表按数组的逆序读取，使最新新增记录在前；不新增排序时间字段，也不擅自按续订日期改变顺序。
- 读改写操作串行化，在同目录写入完整临时文件后以原子替换提交。失败时保留原文件，不出现半份 JSON，不返回成功；本期不扩展多进程同时写同一文件的能力。
- 若后续实施时发现既有数据或其他调用者，先核验格式与兼容方式；未知内容不得自动清空、截断或丢字段。

### 4.3 接口边界

路径是本期计划接口，当前均未实现。

| 接口 | 输入 | 成功结果 |
| --- | --- | --- |
| `GET /api/subscriptions` | `page` 默认 1，`page_size` 默认 20；均为整数，`page >= 1`，`1 <= page_size <= 100` | 200，`data` 为 `{ items, page, page_size, total }`；`items` 为完整实体。有效但超出末页的页码返回空数组与真实总数。 |
| `GET /api/subscriptions/{id}` | 记录标识 | 200，`data` 为完整实体；不存在则 404。 |
| `POST /api/subscriptions` | 四个可写字段 | 持久保存成功后返回 201，`data` 为含生成 `id` 的完整实体。 |
| `PUT /api/subscriptions/{id}` | 标识及完整的四个可写字段 | 持久保存成功后返回 200，`data` 为更新后的完整实体；无记录时不执行 upsert。 |
| `GET /api/settings` | 无 | 200，`data` 为 `{ time_zone: "UTC", storage_path: "data/subscriptions.json" }`，值来自服务端实际常量。 |

本地服务接入应限定在本机，不由单人自用需求推导出公网部署或账户系统。分页、字段和错误规则只在本 Spec 定义；各 Issue 引用，不再复制一套不同规则。

### 4.4 界面要求与设计前置

目前没有实际设计板、Token 或可复用组件。后续 [Issue 002](../issues/002-desktop-design.md) 先形成 HTML 设计预览，再提取对应 Token；当前不制作这些产物。页面实现依赖设计产物，不能把本 Spec 的文字当作已完成的视觉设计。

- **列表：** 紧凑中文界面，名称、金额和下次续订日期清晰；有新增入口、分页、空列表、加载中和加载失败状态。页码保存在可恢复的路由状态中。
- **详情：** 通过 `id` 读取记录，提供编辑和返回列表；返回时恢复原页码与每页条数。直接打开详情无来源页时返回默认第一页。
- **新增：** 使用弹窗。提交期间防止重复点击；失败保留输入；成功后重新请求第一页，使实际保存的新记录可见。
- **编辑：** 从详情进入，表单使用实体同名字段；具体采用页内还是弹窗由设计任务明确。成功后重新读取详情及相关列表，金额和日期保持一致。
- **设置：** 先展示服务端当前时区与保存位置。可编辑设置项没有需求依据，记为 U3，不能顺带增加写设置接口。
- **保存与回读：** 写入成功但随后读取失败时，应说明“已保存，读取失败”，提供重新读取操作；不能把已成功的写入当失败再提交。未确认提交结果与已确认成功必须区分。

## 5. 可观察完成标准

这些是后续功能结果，不表示已实现，也不要求逐条创建测试任务。

| 条件与操作 | 预期结果 |
| --- | --- |
| 文件尚不存在，打开列表 | 显示空列表和新增入口，不报数据损坏，也不生成示例订阅冒充真实数据。 |
| 新增名称“工具 A”、`amount_cents=1299`、`currency=CNY`、`renewal_date=2026-11-15` | API 持久保存后才成功；列表重新读取到新 `id` 的记录，金额显示 CNY 12.99，日期仍为 2026-11-15。刷新或重启服务后仍能读取。 |
| 从第二页打开详情，再返回 | 回到第二页及原每页条数，不强制跳第一页。 |
| 编辑已有记录的金额与续订日期 | 保存后 `id` 不变、不产生重复记录，详情及重新读取的列表一致；刷新后保持修改。 |
| 提交空名称、非整数分值或不存在的日期 | 400 与同名字段错误；弹窗或编辑表单保留输入，文件不变。 |
| 访问或编辑不存在的 `id` | 明确提示不存在，可返回列表；不凭空创建一条记录。 |
| 请求合法的末页之外页码，或请求非法分页参数 | 前者返回空数组和真实总数，界面可返回有效页；后者返回分页参数错误。 |
| 本地写入失败或已有文件损坏 | 分别返回保存失败或数据损坏的统一错误；不显示成功、不清空旧数据。 |
| 写入已成功，但列表重新读取失败 | 显示已保存与读取失败的区别，允许重新读取，避免再次新增。 |
| 在不同时区的浏览器查看同一记录；进入设置页 | 续订日期不偏移；设置从服务读取 UTC，与代码一致。 |
