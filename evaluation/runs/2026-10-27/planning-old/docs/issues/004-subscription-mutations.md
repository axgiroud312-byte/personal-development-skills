# 004 · 新增和编辑完成真实保存及回读

类型：功能。当前状态：受阻，等待写入接口、设计产物及连续查看流程。

## 目标与范围

让新增弹窗和编辑表单提交真实 API，在确认持久保存成功后重新读取列表/详情，刷新后仍保留记录与修改。该任务完成本期从查看到写入再回读的闭环。

依据：[Spec 第 3—5 节](../specs/subscription-management.md)。不扩展归档、删除、批量修改、自动续订或可编辑设置。

## 局部方案

- 新增弹窗使用四个可写字段；编辑从详情的完整实体初始化，同名字段映射 API 与错误，`id` 只用于定位且不能编辑。
- 金额输入通过精确十进制转换得到 `amount_cents`，不进行二进制浮点乘法后直接取整；货币与日期沿用公共契约。前端反馈不能替代服务端最终校验。
- 提交中禁用重复提交。收到字段/整体错误时保留已填内容，展示可修正或重试的状态；404 要提示记录不存在，不能转成创建。
- 新增获得 201 后关闭成功流程并请求第一页，使新记录从真实接口读回；不只向内存列表追加一个对象后宣称完成。
- 编辑获得 200 后重新读取详情，并使相关列表在返回时取得最新记录；保持记录标识与原分页返回语义，不残留旧金额或日期。
- 保存成功但回读失败时显示已保存，提供重新读取；提交响应未确认时说明状态未知并引导核对。两者都不自动重发新增请求。
- UI 的编辑呈现方式以 002 的实际设计决定为准，使用 003 已交付的路由、API 客户端和回读入口，避免重复搭建。

## 关联与依赖

- [001](001-subscription-data-api.md) 的真实 POST/PUT、持久保存与统一错误。
- [002](002-desktop-design.md) 的新增/编辑 HTML、对应 Token 和状态设计，当前仍未存在。
- [003](003-subscription-browsing.md) 的列表/详情路由、读取与返回状态。
- 公共契约由 Spec 维护；发现字段或错误不一致时先修正共同依据和提供方，不在本任务加临时别名接口。
- 本任务在 003 后修改共享前端文件；不回头创建独立前端存储或修改归档业务规则。

## 预期结果

| 前提／操作 | 可观察结果 |
| --- | --- |
| 在任意列表页新增合法订阅 | 保存成功后转到第一页并真实读到新记录；刷新和服务重启后仍存在。 |
| 修改金额和续订日期 | 详情及返回列表显示更新值，`id` 不变且没有重复记录。 |
| 输入非法值或本地保存失败 | 显示统一错误并保留输入；无成功提示、无伪造列表记录。 |
| 重复点击提交按钮 | 提交中的同一次操作只发起一次请求。 |
| 写入成功后读取失败，或提交未收到完整响应 | 分别呈现已保存/回读失败或保存状态未确认，不自动再次创建记录。 |
