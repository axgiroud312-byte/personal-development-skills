# 003 · 列表、详情和设置形成连续查看流程

类型：功能。当前状态：受阻，等待真实读取接口、设计成果及运行约定。

## 目标与范围

让用户在桌面界面读取真实订阅列表、分页浏览、进入详情并返回原列表页，同时查看当前设置。此任务提供 004 所需的公共路由与读取状态。

依据：[Spec 第 3—5 节](../specs/subscription-management.md)。本任务不实现表单提交或设计新视觉风格；不引入浏览器本地持久化替代 JSON。

## 局部方案

- 列表消费 001 的分页接口，显示规范金额和原样日历日期，处理加载、空态、服务端错误与有效的空末页。页码和每页条数放入可恢复路由状态；迟到的旧请求不得覆盖当前页结果。
- 详情按 `id` 读取完整实体。返回入口恢复来源列表的分页参数；直接访问详情时回到默认第一页。不存在的标识呈现 404 对应状态，并保留回列表入口。
- 设置消费只读设置接口，展示后端实际时区和保存位置，不硬编码 README 中的旧时区，也不新增可编辑设置。
- 使用统一 API 客户端解释 Spec 的成功及错误结构；错误应可见且支持重新读取，不能把读取失败当空列表。
- 为 004 交付明确的列表重新读取和详情重新读取入口，路由与读取状态由本任务负责。新增和编辑入口的呈现遵循实际设计，提交行为由 004 接入。
- 只引用 002 实际交付的 HTML、Token 与后续已有组件源码。目前没有这些文件，不能凭空给出“已复用”的组件引用。

## 关联与依赖

- [001](001-subscription-data-api.md)：真实列表、详情、设置接口以及确定的启动入口。
- [002](002-desktop-design.md)：需先交付实际存在的设计 HTML 和对应 Token；当前尚未交付，计划位置见 002，交付后回填实际依据。
- Spec U2：已明确的前端运行方式和本机服务接入约定。
- 解除条件是上述可取得的接口、设计和运行成果，不附加先完成一轮全量测试或构建的要求。
- 004 在本任务形成路由与列表读取后推进，避免同时修改同一入口和分页状态造成冲突。

## 预期结果

| 前提／操作 | 可观察结果 |
| --- | --- |
| 有多页真实记录，打开列表并切页 | 展示对应页数据及真实总数，金额和日期符合契约。 |
| 从第二页进入详情再返回 | 保持原页码与每页条数。 |
| 直接访问详情或访问不存在的标识 | 前者能读真实记录；后者明确不存在，均可回列表。 |
| 列表读取失败后重试 | 显示失败并允许恢复，不伪装为空列表。 |
| 在不同时区查看记录，进入设置 | 日期不偏移，设置显示由服务返回的 UTC 和当前保存路径。 |
