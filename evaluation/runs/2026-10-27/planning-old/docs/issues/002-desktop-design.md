# 002 · 形成可供实现的紧凑中文桌面设计依据

类型：设计。当前状态：待开始；本轮不执行设计。

## 目标与范围

为列表、详情、设置、新增弹窗和编辑流程提供足够支持近期实现的视觉与交互依据。界面使用紧凑中文表达，突出金额、货币与下次续订日期。

依据：[Spec 第 3、4.4、5 节](../specs/subscription-management.md)、[原始需求](../request.md)。当前没有设计板、Token 或组件源码可引用；本任务负责产生这些前置依据，不将文字需求误当已有设计。

## 局部方案与产物

1. 先形成桌面 HTML 设计预览，覆盖分页列表、详情及返回、只读设置、新增弹窗、编辑入口和提交反馈；明确编辑采用页内还是弹窗，并记录该交互决定。
2. 在预览确定后提取与之对应的 Token，覆盖颜色、字体、间距、密度、金额/日期呈现与常见状态。已有实现栈如后续补齐，应优先复用其组件约定，不预选新组件库。
3. 计划交付到 `docs/design/subscriptions.html` 与 `docs/design/tokens.md`；这些是未来产物路径，目前不存在。建立页面与 Token 的对应说明，供 003/004 使用。

设计需呈现以下行为，不负责实现真实数据接口：

- 列表空态、加载态、读取失败、正常列表与末页边界；从详情返回保留原页码。
- 新增弹窗与编辑表单的同名字段、必填错误、整体保存失败、提交中和成功后回读；错误字段使用 Spec 中的契约名称。
- 保存已成功但回读失败，以及提交响应未确认这两种不同状态，避免引导重复新增。
- 设置展示真实配置的占位内容，其含义遵循 Spec；可编辑设置项待 U3 明确，不加入无依据的开关。
- 预览中的订阅数据须清楚标注为模拟，不能声称已联通保存。

## 关联与依赖

- 可与 001 的仓储工作并行；无须等待 API 或归档规则。
- HTML 预览是提取 Token 的前置，不颠倒顺序。
- 003 和 004 的页面实现必须等到需要的 HTML 与 Token 真实交付后再开始。交付时将本 Issue 及下游任务里的计划路径更新为实际可读取链接。
- 当前未选择前端框架或桌面壳，设计不要将新框架作为隐性依赖。归档、手机端和远期能力不进入设计范围。

## 预期结果与交接

接手者能够从 HTML 看到完整的查看、返回、新增与编辑流程，以及必要的成功/失败状态；能从 Token 取得一致的视觉参数。具体金额、日期及错误含义与 Spec 一致，设计产物和实现依赖可定位。

只交付 HTML 与对应 Token，并说明采用的交互决定；不另建设计测试、验收或构建任务。当前尚无任何设计产物或设计完成记录。
