# 001 · 订阅能通过统一接口真实保存和读取

类型：功能。当前状态：待开始；仓储与应用服务可先推进，HTTP 适配和启动入口待 Spec U2 明确。

## 目标与范围

让当前仅有常量的 [src/store.py](../../src/store.py) 承接真实订阅读写，并提供列表、详情、新增、编辑及只读设置接口。数据仍在 `data/subscriptions.json`，服务成功响应必须代表保存已完成。

依据：[Spec 第 2—4 节](../specs/subscription-management.md)。本任务不含 UI、归档、删除、账户、云存储或数据库替换。

## 局部方案

- 复用 `FIELDS`、`STORE_PATH` 和 `TIME_ZONE`，实现实体校验、按标识读取、创建及完整更新。字段类型、UUID、金额与日期语义、分页顺序均以 Spec 第 3、4 节为唯一约定。
- 由一个应用服务协调校验、标识生成和仓储写入；HTTP 适配器调用该服务，统一映射成功与错误，不在每条路由中另写一套实体规则。
- 仓储负责顶层数组格式、文件不存在时的空列表、损坏数据保护、串行化读改写与原子替换。写入失败不得破坏旧文件，也不得先返回成功。
- 按 Spec 第 4.3 节接入五条接口。编辑保留标识与数组位置，不存在时返回 404，不做 upsert；设置值直接读服务端常量。
- 确定启动入口时保证相同项目始终使用同一文件，限定本机服务。当前没有任何已确定的 HTTP 框架；U2 未解决前不新增框架或桌面壳来冒充“沿用现有栈”。
- 未来实际开发交付时将 README 的时区说明与 UTC 代码保持一致；若实施时发现已有 JSON 文件或调用者，先核验兼容方式，不能静默覆盖未知结构。

## 关联与依赖

- 所属目标：本期查看、新增和编辑的共同数据基础。
- 前置成果：本 Spec 已提供字段及错误契约；最终 HTTP 适配、运行与启动方式依赖 U2。视觉设计与归档政策不是仓储工作的前置条件。
- 解除依据：U2 的结果应原位写回 Spec，并交付可运行的本地服务入口；003 消费读取接口，004 消费写入接口。
- 共享修改：本任务负责 Python 仓储、服务与接口层；前端任务不得另建独立数据存储或改写公共错误语义。

## 预期结果

| 前提／操作 | 可观察结果 |
| --- | --- |
| 文件不存在，读取列表和设置 | 返回空列表及真实 UTC/保存路径；不虚构示例数据。 |
| 创建合法记录，再重新读取或重启服务 | 获得稳定 `id`，列表和详情能读到同一持久记录。 |
| 编辑现有标识，或更新不存在的标识 | 前者只修改指定记录且保留 `id`；后者 404，不新增。 |
| 使用非法金额、日期、缺少字段或非法分页参数 | 返回统一字段错误，不修改文件。 |
| 文件损坏、读取失败或写入失败 | 分别返回对应错误，不覆盖原数据、不虚报保存成功。 |
