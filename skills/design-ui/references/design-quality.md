# 好坏设计参考

用于制作完整前端原型。AI slop 是脱离内容、机械拼装常见样式的界面；下表套路默认避免，用户明确指定或内容确有需要时再使用，必要理由放在 HTML 已有的折叠说明区。按用途和整体效果判断，不以命中数量判定；用户指定的参考、组件、字体、背景、配色和动效优先。来源与模拟限制同处说明，Token 文档记录本版实际样式；具体数值和制作方法见 [设计系统与组件规则](design-system.md)，本页不追加评分、验收或报告。

## 什么不好，什么更好

| 方面 | 不好的设计：默认避免 | 好的设计：按内容落实 |
| --- | --- | --- |
| 产品特点与页面长度 | 不管产品用途，都套居中 Hero、顶部 badge/pill、logo 墙、评价、FAQ 和反复出现的行动按钮；为了“完整”堆十个区块，换个 logo 就能套给任何同类产品。 | 从用户任务、内容和品牌决定首屏与页面长度，每个区块都有实际用途；工具界面直接呈现工作内容，保留熟悉的操作方式。 |
| 页面与打开方式 | 只做首页或一级页；按 Spec 数量机械分页，所有入口都弹同一种提示或挤进弹窗。 | 覆盖本次全部页面与二三级子页，明确内容归属、当前位置和返回路径；按关系选择独立页、标签、弹窗、抽屉或内联展开，能进入、关闭和返回。 |
| 布局与容器 | 三四张一模一样的图标特征卡；卡片套卡片，一切都塞进等大网格并居中对齐。 | 按阅读、比较和操作需要选择列表、表格、分栏或卡片；用宽窄、疏密形成节奏，只在内容确需分组时加容器，同类信息保持可比较。 |
| 视觉层级 | 所有元素一样大、一样重，多个主按钮抢注意；每个标题都给单个词换色、斜体或加粗。 | 当前任务有明显焦点，以字号、字重、位置和留白区分主次；强调对应真正重要的内容，次要信息弱化后仍清楚可读。 |
| 间距 | 随手堆 13px、27px 等零散数值；元素距离全一样，看不出分组；用大空洞冒充简洁。 | 优先复用项目间距刻度；相关内容靠近，不相关内容拉开，必要的视觉微调有依据。 |
| 字体与排版 | 不看内容就全站套 Inter，或固定拼 Space Grotesk、Geist、Instrument Serif；字体和字号过多，层次全靠小号灰字。 | 依参考、语言和阅读场景选择少量字体与字号层级；层次靠字号、字重和行高，落实中文、英文与数字表现，真实加载和回退如实区分。 |
| 标签与符号 | 每个标题上方都有全大写、加宽字距的 eyebrow；滥用等宽小标签、胶囊和状态圆点，以及 `→`、`A · B · C`、`WORD — fragment`；非序列内容也编 `01/02/03`。 | 标签、符号和编号表达真实分类、状态、方向或顺序；能直接说明的内容直接写，不为装饰重复加一层英文小标题。 |
| 配色与背景 | 默认紫/靛蓝渐变、渐变标题与按钮；反复套奶油底＋衬线＋赤陶色，或近黑底＋荧光绿/朱红；无理由固定深色模式或 `#0B0B0B`、`#111`。 | 按品牌、内容和使用环境定色，通常以一套中性色阶、一个主色与必要语义色组织；主色突出重点，背景区分层次，整套页面保持一致。 |
| 对比度 | 深色模式用中灰字压深灰底，灰字压彩色底；用低对比度掩盖拥挤或次要内容。 | 正文、辅助文字、必要控件与状态标记都清楚可辨，深浅主题同样处理；按设计系统参考中的适用对象和对比度要求制作，不把装饰线一概当作控件边界。 |
| 圆角与形状 | 所有元素都用 `rounded-2xl/3xl`，或同类按钮、卡片、输入框各用一套圆角。 | 按组件角色使用少量圆角规格，同类保持一致；嵌套容器结合内边距协调内外圆角，不把大圆角当成统一风格的全部。 |
| 深度与装饰 | 每张卡都加柔和灰阴影、彩色光晕和毛玻璃；无意义地加彩色顶/左边条、光斑、星形、十字线或漂浮图形。 | 用背景色差、细边框或少量阴影区分层次；玻璃、发光和彩色边条只服务于明确风格或语义，不层层叠加。 |
| 图标 | 用 emoji 代替导航和操作图标；混用多套图标、不同描边，图标比文字还抢眼。 | 优先沿用同一图标库，统一描边和尺寸刻度；图标帮助识别操作，含义不明确时配文字，避免无关装饰。 |
| 文案 | “快速。简单。强大。”式三连口号，或“Unlock your potential”“Revolutionize…”；按钮只写 Submit，失败只写“出错了”。 | 写具体对象与动作，如“保存修改”；错误说明原因和下一步，文案帮助用户识别、决定和操作，不用空泛口号填版面。 |
| 小字与注释 | 每个区块、标题、卡片和按钮旁都加说明；反复用 `text-xs text-gray-400` 堆副标题、补充句和无用脚注。 | 先删重复解释；保留确有帮助的输入要求、条件、单位和错误提示，放在相关位置且清楚可读。设计理由与来源统一收进折叠说明区，不占满产品页面。 |
| 数字与可信度 | 编造一排 stat、客户 logo、评价、头像和“10,000+ 用户”；凭空显示“系统正常”“实时同步”“AI 在线”。 | 指标和背书有真实依据；原型可用明确标注的样例数据，状态由实际行为支持，模拟成功不冒充服务接通。 |
| 内容、素材与密度 | Lorem ipsum、两条过短数据、空框和灰条假仪表盘掩盖内容不足；无关图库或过小截图替代核心信息。 | 用接近真实长度的中英文、数字和代表样例，呈现目标尺寸下可信的导航比例、行高、列宽、换行、滚动与分页；图片服务于内容，重要细节可辨认。 |
| 组件状态 | 数据没来就空白，报错只有红字 Error；只有静态按钮，没有焦点、禁用或操作反馈。 | 按需设计加载、空数据、错误、成功及悬停、焦点、选中、禁用状态；说明发生了什么、还能做什么，失败时提供合适的恢复入口。 |
| 动效 | 每个区块都淡入上滑、每张卡 hover 都上浮或放大、元素无限弹跳；只写“顺滑”却无法触发。 | 动效回应操作、说明变化和位置关系；需要入场时集中安排，避免到处重复。原型中可触发、可重看，明确时长、延迟和缓动，支持减少动态效果。 |
| 依据与整体成品 | 指定组件、字体和参考只出现在说明里；风格只在首页成立，业务页另起一套；色卡和按钮陈列完整，用户仍要脑补产品。 | 在完整页面落实参考中的比例、组件变体、主题和视觉要求，统一贯穿各页；区分原库使用与视觉模拟，先呈现产品界面，再附实际来源和对应 Token。 |
