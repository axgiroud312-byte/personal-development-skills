# 好设计与坏设计

这份参考用于制作完整前端原型。用户指定的参考、组件与视觉要求优先；在需求范围内组织全部页面，再呈现视觉、状态和动效，功能可以用本地样例简化。来源、模拟内容和资源限制放在 HTML 折叠说明区，Token 取自本版实际样式；做好即交付，不因此增加验收、评分或报告。理念参考 [Taste Skill 设计方向](https://github.com/Leonxlnx/taste-skill/blob/6010f91a9935f1c167dfc500fb1a475681892e6b/skills/taste-skill/library/directions.json)和[设计分析](https://github.com/Leonxlnx/taste-skill/blob/6010f91a9935f1c167dfc500fb1a475681892e6b/skills/taste-skill/references/research.md)。

| 设计问题 | 不好的设计 | 好的设计 |
| --- | --- | --- |
| 是否像这个产品 | 任意项目都套大标题、三张卡片、评价和价格表。 | 由用户任务、内容、品牌和限制决定布局，让产品特点体现在真实业务区。 |
| 页面是否完整 | 只做首页或一级页，子页入口没有画面；摆齐按钮色卡却看不出产品。 | 展示范围内全部页面层级、详情与设置子页，同模板共用代表性样例。 |
| 内容放在哪里 | 按 Spec、前后端或开发任务机械划页，跨模块入口遗漏。 | 按内容关系与用户任务分组，区分全局导航、局部标签和页内区域。 |
| 打开与返回 | 所有操作都弹同一种提示；用户不知道自己在哪、如何返回。 | 页面、弹窗、抽屉和展开各有用途，轻量点击能看清去向、层级与底层关系。 |
| 视觉主次 | 每块同样抢眼，字号接近、层次混乱；靠“高级感”解释选择。 | 用大小、位置、疏密和明暗安排顺序，让主要任务先被看到。 |
| 留白与密度 | 删除装饰后留下大洞；用两条短数据把工作台做成空卡片展厅。 | 留白用于分组和节奏；按目标尺寸呈现可信的行数、列宽、长文本和滚动。 |
| 一致性 | 首页有风格，业务页回到默认模板；同类操作随意换样式。 | 字体、颜色、间距、对齐、图片与组件形成同一套表达，保留有助比较的重复。 |
| 指定参考与组件 | 只抄背景色；用手写近似控件和回退字体却声称已使用指定资源。 | 落实指定布局、比例、组件变体与字体字重；替代和视觉模拟明确说明差异。 |
| 渐变与装饰 | 渐变、发光、彩色光斑、星形或线条到处堆，和内容无关。 | 效果服务于品牌、信息层级或反馈；是否使用由具体方案决定，不统一禁用。 |
| 标签与文字 | 无用途的英文小标题、胶囊标签、NEW；每张卡片都附口号和解释。 | 文字帮助识别、操作和理解；保留字段标签、要求、分类、错误提示，删掉不影响理解的赘述。 |
| 可读性 | 用极小字号、低对比度或夸张字距把多余说明塞进去。 | 标题、正文、辅助文字有明确用途和可读尺寸，中文、英文与数字排版协调。 |
| 数字与状态 | 装饰性编号，编造销量评分，随意写“系统正常”“实时同步”。 | 数字表达真实顺序、金额或进度；样例标明模拟，不冒充服务接通或真实业绩。 |
| 图片与内容 | 无关图库、过小截图、灰条假仪表盘或泛泛图标替代核心内容。 | 展示对象、环境和产品特点，重要细节可看清；内容丰富来自有效信息和组织。 |
| 状态与动效 | 只写动效名，加载与错误看不到；动画为热闹而存在。 | 动效表达变化、关系和反馈，可触发重看；状态用样例展示，支持减少动态效果。 |
