# 好坏设计参考

用于制作完整前端原型，用户指定参考、组件、字体、背景、配色和动效优先；通用原则不能覆盖明确要求。以真实页面表达信息架构、视觉和交互，功能可用样例简化，来源与模拟限制放在 HTML 的折叠说明区，Token 记录本版实际样式；这些是制作参考，不附加评审、评分或验收报告。理念参考 [Taste Skill 设计方向](https://github.com/Leonxlnx/taste-skill/blob/6010f91a9935f1c167dfc500fb1a475681892e6b/skills/taste-skill/library/directions.json)与[设计分析](https://github.com/Leonxlnx/taste-skill/blob/6010f91a9935f1c167dfc500fb1a475681892e6b/skills/taste-skill/references/research.md)。

## 什么不好，什么更好

| 方面 | 不好的设计 | 好的设计 |
| --- | --- | --- |
| 产品特点 | 无论什么产品都套“大标题、三张卡片、评价、价格表”，靠“高级感”代替设计依据。 | 从用户任务、内容、品牌和限制决定布局；工具界面以真实任务和数据体现特点，保留熟悉的操作方式。 |
| 内容与层级 | 只做首页和一级页；页面名字齐全，入口没有对应画面；按 Spec 数量机械分页。 | 覆盖范围内页面和子页，明确内容归属、父子关系、当前位置与返回路径，同模板记录用代表样例即可。 |
| 打开方式 | 每个入口都弹同一种提示，或所有功能都塞进弹窗。 | 按内容关系选择独立页、标签、弹窗、抽屉或内联展开，能点击进入、关闭和返回。 |
| 阅读顺序 | 每块都抢眼、字号接近、信息没有主次。 | 用大小、位置、疏密和明暗突出主任务，辅助信息仍清楚可读。 |
| 留白与密度 | 用大空洞装“极简”，两条短数据掩盖实际拥挤；导航、表格和正文比例失真。 | 留白承担分组和节奏，按目标尺寸呈现可信行数、列宽、控件尺寸、换行和滚动；紧凑有秩序，宽松有内容。 |
| 统一与变化 | 风格只在首屏成立，正文和业务页另一套；为新奇破坏可比较的列表与表格。 | 字体、颜色、间距、图片和组件相互协调，特点贯穿各页；同类信息和操作保持一致。 |
| 色彩与装饰 | 随处加渐变、发光、光斑、圆点、星形、十字线、漂浮图形或无关图标。 | 颜色表达层次、强调和状态，装饰服务于品牌与内容；渐变、阴影、细线、等宽字与圆角按指定方案和用途使用。 |
| 标签与文案 | 无意义地堆英文小标题、胶囊、NEW、PREMIUM；每张卡都重复介绍，再用小字和低对比度掩盖。 | 文案用于识别、操作和理解；保留必要字段、输入要求、分类、步骤及错误提示，删掉无作用的口号和重复解释。 |
| 数字与状态 | 无顺序却编号，把样例人数、销量、评分当业绩；凭空写“系统正常”“实时同步”“AI 在线”。 | 数字与状态有真实业务含义；样例和模拟明确说明，不能暗示服务已接通。 |
| 内容与图片 | 空框、灰条假仪表盘、无关图库或过小截图替代核心信息；素材冒充真实产品或人员。 | 用接近实际长度的中英文和数字组织页面；图片表现对象与环境，重要细节可放大，丰富感来自内容与清楚的组织。 |
| 指定依据 | 指定组件、字体与参考只写在说明里，实际仍用默认模板和回退字体，未说明差别。 | 在页面落实组件变体、主题、字体和字重；直接使用与视觉模拟、真实加载与回退如实区分。 |
| 状态与动效 | 只写“淡入”“顺滑”，无法触发；动态效果遮挡操作或没有减少动态效果处理。 | 加载、空、错、成功等状态可展示；动效表达变化与位置关系，能触发和重看，节奏明确并尊重减少动态效果设置。 |
| 整体成品 | 色卡和按钮陈列完整，用户仍需自己脑补产品；说明报告比界面更抢眼。 | 先看到完整产品页面，导航、布局、内容、组件与交互组合成一套可理解的原型，附属说明收起。 |
