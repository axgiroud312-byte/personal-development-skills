# 设计质量参考

用于网页、Web 应用、后台、桌面 GUI、移动端等前端的设计与评审。按产品、内容、设备和用户任务判断，不把某种颜色或风格当成唯一答案；已有明确要求和有效项目约定优先。

设计板以 HTML 展示设计，不默认实现完整应用。布局、页面导航和列表分页以概略表达为主；组件样式、状态和动效应具体可见。结构覆盖与视觉质量不能省略，但不以业务功能实现数量评分，也不为展示板擅自扩展需求。

## 怎样判断设计好不好

### 设计要符合这个项目

从功能、名字、场所、材料、独特限制或用户工作方式寻找依据。明确用户需要理解、相信或完成什么；布局表现内容的主次、因果与先后，避免所有项目都套“大标题、三张卡片、评价、价格表”。

确定主要吸引点，如真实图片、文字大小对比、作品排列或可信的产品演示。用一句话说明项目特点如何影响布局或操作；换个名字就能给竞争者原样使用时，继续寻找具体依据。工具界面可通过真实任务与数据体现特点，不强加艺术表达。

### 重要内容要先被看到

用大小、位置、疏密和明暗安排阅读顺序，让主任务先被看到，辅助信息仍清楚。避免每块都抢眼、字号都接近，或所有信息同样重要。

留白用于分组、突出重点或调整节奏。删掉装饰留下的洞、过大段落间隔和窄小文字旁的空地，不能只用“极简”解释；按内容补信息、放大重点或收紧布局。紧凑要分得清，宽松也要完整。

### 整个界面要像同一套设计

字体、色彩、间距、对齐、图片和组件相互配合，特点延续到正文、业务区与结尾。保留表格、列表和同类操作中有助比较与学习的重复，不为求新破坏一致性。

颜色有明确用途，字体适合内容并清楚可读。渐变、阴影、细线、等宽字和圆角按品牌与用途判断，不统一禁止；避免无理由反复堆叠。已确认的个人偏好仍是默认方向。

### 页面要有值得看的真实内容

图片应展示对象、环境或产品特点，重要细节可以放大。产品界面要可读，避免无关图库、过小截图、灰条假仪表盘或泛泛图标代替核心内容；素材不能冒充客户真实产品、人员或场所。

丰富感可来自充分内容、大小对比、图片、大面积色彩、排版或清楚组织的数据。简洁需要内容与细节，复杂需要秩序；去掉装饰后仍应充实，不能像没做完的空架子。

### 视觉效果要帮助理解和操作

介绍产品或作品时，用图片、事实或演示说明特点；工具界面帮助看懂数据、比较和操作。视觉效果不能遮住主体、让信息难找或拖延操作。

需求包含窄屏时，重新安排内容顺序、图片裁切、布局与操作空间，避免只缩小桌面；不对所有项目强制额外设备适配。交互和动效用于说明变化、位置关系与反馈。

## 哪些是不好的设计

不为填满空间或显得精致添加无作用的效果，也不用“高级感”“科技感”代替设计理由。

| 问题 | 具体表现 |
| --- | --- |
| 无意义的渐变 | 背景、标题、按钮到处加渐变、发光或彩色光斑，与品牌、内容和阅读顺序无关。 |
| 多余的小标签 | 反复加英文小标题、胶囊徽章、NEW、PREMIUM，既不帮助分类和导航，也不说明真实差异。 |
| 多余的介绍和小字 | 每个页面、卡片、控件都配介绍、口号或说明，删掉也不影响使用，却靠小字、变灰或拉大字距塞进去。 |
| 随意的小装饰 | 圆点、星形、十字线、角标、漂浮图形或无关图标没有表达作用，反而分散注意力。 |
| 装饰性或编造的数字 | 给无先后顺序的内容加编号，用无关版本号、坐标或百分比填位置，编造人数、销量或评分。 |
| 无依据的状态表达 | 没有对应功能或真实状态来源，却显示“系统正常”“实时同步”“AI 在线”、绿点或呼吸动画。 |

界面文字服务于识别、操作和理解，删掉后不影响这些目的的默认删去。例如标题已有“项目”，通常不必再写“在这里查看和管理你的所有项目”；不用小字或低对比度掩盖多余文字。

保留清楚可读的字段标签、输入要求、真实分类、操作步骤、金额与进度、重要状态、错误原因、恢复方法及操作后果。样例和模拟状态明确标注，不能冒充真实业务结果。

设计理由、开发说明和组件来源放在设计文档或设计板说明区，不混入产品页面。设计板的 Token 名称、数值等说明可以保留。

## 怎样在实际页面上检查

展示的标签、角色、成功与失败等含义应与已确认需求和已有规则一致。可以用静态例子或开关重现状态，不要求真实接口、鉴权、数据持久化或业务状态机；政策未知时保留待定。说明区标清静态样例、效果演示与真实接通的区别，不把展示效果当业务验收结果。

1. 核对需求中的布局和页面概貌是否可见，导航关系、列表及分页样式是否清楚。概略表达可以通过少量样例或简单切换完成，不要求正式路由、真实搜索排序或分页逻辑。
2. 实际打开 HTML，重点检查采用的组件外观、尺寸与排版，查看适用的悬停、焦点、选中、禁用、加载、空数据和错误等状态，并触发已采用的动效。只操作演示需要的菜单、弹窗或状态开关，核对关闭、焦点和减少动态效果；不要求跑通完整业务。
3. 在目标尺寸下核对文字可读、重点清楚、内容无溢出，删除重复且没有作用的说明，保留必要标签与反馈。发现问题时说明位置、影响和具体改法；先修结构与视觉问题，再调整细节。截图不能证明动效或演示交互已通过。
4. 修改后复查受影响的展示内容，核对 Token 与实际采用样式一致。已有充分证据时停止重复检查；未验证或受阻部分如实交代，不把候选、静态样例或模拟结果说成产品功能已经完成。
