# 设计系统与组件规则

进入完整原型制作前读取。先沿用项目与用户已确认的参考、主题和组件，只补本次需要的规则；下面的尺寸与节奏是无既定约定时的起始值，按设备、内容密度和实际字体调整。这里约定制作方法，不新增设计交付文件、测试阶段或评审报告。

## Token 放在实际样式中

先读取现有主题、CSS 变量、组件配置和设计记录，从 `globals.css` 等实际入口取得已有命名和值，在 HTML 自身 `<style>` 的 `:root` 中复用本次需要的 Token。缺失部分在原型样式中补齐，不为原型修改生产主题、初始化框架或另建一份 DESIGN.md。

页面和自建组件的 UI 颜色统一引用语义 Token：色值只在 Token 定义处维护，组件中不散写 hex、rgb、hsl、oklch 或 `bg-blue-500`、`text-gray-400` 一类原始色阶类。已有第三方组件优先通过主题 API 定制，不为套规则重写整个库。

| 层级 | 使用方式 |
| --- | --- |
| 原始值 | 用于共用的颜色、间距和字号刻度，只表达数值；已有项目直接复用。 |
| 语义 | 按用途命名，如 `background`、`foreground`、`primary`、`primary-foreground`、`muted-foreground`、`border`、`ring`、`destructive`；引用原始值，或在此集中定义实际值。 |
| 组件 | 只有组件确需偏离共用规则时增加，如特定控件尺寸；不为每个组件复制完整主题。 |

保持引用简单、无循环，避免无意义的多层别名；新小项目先有必要的语义 Token 即可，不要求铺满三层。间距、排版、圆角、阴影和动效沿用共用刻度，使用变量或对应刻度类；确需偏离时说明用途并记录实际值。

已有 [shadcn/ui](https://ui.shadcn.com/docs/theming) 项目沿用成对的背景/前景语义名；[Tailwind v4](https://tailwindcss.com/docs/theme#referencing-other-variables) 用 `@theme inline` 将已有变量映射到主题，例如 `--color-warning: var(--warning)`，再用 `bg-warning`。按实际版本处理，普通 HTML 不需要引入 Tailwind。

## 排版、间距与形状的起始值

| 项目 | 起始约定 |
| --- | --- |
| 间距 | 4/8/12/16/24/32/48/64/96px；组内小于组间。控件内部通常 4–12px，组件之间 16–32px；大区块留白按内容密度决定，工具界面不套落地页间距。 |
| 字体与字号 | 通常 1–2 个字体家族，从 12/14/16/18/20/24/30/36/48/60px 中选 4–6 档；正文默认 16px，密集表格可用 14px，辅助文字默认不小于 12px。 |
| 行高与字重 | 正文行高 1.5–1.7，中文长文可用 1.6–1.8，标题 1.1–1.3；正文 400，强调 500 或 600，标题 600 或 700，通常不超过三种字重。 |
| 圆角 | 选一个基准，按组件角色派生少量规格；同心嵌套可按外圆角减内边距协调内圆角，最小为 0，不把所有容器和控件都做成大圆角。 |
| 阴影与边框 | 阴影通常 2–3 级；先用留白和背景色差分组，再按需要补细边框或阴影，不在每层容器重复叠装饰。 |

沿用指定字体并落实实际加载；需要回退时补合适中文字体，如 PingFang SC、Noto Sans SC、Microsoft YaHei。中文默认不用斜体；数字、金额和时间列可用 `tabular-nums`。标题字距只按字体需要微调，少用全大写和加宽字距标签。

正文、表单和列表默认左对齐，居中用于适合的短内容；长文行宽可从英文 45–75 字符、中文约 25–40 字/行起步。标题语义与视觉大小分别处理，层级清楚、主标题具体；保留表单标签，删除无助理解的重复数据标签和小字解释。

## 配色与可读性

通常以一套中性色、一个主色和必要语义色组织；重点色服务于主操作、选中态和关键内容。具体色值来自本项目的方向，示例颜色不成为默认品牌。渐变或光晕确有需要时也集中定义 Token。

普通文字与背景至少 4.5:1，大字（至少 24px，或约 18.7px 粗体）至少 3:1；占位文字和次要文字也要清楚，见 [WCAG 文字要求](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。识别控件、状态及关键图形所必需的非文字视觉信息对相邻色至少 3:1；纯装饰线不一概适用，见 [非文字要求](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)。状态不能仅靠颜色区分，应有文字、图形或其它可辨识线索。

只在本次范围需要时提供深浅两套主题；通过同一批语义 Token 重新映射，用表面明度区分层级，不简单反色。背景和前景、边界和焦点成对考虑，不因深色模式而弱化可读性。

## 组件与交互

优先复用现有组件、变体与定制；单 HTML 原型缺少的表现用共用样式和轻量脚本补齐，无法直接使用的组件按主技能标明视觉模拟。生产组件的扩展按后续实现授权处理。

- **操作与图标：** 当前任务区域主次分明；按钮写清动作与对象，流程中称呼一致。交互元素提供适用的悬停、焦点、按下和禁用反馈，用 `:focus-visible` 保留键盘焦点。一套图标库、统一描边，尺寸可取 16/20/24px；纯图标按钮有可访问名称。
- **表单：** 标签常驻且与控件关联，placeholder 不代替标签；输入要求与字段错误就近说明。通常在失焦或提交时校验，错误后保留输入，按字段选择 `type`、`inputmode` 和 `autocomplete`。
- **列表与导航：** 数字便于纵向比较，排序和当前位置可辨认；长内容有合适换行或省略与查看出口。固定表头、分页或滚动按数据量和窗口需要选择。
- **浮层与反馈：** 模态框打开后管理焦点，支持关闭与 Esc，关闭后回到触发位置或合理的后续位置，参照 [对话框模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)。破坏性操作按风险提供确认或撤销；短暂通知用于操作反馈，必须阅读的错误或说明保留在页面中。

## 状态与代表性内容

为本次确实存在的读取、提交和操作补相应状态；原型可用可切换样例演示，不因此接入后端或实现正式异常框架。

| 状态 | 应表达的内容 |
| --- | --- |
| 加载与提交中 | 稳定占位或明确反馈，避免布局突然跳动；保留动作含义，防止重复提交。 |
| 空数据与无结果 | 说明这里会有什么，并提供合适的下一步，例如新增、清除筛选或更换关键词。 |
| 错误与部分失败 | 用人话说明原因和恢复方式，保留输入；能局部恢复时不让整个界面空白，实际错误含义沿用业务约定。 |
| 成功与禁用 | 反馈操作结果，已有撤销能力时呈现入口；禁用原因不明显时说明原因，不给每个控件堆注释。 |

用零条、一条、多条、长名称、大数字和缺失素材等代表内容呈现密度与边界；设计乐观反馈时同时说明失败恢复。样例数据与真实接入清楚区分，不编造指标、客户或服务状态。

## 适配与动效

以用户指定设备和窗口为范围，不默认 Mobile-first 或追加手机端。需要适配时，内容宽度、网格和分栏随内容与空间调整；表格可在自身容器滚动，图片保持比例，长文本和放大后的内容有可访问出口。触屏功能不只依靠 hover，可点击目标优先做大；触屏常用 44px 起步，紧凑目标按 [WCAG 尺寸与间距要求](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) 处理。

动效服务于操作反馈和位置变化，默认省去装饰性循环与全区块重复入场。微交互可从 120–200ms、展开或浮层从 200–300ms 起步，统一时长和缓动 Token，优先使用 `transform`、`opacity`。尊重 `prefers-reduced-motion`，减少或关闭位移、缩放和循环，保留必要状态反馈；内容可用性不依赖动画结束。
