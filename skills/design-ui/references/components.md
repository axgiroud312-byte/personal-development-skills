# 组件选型与 shadcn 衔接

在确定组件方案、安装或调整组件时读取。选择服务于项目用途，用户指定的组件、来源、技术栈与参考优先。

通用 SaaS、工作台与 Agent 界面的具体默认方案见 [前端默认搭配](frontend-defaults.md)。这是用户的选型偏好，不是实时流行度排名；先按所需能力选用其中方案，再为未覆盖的需求寻找社区组件。同一种能力优先沿用同一个方案，按页面需要引入依赖。

## 选择顺序与依据

1. 盘点已有组件及其业务行为；适合当前设计的直接复用，包括用户自研组件。
2. 基础控件和常见组合优先采用 shadcn，沿用项目的底层组件体系、主题、图标和变体约定。
3. 缺口查找成熟的社区开源组件或 registry。在满足功能、技术栈与设计适配的候选中，优先考虑社区广泛采用、持续维护、文档完整的方案。核对官方仓库与文档、近期发布、真实使用或下载证据、兼容性及适用的开源许可；星数仅作辅助，不能据此宣称“社区最常用”。按选型影响控制调查范围。
4. 业务特有能力优先组合已有组件；仍有缺口时明确自研范围与原因。避免为一个控件混入另一套完整视觉和交互体系。

组件清单写入项目设计规范，至少能回答：

| 信息 | 用途 |
| --- | --- |
| 组件、用途与使用位置 | 本次为什么需要，哪些场景使用或不使用 |
| 来源与版本依据 | 项目代码路径、开源仓库/文档、包或 registry 标识，选用版本或核对日期 |
| 选择与调整 | 直接复用、组合、修改变体或自研；选择原因和必要调整 |
| Token、变体与尺寸 | 消费哪些语义定义，哪些尺寸和变体可用 |
| 行为与状态 | 适用状态、键盘/焦点、反馈与错误恢复，引用共享规则 |

用实际来源和版本，不虚构已安装组件。没有网络证据时标明未核实，不把候选写成已确认的流行度或兼容性结论。前端组件与样板共用选型结果，后续 Issue 引用这份清单。

## 工程接入

- 有实际 UI 项目时，按项目包管理器使用 shadcn CLI，在项目根目录运行 `info --json`；命令不可用时读取 `components.json`、包文件与实际源码，说明无法确认的内容。没有检测到配置就不能假定别名、底层库、图标或已安装组件。
- 搜索官方与相关社区 registry，查看候选内容；使用组件前获取当前组件文档及示例。读取可用的 `shadcn` Skill 处理这些命令与 API，不把机器路径写进可分发的 Skill。
- 先确定并记录来源，再按明确 registry/组件名执行安装或交接。例行选型按本工作流偏好由 Agent 判断；只有确实影响需求、既有设计或授权范围的歧义才交给用户。
- 查看已有组件后按需添加。更新已有代码先检查差异，保留项目定制；不为了套用预设覆盖无关界面或批量安装所有组件。
- 检查导入别名、依赖、图标、样式、行为和状态是否与项目一致。第三方或自研组件同样消费共享 Token，使用相同的反馈、焦点与恢复规则。

当前官方依据：[shadcn 文档](https://ui.shadcn.com/docs)、[主题与语义变量](https://ui.shadcn.com/docs/theming)、[社区目录](https://ui.shadcn.com/docs/directory)、[自有组件 registry](https://ui.shadcn.com/docs/registry)。实际选型时核对当前内容，不固定一张永久组件库排行榜。
