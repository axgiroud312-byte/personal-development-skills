# 交互、状态与验收

设计交互和选择验收项时读取。以下是用户约定的设计底线；按本次组件、页面和平台选择适用项。不适用项说明原因，不要求每个控件都具有所有状态，也不把这些检查称为完整 WCAG 合规认证。

## 统一操作规则

| 操作 | 项目内需要稳定的规则 |
| --- | --- |
| 保存 | 点击后立即有处理中反馈；避免同一次操作重复提交；成功明确告知结果；失败保留输入并提供修正或重试办法，结束后恢复适当的可操作状态 |
| 弹窗与菜单 | 明确打开、关闭、Escape/外部点击的行为与未保存内容处理；管理进入、移动、退出和返回焦点；模态框与菜单采用各自的键盘模式 |
| 返回 | 用户能预期回到哪里，以及草稿、筛选和位置是否保留；有未保存内容时采用一致且符合业务的处理 |
| 删除 | 按业务规则与可恢复程度确定确认、处理中反馈、失败恢复或撤销；破坏性行为有明确对象和结果，不能只靠颜色表达 |
| 筛选 | 即时应用或提交后应用的模式一致；显示已生效条件，提供清除/重置；无结果时可理解且有恢复路径 |

业务层是否保存、重试或删除哪些对象由领域定义决定；本文件只规定如何呈现和操作。不要为统一界面而悄悄改变业务规则。

## 分成两层检查

- **控件状态**：默认、悬停、按下、键盘焦点、禁用、选中、处理中。表单按需要补充校验错误；触屏操作不能依赖悬停才可发现。
- **页面和数据状态**：加载中、正常内容、首次没有数据、搜索无结果、权限不足、部分失败、保存成功、保存失败。首次空数据与搜索无结果采用对应原因和下一步；部分失败保留已成功内容并说明可恢复部分。

对适用状态明确触发条件、视觉/文案、可用操作和状态转移。样板能展示关键状态并实际操作相关流程；“有一张错误截图”不能证明保存失败会保留用户输入。状态提示应能被辅助技术获取，反馈不无故抢走输入焦点。

## 排版、层级与内容

从真实或有代表性的内容检查注意力层级、对齐、间距、字重与可预测的阅读顺序。字体与图标形成一致体系，表面、边框、阴影用于解释层级；保留一两个产品特征并在重复细节中延续。

按本次使用场景覆盖长短文本、真实中文、数字、空内容和密集内容。检查控件对齐、文本截断或换行、放大后阅读与操作、固定区与滚动区关系。用户参考给出明确几何时，在相应视口记录关键尺寸和差异，避免只做主观“相似”判断。

## 动效

优先用于确认操作被接收、解释内容来源与去向、维持展开/收起/切换的空间关系和平滑状态变化。根据距离、组件大小和操作频率选择时长与缓动；日常操作迅速，重要内容和操作不必等待动画完成。

尊重 `prefers-reduced-motion`，减少或替换非必要位移与复杂动画，同时保留可理解的状态反馈。这是本工作流的明确要求；WCAG 的交互动画可关闭条款为 AAA，不将其误标为 AA。

## 可测量底线

标准核对日期：2026-10-21。发生标准或实现争议时查下方官方依据。

| 项目 | 验收依据与范围 |
| --- | --- |
| 文字对比度 | WCAG 2.2 AA：普通文字至少 4.5:1；符合定义的大字至少 3:1。大字通常为至少 18pt，或至少 14pt 粗体（中日韩字体采用等效字号）；停用控件、纯装饰、Logo 等有条款例外。按实际前景/背景与适用主题测量，不能只看调色板 |
| 点击区域 | WCAG 2.2 AA：实际命中区域通常至少 24×24 CSS px。保留间距、同页等效控件、行内目标、未改动的浏览器控件和必要呈现等例外；间距例外按以目标为中心的直径 24px 圆不相交规则判断。触屏主要操作选择更宽裕的区域 |
| 键盘与焦点 | 功能可用键盘完成，除条款允许的本质依赖移动轨迹等情况；焦点可见、不会完全被作者内容遮挡，也不会被困住。实测 Tab/Shift+Tab、相应方向键、Enter/Space、Escape 与关闭后的合理回焦。模态框内部约束焦点，菜单按菜单模式操作 |
| 窄屏与放大 | 普通纵向内容在等效 320 CSS px 宽度重排，不丢失信息或功能，不要求双向滚动；必要二维内容如地图、数据表格可例外。按实际页面检查，而不是强行把二维内容变成一列 |
| 加载与响应 | 网页的良好目标：LCP ≤2.5s、INP ≤200ms、CLS ≤0.1。真实用户判断用 p75，并区分移动端与桌面端；实验室数据用于诊断和回归，不能代替真实用户达标结论。没有真实数据时写清未验证；普通 Lighthouse 加载测试的 TBT 不能当作 INP |

桌面产品还要在目标桌面窗口检查实际布局、反馈和交互；浏览器替代检查应标明范围。检查按风险和改动范围选择，结果区分通过、失败、未验证及合理不适用。图形展示、类型检查、打包成功均不能替代尚未操作过的交互验收。
