# 设计界面与交互

将产品需求转成可复用、可检查的界面设计。用中文说明选择与实际结果。默认交付设计规范、真实 Token 定义、本次组件清单及可操作的关键页面样板；用户只要求讨论、评审或文字方案时遵守该范围。

## 先理解内容与使用场景

1. 确认本次项目与实际工作目录，读取必要的需求、领域定义、Spec、现有界面、设计规范、Token 和组件。沿用已有技术栈与设计系统，只补当前变化；小范围界面修复已有依据足够时直接处理。
2. 明确用户要完成的操作、主次信息、真实内容、目标设备和输入方式。业务对象或规则不清楚时主动结合 `domain-modeling`；本技能负责呈现与交互，不自行改写业务含义。无法调查解决且会改变需求或设计方向的选择才提问，给出推荐与影响。
3. 有用户参考时先查看原图、页面或文件，提取布局关系、尺寸比例、对齐、间距、字体字重、内容密度、颜色职责和表面层级；可测量的几何作为验收依据，不能只借用配色。无法读取必要参考时明确缺项，不声称已经按图设计。响应式适配或与已确认的可用性要求冲突时说明调整依据。
4. 没有参考时，根据产品用途、内容与已有品牌选择一个推荐方向，简述理由后在本次设计实施范围内直接制作样板，再按反馈调整。不默认生成多个方向或增加选风格的确认步骤；只要求讨论或文稿时仍按该范围交付。

## 定义视觉规则和共享 Token

围绕真实内容建立可预测的秩序：先安排注意力层级和主要操作，再设计对齐、间距、排版与字重。检查真实中文、长标题、数字、密集内容和不同内容长度。为产品选择一两个适合用途的鲜明特征，例如标题字体、图标体系、品牌色或过渡方式，并在重复细节中保持一致。

Token 覆盖本次需要的语义颜色、字体与字号层级、字重、行高、间距、控件高度、圆角、边框、表面层级、阴影和动效。正文色、次要文字色、普通间距、输入框高度等应有明确名称与职责；区分品牌、操作、状态、焦点和装饰用色，错误与成功还要有文字或图形提示。

实际值只在项目既有的 Token/CSS 源文件中维护；全新项目尚无该文件时，按所选技术栈建立一个明确的 Token 源，再让组件与样板共同消费。设计规范解释名称、职责和使用条件，避免手工维护第二份数值。采用 shadcn 时沿用其语义变量和项目的实际主题入口，按需补充变量或组件变体，统一更新本次受影响的控件；局部设计通过适当的作用域或变体实现，保留范围外的现有规则。外部设计稿若另有变量系统，说明实际同步方式和已同步范围，不凭同名声称自动同步。只处理本项目需要的主题模式。

## 选择本次真正需要的组件

实际选型时读取 [组件选型与 shadcn 衔接](references/components.md)。通用 SaaS、工作台与 Agent 界面采用 [前端默认搭配](references/frontend-defaults.md)，按本页所需能力选择，已有明确项目方案优先。优先复用项目已有的合适组件；新增基础控件统一采用 shadcn，默认搭配未覆盖的缺口再从适配、常用且持续维护的社区开源组件中选择，业务特有能力可组合或自研。

选型由 Agent 依据上述偏好完成并记录明确来源、适用场景、变体、状态和必要调整。社区使用程度需有当前依据，不按过时的固定排行榜选库。只引入本次需要的组件，确保来自不同来源的组件使用同一套 Token 和行为规则。

使用 shadcn 工程能力时读取可用的 `shadcn` Skill，并在实际项目根目录核对配置、已安装组件和当前文档。将已选来源或 registry 明确传给后续安装操作。这里的项目级交付范围是本次所需组件和关键页面，不默认套用全量组件展示站、安装全部组件或替换已有项目的流程。Skill 不可用时按官方文档完成等价操作。

## 统一行为与两层状态

设计交互和选择验收项时读取 [交互、状态与验收](references/interaction-and-checks.md)。保存、弹窗、返回、删除、筛选在同一产品里保持稳定规则；外观通过 Token 和组件变体复用，行为通过共享组件和交互逻辑落实。

分别定义控件状态与页面/数据状态，记录本次适用状态、触发条件、呈现方式、用户下一步和恢复办法。普通操作保持迅速，动效用于反馈接收、解释来源与去向、维持空间关系和平滑状态变化；根据场景定参数，支持减少动态效果设置。

## 制作并实际检查关键页面样板

1. 选择能代表主任务的一条关键流程，使用选定组件、共享 Token 和真实或明确标注的代表性内容，制作可查看、可操作的页面样板。复用项目现有预览路由、故事或开发入口；按任务规模选择最小可运行方式，不为样板额外搭建完整展示系统。
2. 样板应能实际操作主要控件，并展示关键的处理中、成功、失败和恢复等适用状态。可用清楚标注的模拟数据或响应；记录模拟范围，不能把演示状态当成后端连通或持久化验收。
3. 在实际浏览器或目标桌面窗口查看并操作，核对布局、内容、状态转换、键盘与焦点，以及相关窄屏和减少动效行为。参考图涉及固定几何时按对应视口测量关键尺寸与间距，报告实际差异。截图辅助核对视觉，交互结论依据实际操作。
4. 按参考文件选择本次必要的测量和检查，修复观察到的问题。构建、检查脚本与浏览器各自只能证明实际覆盖的范围；工具或运行条件不足时说明已完成部分与未验证项，不将样板记作已验收。通过必要检查后，无新变化或失败就继续交付，不重复扩大测试或生成发布包。

## 保存依据并衔接开发

沿用项目文档位置；没有约定时用 `DESIGN.md` 保存当前视觉方向、参考依据、Token 源位置、组件清单、交互与状态约定、样板入口及检查结果。内容按任务规模取舍，不预建空模板；实现细节已有权威来源时引用。

本技能在需求和核心领域概念清楚后介入，与 Spec 往返配合。领域记录保存业务定义；设计规范保存界面呈现与交互；Spec 保存总体技术设计并引用前两者；Issue 细化本次实现和可观察验收。拆界面任务前应有足够的设计依据，开发复用样板中的 Token 和组件。

由其他 Skill 衔接时沿用原任务范围。仅写 Spec 或拆 Issue 时先补必要设计依据，尚未获授权实施的样板列入后续任务并标明待验证；已要求界面设计或整套开发时默认交付可操作样板，继续已授权工作。

发现业务规则变化时先回到领域梳理；设计、组件或 Token 变化时更新唯一有效来源及受影响的样板、Spec 和 Issue。已有完整开发授权时继续后续工作，不在样板完成后额外询问是否继续。最终交付文件与可用入口、主要设计选择、组件来源、实际验证结果和影响使用的剩余问题。
