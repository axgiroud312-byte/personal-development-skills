# 预览整套产品的界面组织与设计

帮助用户在正式开发前看到产品由哪些界面组成、如何进入和切换，以及最终大致长什么样，便于反复调整和后续开发参考。主线是信息架构与界面组织 → 视觉方案 → 组件、状态与动效 → HTML 和 Token；这些融入同一份预览，不要求额外文档或阶段批准。

以完整页面为主要展示单位，将导航、布局、内容、组件与动效组合起来；不是组件陈列、低保真线框，也不是完整应用开发。适用于网页、Web 应用、后台、桌面 GUI 和移动端，不因 HTML 展示方式改变最终产品的技术选型。

**以代码实际为主。** 代码和实际行为用于判断现状，文档不一致时沿用现有实现惯例，差异在交付说明中简述。用户明确提出或已确认的新需求决定本次目标，不能因为尚未实现而忽略。

## 使用用户指定的设计依据

读取当前需求、用户指定的参考与组件、已有项目样式及已确认偏好。明确本次范围、目标设备和尺寸，不额外增加功能或设备适配，不重复询问已有答案。

用户明确指定的组件、变体、主题、字体、字重、背景、配色和动效优先，从组织页面时就作为依据，不能被通用审美规则或 Agent 的偏好覆盖。未指定的细节按参考与已有设计合理补齐，不逐个询问间距或圆角。

打开指定的原图、页面或文件，按用户说明分别借鉴布局、比例、排版、色彩、组件或动效；没有说明时结合需求采用合适部分，不只抄背景色，也不将多个参考随意混杂。参考不可访问、资源缺失或要求相互冲突时如实说明，只澄清确实阻止呈现的选择。

制作时参考 [设计表达参考](references/design-quality.md) 中的好坏设计原则；它帮助作出设计选择，不是验收清单，不触发额外评审、评分或优化循环。只要求讨论、解释或局部修改时完成该范围；已要求制作时直接推进。

## 先组织信息架构与界面

从需求和相关 Spec 汇总本次范围内全部页面、子页面及其内容归属、入口和父子关系。明确哪些信息放在一起，哪些独立成页或作为页内分区；Spec 和开发任务的拆分不直接等同页面划分，也不能成为遗漏其他模块的理由。整产品预览覆盖已确认的产品范围，明确限定局部时才收窄；同一模板下的不同数据记录可共用代表性样例。

按指定参考与用途呈现全局布局：顶部、左侧或右侧导航、内容区、分栏、工具区和适用的滚动关系。区分全局导航、二三级菜单与页内标签，显示当前位置和选中层级；不把所有产品都强制套成左侧边栏。

各页面入口有明确去向和打开方式：进入独立页面、切换页内标签、打开弹窗或抽屉，或在原位置展开。用轻量点击演示进入、切换、返回与关闭，让用户直接看懂关系；不能只罗列页面名、将全部操作统一做成弹窗，或用通用提示代替目标画面。未指定的呈现方式按任务性质合理选择，作为可调整的设计方案，不替用户制定业务政策。

按目标窗口尺寸呈现接近实际的一屏信息量：列表行数、表格列宽、文字长度与换行、导航项目、卡片数量、留白和滚动区域。样例足以表达预期密度即可，不需要真实查询或大量数据；不因功能简化而把密集工作界面变成几张空卡片。

页面关系直接体现在 HTML 的导航与画面中；必要说明可放在附属折叠区，不另交信息架构图、页面清单或报告。可以分批制作，但不能用首页或一级页面代替本次要求的整套界面。

## 在 HTML 中呈现视觉方案、组件与动效

默认在 `docs/design/design-board.html` 制作一个 HTML 文件，已有约定位置则沿用。页面、自定义 CSS、演示脚本和组件来源说明集中在该文件，必要的外部库、字体与素材用明确的资源链接引用，并注明联网依赖；不另交应用工程或一套原型。

打开 HTML 首先看到接近预期成品的产品界面，而不是色卡、组件目录或设计说明。在同一个 HTML 中用简单状态切换串联各级页面；保持适用的全局导航与局部布局，独立页、弹窗、抽屉按各自设计呈现，不只是互不相通的截图。

简化的是功能实现，不是影响预期的视觉表达。页面切换、列表分页、标签和浮层用少量 JavaScript 与本地样例演示；无需正式路由、真实查询或生产级数据处理，不适用的页面或分页不硬加。

| 内容 | 在成品效果预览中呈现 |
| --- | --- |
| 字体与字重 | 加载指定字体与可用字重，呈现中文、英文和数字；体现标题、正文、辅助文字的字号、字重、行高与字间距。不能只写字体名却把回退字体说成指定字体已加载。 |
| 背景与配色 | 体现页面、导航、内容区、卡片和浮层的背景层次，以及文字、边框、强调色和状态色的实际搭配。 |
| 布局与密度 | 按参考表达导航位置与宽度、内容区比例、分栏、留白、控件尺寸及列表密度；不要求实现拖拽、缩放等复杂布局功能。 |
| 组件细节 | 使用指定组件与变体，呈现圆角、边框、阴影、图标及适用的悬停、焦点、选中、禁用等外观，放在真实页面位置而非只作独立陈列。 |
| 状态与动效 | 以样例或简单开关呈现需要的加载、空数据、错误、成功等状态；采用的动效能触发和重看，体现出现方式、节奏、时长与缓动，不只写效果名称。 |
| 切换与浮层 | 点击导航能进入对应页面或子页，标签、分页、弹窗和抽屉能轻量切换与关闭，体现父子层级、返回路径及底层页面关系，不扩展成完整业务流程。 |

交互只服务于看效果。弹窗和菜单可关闭，保留合理焦点反馈；动效支持减少动态效果。不要求登录鉴权、保存恢复、完整业务状态机或后端；已确认规则与真实接口状态不应被样例歪曲，模拟内容不能冒充真实业务结果。

字体使用实际资源而非仅声明名称；可在 HTML 说明区显示字体的加载或回退状态，方便用户直接看到实际情况，不为此启动测试流程。暂用替代字体或缺少字重时如实标明，不悄悄改变指定方案。

## 组件与开源库说明放在 HTML 里

优先实际使用用户指定的组件、主题与定制，能复用的项目样式继续复用。需要运行库才能展示时只引入必要资源；确需使用 shadcn 等组件 Skill 时按其方法处理，不为预览初始化完整应用或安装无关依赖。

原生组件或指定库确实不能直接用于该 HTML 时，说明限制和视觉模拟的差异；不能用相似手写控件替代后仍声称使用了原组件。不因预览载体而改变最终产品的技术选型。

在 HTML 的折叠“组件与来源”区域写清实际使用的组件、所属开源库、用途、已知版本或变体、来源链接和必要定制；图标、动效库与字体来源也按实际使用说明。区分直接使用与视觉模拟，不把候选库列作已使用；没有外部库就如实写明。

参考来源、模拟数据、静态部分与资源限制也可简述在同一区域，不另出来源文档，不让说明遮住产品界面，不编造版本、授权信息或已接通能力。

## 再从采用的设计提取 Token

HTML 制作后直接输出 `docs/design/design-token.md`，记录本版采用的设计规则，作为可继续修改的开发参考；不等待用户批准，不以验收、测试或业务实现完成为前提。已有对应文件则原位更新。

从本版 CSS、主题变量和实际组件配置提取名称、值、用途与对应位置，不从截图猜值，也不把候选方案当成已采用。已有变量名和设计规范优先复用，不能另写一套与预览不符的值。

- **颜色：** 页面及各区域背景、文字、边框、强调色、状态色与焦点色。
- **文字：** 字体与回退方案、字号、字重、行高、字间距及标题、正文、辅助文字用途。
- **布局与组件：** 导航宽度、内容区约束、分栏比例、间距、控件尺寸、列表行高、表格列宽、圆角、边框、阴影和浮层层级等本版实际采用的值。
- **动效：** 使用位置、触发方式、时长、延迟、缓动和减少动态效果的处理。

后续按用户反馈调整 HTML，并同步变化的 Token；无需为迭代额外生成评审或差异报告。组件和开源库来源仍以 HTML 内说明为准。

## 做好就交付

最终只交付一个 HTML 预览文件和一份设计 Token，并简短说明打开方式。默认不进行质量检测、截图审查、浏览器自动化测试、评分、验收或多轮自评，不输出检查清单、测试报告或额外设计文档，也不为补齐这些流程延迟展示。

这里的好坏设计原则用于制作，不用于追加质量关卡。用户看效果后直接提出修改即可；如用户另行明确要求评审或实际功能开发，再按该次授权处理，不把生产实现的测试要求套到本次设计预览上。
