# 生成设计版与设计 Token

只在用户主动调用后执行；后续答疑、修改、确认和 Token 提取属于同一次设计任务，无需重复调用。仅要求讨论或草图时按该范围交付，确认草图也不追加 Token；Token 阶段只对应已要求制作并确认的设计版。

## 先弄清必要信息

读取需求、目标设备与窗口、指定参考、已有主题和组件。需求不清时，一次问通常 3–5 个关键问题，只覆盖尚未明确的页面范围、主要操作、视觉参考、尺寸或组件约束；缺口更少就少问，不为凑数重复提问。每题给两个或更多中性选项，不附建议或解释。需求已经清楚，直接开始。

## 制作并交付设计版

1. 使用 [常见 AI slop](../design-quality/SKILL.md) 指导，优先复用指定参考、字体、组件和实际样式变量。指导缺失时沿用已有设计依据，不阻塞明确任务；不在本技能重复铺设计规则。
2. 用一个 HTML 展示约定范围内全部页面与子页的组织、导航、布局和可信的一屏密度，同模板页面可共用代表样例；体现指定组件样式、必要状态与可重看的动效。分页和轻量交互按需求呈现，足以判断设计即可，不初始化正式工程、安装应用开发依赖或构建应用，不实现正式业务、鉴权、持久化或后端；样例、视觉模拟和资源限制如实说明。
3. 需要比较结构时先做一次性草图，再完善同一份 HTML。已有或用户指定的产物路径优先；否则相对于项目根目录（无项目时为当前工作目录）保存到 `docs/design/design-board.html`。打开先看到产品界面，必要组件说明、来源、联网依赖和模拟限制放在同一 HTML 的折叠区。正式开发参考其布局与交互，不要求共用原型源码，也不把原型完成算作正式前端完成。
4. 轻量查看实际显示与必要操作，无法查看时如实说明；交付设计版和简短打开方式，等待用户确认当前版本。确认前只修改设计版，不生成或更新 Token 文档；不追加设计规范、组件清单、自评分、质量报告或自动测试流程。

## 确认后输出一份 Token

用户确认当前设计版后，从该版实际 CSS、主题变量和组件配置提取共用 Token；已有确认和样式依据足够时直接提取，不重问设计问题。沿用已有或用户指定的 Token 位置，否则在设计版同目录输出 `design-token.md`，默认即 `docs/design/design-token.md`。

用一张简短的“名称／实际值或引用／用途”表记录实际使用的共用 CSS 变量或主题 Token。没有变量化的共用样式只引用源码位置，必要差异简述即可；不展开逐组件尺寸、状态清单、响应式细节或完整设计规范，不为凑类别新增变量，也不从截图猜值。

Token 文档开头注明对应的已确认设计版位置与版本标识。之后修改设计时，先更新设计版；旧 Token 仍对应旧版，不冒称已经同步。用户确认修改后的版本，再原位更新同一份 Token。只交付这份 Token 及设计版位置，供 Spec、Issue 和实施引用；不自动进入规格、拆任务或开发。
