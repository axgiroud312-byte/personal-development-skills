# 设计界面与交互

用通俗中文说明，先明确设计，再做出规则与效果。方法随项目调整，已有设计、技术栈、组件与定制优先沿用。

## 设计哲学

以代码实际为主：核实现状时以代码和实际行为为准，文档不一致就沿用现有实现的惯例，完成后列出差异与处理。本次目标仍以用户已确认的需求和规格为准，未实现的新要求不能当作过时文档；从零项目依据目标、约束与必要验证设计。

## 明确当前范围

了解产品解决什么问题、谁在用、主要操作、真实内容、设备与使用方式。业务含义不清时按需衔接 `domain-modeling`，只追问无法查清又影响设计的关键选择。

分阶段开发先做好当前交付需要的页面与交互，后续逐步扩展，远期页面不阻塞当前开发。只要求讨论、评审或局部修改时完成该范围；明确要求完整设计时连续完成，不逐阶段增加确认。

## 看参考，形成方向

先打开用户提供的原图、页面或文件，理解主次、布局、内容与操作；参考打不开时如实说明。借鉴点要具体到比例、对齐、间距、字重、颜色用途与图片处理，有尺寸要求时按要求制作。

结合项目特点与真实内容形成方向，避免只换配色、字体和装饰来套模板，也不照搬参考中难读、难找或妨碍操作的部分。方向不清时可用相同内容做少量差异明显的小样，区分候选与已采用方案。

## 怎样判断设计好不好

- **符合项目特点：** 从功能、内容、品牌或使用方式找到依据；布局表现内容的主次、因果与顺序。工具界面用真实任务体现特点，不强加艺术表达。
- **重点清楚：** 用大小、位置、疏密和明暗引导阅读，辅助信息仍清晰。留白用于分组、突出或调整节奏；无作用的空洞应收紧或补足内容，紧凑与宽松都要完整。
- **整套一致：** 字体、色彩、间距、图片和组件相互配合，特点延续到业务区域和结尾；保留表格、列表等有助比较与学习的重复。
- **内容真实：** 用具体产品、任务、图片与数据支撑页面；不用灰条假界面、无关图库或泛泛图标代替主体。样例与模拟状态明确标注，不冒充客户或真实结果。
- **方便操作：** 视觉与动效帮助理解、定位和反馈；窄屏重新安排内容、裁切与操作空间，避免只缩小桌面布局。

颜色、字体、渐变、阴影、圆角等按内容和用途判断，不规定统一风格。简洁要有内容与细节，复杂要有秩序。

## 哪些是不好的设计

避免无目的地堆渐变、发光、英文小标题、胶囊标签、圆点、星形、角标或装饰性数字；不靠缩小字号、变灰、拉大间距掩盖多余说明，不用“高级感”“科技感”代替理由。

不编造人数、销量、评分，也不添加无真实来源的“系统正常”“实时同步”“AI 在线”等状态。文字服务于识别、操作与理解，删掉不影响使用的默认删去。

保留清楚可读的字段标签、输入要求、真实分类与步骤、金额与进度、重要状态、错误原因、恢复方法及操作后果。设计理由和开发说明放在设计文档或设计板说明区，不混进产品页面。

## 交付规则与效果

主要成果放在项目的 `docs/design/`，沿用已有合适位置，不为目录完整额外建文件：

- `design-token.md`：记录本次采用的颜色、字体、尺寸与必要效果的名称、具体值和用途，引用现有主题变量与源码位置，简述相关理由与待定项。
- `design-board.html`：展示实际配色、排版、组件状态、完整页面与必要交互；分区和顺序按内容决定，不单独规定原型文件。

先整理 Token，再制作设计板；优先打磨能代表主任务的一屏，按本次范围补齐页面与状态。用中文、英文、数字和长短内容看效果，确认字体与字重实际加载，库名清单或截图不能代替页面。

设计板中的菜单、弹窗、切换、筛选等按需可操作，反馈及时，支持必要键盘操作、关闭与焦点返回；动效尊重“减少动态效果”。不要求穷尽全部状态，模拟数据与保存结果必须说清。

已有样式与文档不一致时，以实际源码对齐说明和设计板；本次明确要求的新设计，再同步相关说明、页面和实际样式。多份 Spec 共用设计规则，避免各自维护一套 Token。

## 复用组件，方便继续开发

先用项目已有组件，再按约定来源补缺口，保留定制并区分已使用与候选。设计板与产品尽量共用实际样式和源码，不从截图重新猜数值。

使用 shadcn 时读取其 Skill，按它完成必要的初始化、搜索、来源配置与安装更新；不可用时查[官方文档](https://ui.shadcn.com/docs)，只处理本次需要的组件。

沿用项目已有服务和预览方式，核对设计板能实际打开、主要页面与交互可查看。交付文件位置、准确查看方法、采用的组件和定制，以及模拟、未验证或待定内容；素材与少量源码按实际需要添加。

设计变化同步 Token 说明、设计板、实际源码与受影响规格或任务。理念参考 [Taste Skill 设计方向](https://github.com/Leonxlnx/taste-skill/blob/6010f91a9935f1c167dfc500fb1a475681892e6b/skills/taste-skill/library/directions.json)与[设计分析](https://github.com/Leonxlnx/taste-skill/blob/6010f91a9935f1c167dfc500fb1a475681892e6b/skills/taste-skill/references/research.md)。
