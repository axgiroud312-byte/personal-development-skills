# 制作完整前端原型

让用户在正式开发前看清整套产品如何组织、怎样操作、最终长什么样。按“页面与信息架构 → 视觉与交互 → HTML → Token”推进；以完整页面呈现，适用于网页、Web 应用、后台、桌面 GUI 和移动端。HTML 是预览载体，不改变正式产品的技术选型。

以代码和实际行为判断现状，以用户已确认需求确定目标；文档不一致时沿用现有实现惯例，交付时说明差异与处理。

## 1. 读取设计依据

读取需求、指定参考原图或页面、组件及已有样式，确认本次范围和目标尺寸。用户指定的组件、变体、主题、字体、字重、背景、配色与动效优先；按要求借鉴参考的布局、比例、排版等具体部分，缺失细节自行补齐。资源不可访问或有冲突时说明，只询问真正阻止呈现的选择。

制作时读 [好设计与坏设计](references/design-quality.md)。它辅助设计取舍，不是额外验收流程；只要求讨论或局部修改时完成该范围。

## 2. 组织整套页面

覆盖本次范围内全部页面、子页面和内容归属，明确父子层级、全局导航、页内标签、进入与返回路径；Spec 或任务拆分不直接等于页面划分。同模板的不同记录可用代表性样例，不能用首页或一级页代替整套产品。

按参考和内容关系安排顶部、侧栏、分栏、工具区与滚动区域，选择独立页、页内标签、弹窗、抽屉或内联展开，不套固定布局。以轻量点击演示真实去向，避免所有按钮都弹通用提示。

在目标窗口呈现可信的一屏信息量：导航宽度、内容比例、列表行数和行高、表格列宽、文字长度与换行、卡片数量、留白和滚动。简化功能时保留影响观感的密度和层级。

## 3. 在一个 HTML 中呈现

沿用已有位置，否则写入 `docs/design/design-board.html`。页面、CSS、演示脚本和来源说明放在同一文件；打开先看到接近成品的产品界面。必要外部库、字体与素材可用明确链接引用，并注明联网依赖，不为原型初始化完整应用。

| 内容 | 呈现要求 |
| --- | --- |
| 字体与字重 | 使用真实字体资源和可用字重，展示中文、英文、数字的字号、行高、字距与用途；缺失或回退如实注明。 |
| 背景与配色 | 表达页面、导航、内容、卡片与浮层的层次，落实文字、边框、强调色与状态色。 |
| 组件 | 在页面中使用指定组件、变体与定制，表达图标、尺寸、圆角、边框、阴影及适用的悬停、焦点、选中、禁用状态。 |
| 交互 | 以本地样例串联切页、返回、标签、适用的分页和浮层开关；菜单可关闭，焦点有反馈。 |
| 状态与动效 | 展示需要的加载、空数据、错误、成功状态；动效可触发和重看，体现时长、节奏与缓动，并支持减少动态效果。 |

交互服务于设计预览，不要求真实查询、登录鉴权、持久化或后端；已确认规则与真实接口状态不能被样例歪曲。只在需求包含时安排窄屏适配，不为完整性添加无关功能。

指定组件优先实际使用，操作按相应 Skill 处理；若无法直接用于 HTML，在折叠“组件与来源”区说明视觉模拟与实际组件的差异。该区同时记录组件、图标、动效库和字体的用途、已知版本或变体、来源链接、定制、参考及资源限制；区分已使用与候选、真实与模拟，不编造版本或能力，不让说明遮住产品界面。

## 4. 提取本版 Token 并交付

HTML 完成后直接写入 `docs/design/design-token.md`，已有位置则原位更新。从实际 CSS、主题变量与组件配置提取“名称、值、用途、对应位置”，沿用已有命名，不从截图猜值或另造一套规则。覆盖本版使用的颜色、字体与回退、字号字重行高字距、布局约束和分栏比例、间距、组件尺寸、列表行高和表格列宽、圆角边框阴影、浮层层级，以及动效位置、触发、时长、延迟、缓动和减少动态效果处理。

最终只交付一个 HTML 和一份 Token，简述打开方式；不用等待批准，不默认追加质量检测、截图审查、自动化测试、评分、自评循环或验收报告。按反馈修改 HTML 时同步 Token，用户另有评审或实际开发要求时再按该范围处理。
