# 设计界面与交互

将需求转成本地可查看、可修改、可继续开发的设计项目。完整设计默认在实际项目内建立 `Designer/`，按 **Design Tokens（设计变量）→ 可视化设计板 → 可操作原型** 推进，用中文说明结果。所有工作规则集中在本文件，不另拆参考文档。

已有设计目录、技术栈、组件和规范优先复用，只补当前变化。只要求讨论、评审、文稿或局部修补时遵守该范围；已有完整设计或开发授权时连续推进，不新增阶段批准。

## 技术栈与组件

默认使用 **React + Tailwind CSS v4**，组件主要使用 [shadcn/ui](https://ui.shadcn.com/)，图标默认使用 [Lucide](https://lucide.dev/)。可使用 [Animate UI](https://animate-ui.com/) 制作图标、组件或动画，也可参考 [Aceternity UI](https://ui.aceternity.com/)。具体依赖按项目需要选择，共用项目 Token，保留已有定制。

前端实施前（包括设计板与原型），在实际前端目录完成以下准备；仅讨论或写文档时不执行初始化：

1. 按项目包管理器使用 shadcn CLI，以下以 `npx` 举例。运行 `npx shadcn@latest info --json` 核对配置、主题、别名、底层组件体系和已有组件；命令不可用时读取 `components.json`、包文件与源码，说明缺项。未初始化时执行 `npx shadcn@latest init`，适配 React、Tailwind CSS v4 和 Token 入口；已有配置核对复用。
2. 官方源 `@shadcn` 由 CLI 内置。在 `components.json` 的 `registries` 中合并补齐以下来源，保留其他字段；执行时对照官方文档或 [registry 目录](https://ui.shadcn.com/r/registries.json)确认地址，其他来源按需添加。

```json
{
  "registries": {
    "@animate-ui": "https://animate-ui.com/r/{name}.json",
    "@aceternity": "https://ui.aceternity.com/registry/{name}.json"
  }
}
```

3. 通过 `search` 或 `view` 检查所需来源和组件，再按明确 namespace/组件名执行 `add`。只添加本次采用的组件；来源不可用时如实记录，只影响相关部分。注册来源不代表组件或运行依赖已安装，Animate UI 的包与 CLI 接入按其[安装文档](https://animate-ui.com/docs/installation)处理。

使用 shadcn 工程能力时读取可用的 `shadcn` Skill，不可用时按[官方文档](https://ui.shadcn.com/docs)操作。添加组件后检查实际源码、依赖、图标和导入别名；更新已有组件先看差异，保留项目定制。

## 理解场景与保持文案克制

核对实际目录、需求、业务定义与已有设计，明确主任务、真实内容、目标设备和输入方式。业务含义有缺口时按需衔接 `domain-modeling` 或等价梳理，只追问无法调查解决且影响设计的关键选择，不自行改写业务规则。

有参考时先查看原图、页面或文件，提取布局比例、尺寸、对齐、间距、字体字重、密度、颜色职责和表面层级；明确几何作为验收依据。无法读取时说明缺项。无参考时推荐一个方向；方向不明确或用户对效果不满意时，可用相同内容做两个差异清楚的轻量小样，说明推荐，不把推荐当成用户已选择。

界面文字只服务识别内容、完成操作和理解状态。删除后不影响这些目的的文字，默认删去；不为每个页面、卡片或控件附加介绍、重复副标题、标语和说明性小字。例如标题已有“项目”，通常不再补“在这里查看和管理你的所有项目”。字段标签、输入约束、关键状态、错误与恢复提示、影响决定的操作后果按需保留且保持可读，不用缩小字号或降低对比度隐藏冗余文字。

设计理念、布局理由和实现解释写入设计说明，不放进产品界面。设计板中必要的 Token 名称、数值和组件来源标注保留，展示性注释不照搬到产品页面。

## 本地设计目录

新项目默认组织如下；已有明确位置直接沿用，再次执行更新同一个设计项目。各目录放实际成果，不建立空占位：

```text
Designer/
├── index.html       总览：Tokens、设计板、原型与复用入口
├── tokens/          唯一 Token 源，或对既有主题的导入与适配
├── boards/          四块可视化设计板
├── components/      共用组件，或对已有组件的导入与重导出
├── prototype/       页面、交互与代表性数据
└── DESIGN.md        设计依据、预览方式与开发交接说明
```

图片、图标和字体按需放入 `assets/` 或复用项目资源。预览优先沿用已有服务、路由和工具链；独立设计项目才补必要脚本与依赖。总览能实际访问各项成果；支持直接打开或给出已核实的启动命令和本地地址，不能把 TSX 源文件或截图目录当成可操作入口。

## 先定义 Design Tokens

根据产品用途、内容和参考建立 Token 初版，覆盖本次需要的语义颜色、字体、字号、字重、行高、字间距、间距、控件高度、圆角、边框、表面、阴影与动效。区分品牌、操作、状态、焦点和装饰用色，只处理需要的主题模式；后续视觉打磨持续校准同一份源。

实际值只维护一份。新项目默认使用 `Designer/tokens/tokens.css` 或技术栈适用的原生主题源；已有项目导入既有 Token，不复制另一套数值。沿用 shadcn 的语义变量与实际主题入口，局部变体限定适用范围。设计板、原型和后续产品共同消费这份源，展示值从源读取或生成；额外 JSON 等导出按需生成并标明派生关系。

设计说明解释职责与用法，不另抄数值表。外部设计工具有另一套变量时说明真实同步方法和范围。若提供调色、字号或密度控制，只在浏览器生效的调整标明临时，实际保存或导出后才能声称已更新项目 Token。

## 再制作可视化设计板

在总览中实际呈现以下四块板，可以是同页分区或路由；使用真实或明确标注的代表性内容，形成适合产品的一两个视觉特征。文字规范、库名清单或截图不能代替相应的可视化样例。

| 板块 | 要展示的内容 |
| --- | --- |
| 视觉方向板 | 可访问的参考图或页面片段、借鉴点、当前方向与内容小样，体现构图、留白、密度和视觉特征；区分采用与待定方向 |
| 配色板 | 真实色块、名称、数值、角色与使用位置，展示文字和背景搭配，以及按钮、面板、状态提示的应用 |
| 字体与布局排版板 | 中文、英文、数字和长短文本；标题、正文、说明、标签与数据的字体及回退、字号、字重、行高、字间距；实际分栏、留白、间距、控件高度与滚动关系 |
| 组件板 | 本次采用的图元、图标、控件和必要业务组合，实际展示尺寸、变体与适用状态，标明库或 registry、版本依据、源码、用途与调整 |

检查字体实际加载与字重是否可用，用真实字形比较本次采用的字重，不能只看英文短标题。候选方向、字体和配色不混用到当前方案。

组件先复用已有合适实现，再从约定来源中选择组合，确有缺口时补充或自研并说明原因。组件板、原型与产品共用同一份实现；标清“实际采用并渲染”和“候选、未安装”，不虚构来源、安装状态或兼容性。

## 最后制作原型并检查

先打磨能代表主任务的一屏，再扩展到本次需要的页面与状态。主要控件能操作，成功、失败与恢复路径按本次范围可体验；允许明确标注的模拟数据与响应，不能把模拟保存当成真实后端或持久化验收。

按需要区分两层状态：控件的默认、悬停、按下、焦点、禁用、选中、处理中与校验错误；页面的加载、正常内容、首次空数据、搜索无结果、权限不足、部分失败和保存结果。说明触发条件、呈现、下一步和恢复方式，不要求每个控件具备全部状态。

保存及时反馈，失败保留输入并可重试；弹窗、菜单处理关闭、键盘与回焦；返回遵循草稿和位置保留规则；删除按业务后果提供确认或恢复；筛选有明确生效方式、条件与重置入口。动效用于反馈、空间关系与状态变化，日常操作迅速，支持减少动态效果设置。

在真实浏览器或目标桌面窗口查看设计板与原型，操作关键流程，核对视觉方向、中文字体、主次层级、密度、对齐、留白、长文本、滚动关系与相关窄屏行为。有固定参考几何时测量关键尺寸和间距，报告差异；“太挤”“字太轻”等反馈转成具体调整与前后对照，必要时通过一次 Token 调整确认板块与原型共同变化。

按改动范围依据 [WCAG](https://www.w3.org/TR/WCAG22/) 核对文字对比度、可点击区域、窄屏重排、键盘操作、可见焦点与状态提示，按适用条款判断，不把局部检查称为完整合规认证。

有性能要求时按本次约定另行核对，区分实验室诊断与真实使用数据；未测量的效果不写成已验证。

修复实际观察到的问题，按风险完成必要检查后交付；无新变化或失败就不重复扩大测试，不为查看设计生成生产构建或安装包。记录实际查看、实际操作、模拟和未验证范围；截图辅助视觉核对，构建或脚本通过不等于用户满意与验收。

## 保存依据并衔接开发

以 `Designer/DESIGN.md` 保存当前范围、参考与方向、Token 和组件的权威源、板块与原型入口、交互约定、预览命令、模拟边界、实际检查结果及影响继续工作的待定项。已有设计规范时更新原文，目录入口引用它，保持每项决定只有一份有效正文。

后续开发先读取设计目录、Token 与设计板，复用组件源码和原型行为；直接导入共用资源或明确适配，确需迁移时同步所有引用与板块，不能从截图另猜数值或复制出脱节的组件。设计变化更新对应源、设计板、原型和受影响的 Spec、Issue 与项目索引。

与 Spec 往返调整，交接设计要求、实际成果入口与未完成项。仅写文档或拆任务时不自动制作整套原型，可将设计列为前置任务；已有完整设计或开发授权时连续推进。最终交付准确目录、可查看入口、预览方法、复用位置与真实验证范围，区分设计交付、业务实现和用户验收。
