# 逐步做出可交互的 HTML 原型

用户主动调用后，读取需求、目标设备、页面范围、指定参考和已有设计；已有原型从当前进度继续。

## 先看应用结构

先在一个可交互的 HTML 中做出应用外壳、导航、主要布局和信息层级。页面与子页面先用简洁内容呈现，让用户能点击入口、切换页面，判断层级和前后关系。

先展示这一版供用户反馈，再在同一文件中逐步完善。已有明确结论直接沿用。

## 按反馈逐步完善

根据反馈补充页面内容、关键操作流程和必要状态。使用接近真实长度的内容，让用户看清信息主次和操作前后的变化；重要选择说明效果与代价，常规细节自行补齐。

沿用已有位置，默认使用 `docs/design/design-board.html`。用 HTML、CSS 和必要脚本演示设计，按需参考 [AI slop 清单](../design-quality/SKILL.md)。组件、来源、联网依赖和模拟范围放在同一 HTML 的折叠说明区，打开文件先看到产品界面。

每次交付前轻量查看实际显示与必要操作，在聊天中提供打开方式、已展示和待完善的部分。

用户说停时立即结束设计，保留当前可打开的 HTML 和进度；后续继续时从这里接着做。

## 满意后提取 Token

用户确认本次范围内的完整原型满意后，从实际样式提取一份 Token 文档，默认使用 `docs/design/design-token.md`。用“名称／实际值或引用／用途”短表记录，注明对应原型版本。

后续修改继续更新同一原型，新版获确认后同步 Token。正式开发参考原型与 Token 完成真实业务。
