# 制作完整前端原型

让用户在正式开发前看懂整套产品怎么组织、如何操作和最终观感。先组织信息架构，再落地视觉、组件、状态与动效，集中呈现在完整页面中。原型简化业务实现，保留影响设计判断的细节；HTML 是预览载体，不改变最终技术栈。

以代码和实际行为核实现状，已确认的新需求决定本次目标；文档冲突时沿用现有惯例并说明差异。只要求讨论或局部修改时完成该范围。

## 读取设计依据

读取需求、目标设备与尺寸、指定参考、组件和项目已有样式。打开原图、页面或文件，按用户意图借鉴布局、比例、排版、配色或动效；不能只抄背景色或混搭无关参考。

用户指定的组件变体、主题、字体、字重、配色、背景与动效优先。未指定细节合理补齐；资源不可访问、缺失或冲突时如实说明，只澄清真正阻止制作的选择。

制作时读取 [好坏设计参考](references/design-quality.md)，用于帮助设计，不作为验收清单。

## 组织全部页面与交互

汇总本次范围内全部页面、二三级子页、内容归属及父子关系；同模板记录可共用样例。按用户任务组织页面，Spec/Issue 的拆分不直接等于页面划分，完整产品原型不能只做首页。

落实全局与局部布局：导航位置、各级菜单、页内标签、分栏和滚动区，显示当前位置；不固定套用左侧栏。为每个入口选择独立页、页内切换、弹窗、抽屉或内联展开，并演示进入、返回与关闭，不能用通用提示代替目标画面。

在目标窗口呈现可信的一屏信息量：导航宽度、内容比例、列表行数和行高、表格列宽、卡片数量、真实长度文字与换行。样例足以表现密度即可，按需求安排分页和设备适配，不扩大范围。

## 制作 HTML 原型

沿用已有位置；默认交付 `docs/design/design-board.html`。页面、CSS、轻量脚本与说明放在这一个 HTML 中，首次打开先看到产品界面。必要外部库、字体与素材明确引用并说明联网依赖，无需初始化完整应用工程。

| 要素 | 应呈现的内容 |
| --- | --- |
| 字体与字重 | 实际加载指定资源，呈现中文、英文、数字及标题/正文/辅助文字的字号、字重、行高和字间距；缺少字体或字重时说明回退，不能只声明名称就声称已加载。 |
| 背景与配色 | 页面、导航、内容区、卡片和浮层的背景层次，以及文字、边框、强调色、状态色与焦点色。 |
| 组件与布局 | 指定组件和变体在真实页面中的尺寸、圆角、边框、阴影、图标及悬停、焦点、选中、禁用外观；保留参考中的布局比例和信息密度。 |
| 状态与动效 | 按需要用样例展示加载、空数据、错误和成功；动效可触发、可重看，体现触发方式、时长、延迟和缓动，并支持减少动态效果。 |
| 交互 | 用本地样例演示切页、标签、分页与浮层开合，弹窗和菜单可关闭且有合理焦点反馈，能看懂页面层级和底层关系。 |

不需要正式路由、登录鉴权、持久化或后端；模拟行为与真实接口状态分清，不歪曲已确认业务规则。组件无法直接用于 HTML 时可做视觉模拟，但必须标明差异，不冒称原库组件。

在 HTML 折叠的“组件与来源”区列实际使用的组件/库、用途、已知版本或变体、链接及必要定制；图标、字体、动效、参考、模拟数据与资源限制同处说明。区分直接使用、视觉模拟与候选资源，不编造版本或授权，不让说明挤占产品界面。指定组件的操作按相应 Skill，复用现有配置。

## 从实际样式提取 Token

HTML 完成后直接整理 `docs/design/design-token.md`，记录名称、实际值、用途和对应位置：颜色；字体与回退、字号、字重、行高、字间距；导航/内容尺寸、分栏、间距、控件、列表、表格、圆角、边框、阴影、浮层层级；动效触发、时长、延迟、缓动与减少动态效果处理。

从本版 CSS、主题变量和组件配置提取，复用现有命名，不从截图猜值或另造一套规范。根据反馈改原型时同步 Token。

## 直接交付

最终只交付一个 HTML 原型和一份 Token，简述打开方式。做好即交付，不等用户批准，不默认追加质量检测、截图审查、自动化测试、评分、自评循环或报告。另行要求评审或正式开发时，再按该任务处理。
