# 先看原型，再提取 Token

用户调用后开始设计，后续反馈、修改和确认在同一次任务中连续处理。

## 弄清设计依据

读取本次需求、目标设备与尺寸、指定参考、已有主题和组件。需要用户决定的关键问题集中提出，每题配两个或更多中性选项；已有答案直接复用。

常规设计细节自行补齐，重要假设简短说明。参考与当前要求冲突时先查证，用户反馈后据此调整设计。

## 做出可查看的原型

按需参考 [AI slop 清单](../design-quality/SKILL.md)，将用户指定的布局、字体、组件和视觉要求落实到页面中。

用一个 HTML 展示本次范围内的页面、子页、导航、布局和一屏信息量。同类页面可以使用代表样例，轻量交互表达切页、弹层、必要状态与动效。

直接使用 HTML、CSS 和必要脚本，以样例数据演示设计。组件、来源、联网依赖和模拟限制放在同一 HTML 的折叠说明区；正式业务在实施阶段接入。

需要先看结构时，先做草图，再在同一文件完善。草图请求交付草图，完整设计请求继续完成原型。

沿用已有或用户指定的位置，默认 `docs/design/design-board.html`。打开文件先看到产品界面，轻量查看实际显示与必要操作后，交付文件和打开方式，供用户反馈。

## 满意后提取 Token

用户确认当前完整原型满意后，从实际 CSS、主题变量或组件配置提取共用样式。用“名称／实际值或引用／用途”短表记录，保留对应原型位置与版本。

沿用已有 Token 位置，默认 `docs/design/design-token.md`。共用样式尚未变量化时引用实际源码位置，必要差异简短说明。

原型修改后，旧 Token 继续对应旧版；新版获确认后原位更新 Token。正式开发参考布局、交互和这些实际数值，在正式项目中组织代码。
