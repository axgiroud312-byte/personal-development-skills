# 设计界面与交互

统一负责各类前端的设计方向、视觉与交互效果和 Token 整理。交付 HTML 设计展示板，不是完整应用或全功能原型：整体看结构，局部看细节。沿用项目已有设计、技术栈、组件和定制，不因展示方式改变最终产品的技术选型。

**以代码实际为主。** 核实现状时以代码和实际行为为依据；文档不一致就沿用现有实现的惯例，完成后列出发现的差异与处理。用户明确提出或已确认的新需求决定本次目标，不能因为尚未实现而忽略。

## 先确认这次要做什么

先看实际项目、需求、已有界面和业务说明。明确产品解决什么问题、谁在用、主要操作、真实内容、设备和使用方式。

按需求梳理要展示的布局、页面与导航、列表分页，以及采用的组件、状态和动效；不适用的内容不添加，不为桌面专用项目额外制作手机端。

功能或数据含义不清时，按需使用 `domain-modeling` 或做同等梳理。只追问无法查清又影响设计的关键选择，不自行更改业务规则。

只要求讨论、评审、写说明或局部修改时完成该范围。整套设计可以分批展示，但不能只交一个首页而遗漏需求中的其他页面概貌；结构覆盖不等于功能实现，不逐阶段增加确认。

## 看参考，确定设计方向

有参考时先打开原图、页面或文件，理解它要表达什么、哪里吸引人、内容与操作如何安排，需要什么素材才能成立。选择适合当前任务与内容的参考；打不开时如实说明。

把借鉴点说具体：比例、对齐、间距、字号与字重、颜色用途、背景和边框分区、图片裁切。有明确尺寸要求时按要求制作。

避免只换成相同的配色、字体和装饰来套模板。参考中的小字、难找的导航或妨碍操作的效果，也不能一起照搬。

没有参考时，结合任务和已确认偏好形成方向。方向不清或用户不满意时，可用相同内容做少量差异明显的小样，区分候选与当前采用方案，不把推荐当成用户已选择。

## 设计判断

开始设计或评审时读取 [设计质量参考](references/design-quality.md)，交付前据此复核。关注结构是否看得懂、视觉是否符合产品、组件与状态是否清楚、动效能否看到，而非完整业务是否跑通。

展示涉及已确认业务规则或真实接口状态时，表达不能与之矛盾；可以直接展示错误、成功等样例，不要求真的调用接口或实现权限系统。未决定的政策保留待定，模拟效果不能冒充真实结果。

## 先做 design-board.html

在 `docs/design/design-board.html` 制作 HTML 设计展示板，已有合适位置则沿用。使用 CSS 和少量 JavaScript 演示效果，不为展示板新建完整应用、正式路由、桌面壳或后端。已有主题变量与可用资源可直接复用，不要求先写 Token 文档。

用有代表性的内容展示整体样子，再突出组件细节。页面概貌可分区排列或简单切换；说明和演示控制放在附属区域，不与产品页面混在一起。

| 内容 | 展示深度 |
| --- | --- |
| 整体布局 | 概略展示需求中的区域位置、比例和分区，能看懂整体结构即可；无需实现拖拽、缩放等复杂布局行为。 |
| 页面与导航 | 展示需求内各页的大致结构、入口与关系，可静态排列或简单切换；无需正式路由或完整跨页业务流程。 |
| 列表与分页 | 用少量样例展示列表、表格、筛选及分页控件的样式；不要求真正实现搜索、排序、筛选和翻页逻辑。 |
| 组件样式 | 重点呈现实际采用的按钮、输入框、卡片、菜单、弹窗等的外观、尺寸、间距和搭配，并放回页面场景看效果。 |
| 状态与反馈 | 具体展示适用的悬停、焦点、选中、禁用、加载、空数据、错误和成功等效果；可并列示例或用开关切换，不必由完整业务触发。 |
| 动效与过渡 | 用少量 CSS／JavaScript 实际播放采用的过渡、展开收起、弹窗进出或反馈，便于触发与重看；不只写动效名称，也不强加无用动效。 |

配色、排版、中文、英文、数字与长短内容使用真实效果，确认字体和字重实际加载。布局概略不等于灰条空架子；用清楚的标签与代表性内容表达页面，不用组件清单代替设计。

只实现观看设计所需的交互。例如菜单、弹窗演示应能关闭并有合理焦点反馈；动效支持“减少动态效果”。静态导航或分页样例不必全部可用，在展示说明中区分静态样例、演示交互与未完成内容。

不要求真实数据处理、登录鉴权、保存恢复、完整业务状态机或后端连接，不另做一套重复原型。明确区分样例状态与实际功能；完整应用开发属于另行授权的实施任务。

## 再从采用的设计提取 Token

设计板已能展示本次范围的结构、组件、状态和动效，并完成相应检查后，再输出 `docs/design/design-token.md`，不以业务功能完成为前提。直接读取采用的 CSS、样式与组件源码，不从截图猜值；已有合适文档原位更新。

- **颜色：** 背景、文字、操作、状态与焦点等的名称、实际值和用途。
- **文字：** 字体与备用字体、字号、字重、行高和字间距。
- **尺寸与效果：** 间距、控件高度、圆角、边框、阴影，以及已采用动效的触发、时长和缓动。

沿用已有变量名称和唯一源码，标明源码位置；保留必要设计理由、组件来源与待定项，不把候选写成已采用，也不建立第二套值。提取或统一 Token 改变效果时回到设计板核对，两份成果与实际样式保持一致。

## 组件复用、查看与交接

先参考和复用项目已有样式与组件，再从约定来源补缺口；保留定制，区分实际复用、HTML 视觉演示与候选。能直接共用的源码继续共用，不为让展示板等同生产界面而强制搭建应用。

确需使用 shadcn 时读取其 Skill，按它完成本次必要的搜索、配置或安装；不可用时查[官方文档](https://ui.shadcn.com/docs)。简单 HTML 示例够用时不为展示板额外初始化框架或安装无关依赖。

实际打开 HTML，检查要求的页面概貌、目标尺寸、组件视觉、适用状态和演示动效；只检查承诺的演示交互，不以端到端业务跑通作为设计验收门槛。已有预览服务可沿用，没有则提供直接打开文件或所需的准确查看方式。

交付 HTML 与 Token 位置、查看方法、覆盖范围及状态和动效的演示方式，注明静态、模拟、未验证与待定部分。设计变化同步两份成果、相关样式及受影响的 Spec 和任务，不另加阶段批准。
