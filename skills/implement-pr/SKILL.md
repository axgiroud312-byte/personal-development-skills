# 在当前项目目录交付一个 PR

主 Agent 负责交付。所有参与者使用用户当前的项目目录；整个 PR 使用一条交付分支。明确的小改可以由主 Agent 直接完成。普通本地修复可直接在当前分支处理；本技能用于用户要求交付 PR 的场景。

## 确认目标与当前改动

读取项目指令、相关代码和已有的 Spec 或 Issue。弄清完成后用户能做什么，以及哪些任务要用到上游的实际结果。已有决定和资料原位引用。

开始时查看当前分支、目标分支、对应 PR，以及已暂存、未暂存和未跟踪的改动。优先复用本次交付已有的分支和 PR；需要新分支时，在当前目录从正确的基线建一条普通交付分支。由主 Agent 统一管理分支、暂存、提交与推送。

保护用户原有内容及其暂存状态。即使在同一文件，也只纳入可明确归属本次任务的修改。若同一段改动归属不清，或分支已有无关提交会被带入 PR，先处理可安全继续的任务，把需要用户决定的具体部分说清。缺少 Git 或远程入口时，继续可完成的本地工作，说明交付 PR 还缺什么。

## 在同一目录分工

同一时间由一名 Agent 修改项目文件。主 Agent 可以自己实施，也可将明确的模块交给子 Agent，给出项目目录、目标、负责范围、用户可观察的完成条件和必要的接口约定。受托者结束写入并交回改动位置、实际行为和检查结果后，再安排下一位写入。各任务直接在当前文件上接续。

互相独立的调查可以并行。给只读调查者一个具体问题，让它返回在什么位置看到了什么、如何复现或还缺哪项事实。调查涉及正在编辑的文件时，指明要读的提交，或等写入者完成该处修改。多人共用的测试数据或运行环境也要错开。

## 按可用行为交接

上游完成后，先在当前目录验证下游真正依赖的行为，再交接。例如界面依赖保存接口时，先写入一条设置并读回，核对实际值，再接界面。检查失败就先修根因，其他独立调查可以继续。

已有工单记录实际进展及剩余事项，需要时引用上游检查结果。中断后，主 Agent 核对当前分支、实际差异、已有提交及上次验证结果，从未完成的地方继续。

## 验证并审查最终版本

通过正常使用入口验证整个功能。先运行足以证明本次改动的最小检查，失败、影响其他功能或项目交付要求时再增加检查；构建只在交付或验证需要时执行。将实际结果对应到具体版本。若本地检查依赖未收入 PR 的修改，说明该结果的适用范围；需要验证 PR 版本时使用项目已有的相应检查。

主 Agent 对照目标分支核实提交和完整差异，并检查工作目录是否遗漏了本次需要的新文件或改动。已有暂存内容单独核对，确保提交后仍保留用户原有的暂存状态。

请新的独立上下文审查者只读检查目标基线与本次提交之间的完整差异，关注正确性、接口配合和回归。每条意见给出代码位置、可触发的输入或操作、用户会遇到的后果和证据；判断依赖未确认的产品事实时写明缺哪一项。无法获得独立审查时，完成可做的自查并说明缺项。

主 Agent 核实意见，安排当前写入者修复本次引入或阻碍交付的问题。修复后按影响验证和复核；范围显著扩大时再做整体审查。范围外的问题单独说明。遇到会改变产品体验、范围或导致大量返工的取舍时，及时用几句话说明影响和建议。

## 交付与合并

在已有授权内推送并创建或更新本次唯一的 PR，关联已有 Spec 和工单。写清用户现在能做什么、实际验证了哪项行为、仍有哪项待验证；改动较大时指出优先看的代码和理由。交付依赖远程检查时，跟到最终结果，明确失败或受阻事项。必要验证与独立审查完成后交由用户决定合并；存在未完成项时标明当前状态。
