# 讨论并记录

从当前对话、项目材料和已有记录开始，用中文推进；无需先有 Spec 或领域模型。

1. 用具体使用场景澄清目标，先调查事实，默认一次问一个关键问题并给出推荐答案。内容已清楚时直接整理。
2. 结论明确后及时更新相关文档：已有 Spec 接收目标和设计，术语表接收业务定义，任务接收执行细节。只保留一份当前有效的决定。
3. 暂无合适文档时，将必要讨论结果记入 `docs/discussions/<主题>.md`；已有项目位置优先。不逐字复制聊天，也不预建空模板。
4. 新概念在讨论中即可明确并记录，复杂关系可结合 `domain-modeling` 推敲。重要且有长期解释价值的取舍沿用项目的决策记录方式。
5. 区分已确认要求、采纳的建议、待定问题和缺失证据。后续文档接管结论时，让讨论记录链接到对应位置，避免维护重复正文。

需要形成完整规格时可结合 `to-spec`；其他技能不可用时仍按以上方法完成记录。交付文档位置、已定内容和关键未知，不因记录需求而自行进入开发。
