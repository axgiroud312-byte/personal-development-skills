# 按工单冷启动执行

从 `to-tickets` 产出的工单和项目 `AGENTS.md` 开始。先核对项目级红线与实际验证命令。若只有一张小票且当前上下文干净，直接完成即可，不必为形式另起子代理。

## 一票一新会话与返修

按工单依赖顺序每次推进一张未完成工单，默认由新的干净会话或新子代理冷启动执行，只传入项目红线、本票正文、上游已验证入口与当前基线。

若验收失败需要返修，同样默认开启新的干净会话，传入合并后的目标、当前差异与失败复现命令，避免在超长旧对话里滚雪球。仅当强依赖当前未提交状态或运行中进程时，才在原会话继续。

## 实施、回写与高危复核

严守本票改动边界与先冻结的契约；跨组件或进程时，先从真实入口跑通最短路径再展开细节。实施中若因现实约束改变了规格取舍，原位同步更新对应规格。

每张票须凭真实运行证据（命令、测试或实测页面结果）验收，完成后在工单里补充进展、已验证入口与实测结果，再推进下一张票。

普通工单凭真实运行证据即可过关，不默认拉起独立审查。仅当工单触及高危红线（资金账务、权限隔离、数据迁移、对账）或用户明确要求时，启动独立只读对抗复核：只读本次 `git diff`、项目红线与相关规格，任何未用真实运行证明失败的发现一律丢弃，不报风格或假设性猜测；无有效发现即通过。
