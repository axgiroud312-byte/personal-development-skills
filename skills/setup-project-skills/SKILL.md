# 写清项目的工作入口

读取当前项目的 `AGENTS.md`、启动脚本、任务入口和已有资料。找出下一位开发者在这个项目要用的命令、路径和例外，把它们原位写进 `AGENTS.md`。保留项目其他指令；文件缺失时再创建。文档和代码有差异时，沿用现有实现的惯例，完成后列出具体差异。

## 记录哪些信息

- **启动与验证。** 核实项目实际采用的启动方式及最直接的验证入口。例如告诉下一位开发者怎样打开设置页、改一个值，并在重开项目后确认值仍存在。注明确实影响执行的前置条件，并明确写入“无运行证据不汇报”（完成声明、根因判断和审查发现必须附真实运行结果，未实际运行的推测明确标为未验证）。
- **工作资料。** 写明规格、开发工单、交付记录和已有设计资料的实际位置。优先引用已有正文。项目尚无远程任务入口时，可约定规格放在 `docs/specs/<slug>.md`、工单放在 `docs/issues/<feature>/<NN>-<slug>.md`。说明哪些是建议位置，哪些已有可打开的资料。
- **红线与例外。** 记录跨功能不可破坏的系统不变量（如权限边界、数据守恒、兼容约束），以及本项目特有的分支约定、必要检查或平台限制，并说明何时适用。

## 引用技能

按项目实际需要引用已安装的技能名或项目内可访问的链接。普通小修可直接在当前目录完成。需要推敲想法、保存规格、整理工单或按工单执行时，分别给出 `grill-me`、`to-spec`、`to-tickets`、`run-tickets` 的手动入口；界面评审按需指向 `design-quality`。通用操作步骤由各自的技能维护。

更新已有项目时，留意旧模板中按任务建立工作树或分支的说明。属于这套技能的旧流程时，将它原位换成当前入口引用；如果是项目自己另有用途的约定，保留并说明来由。只处理本次指定的项目。完成后给出修改位置与查明的差异。
