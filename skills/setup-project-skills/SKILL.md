# 配置项目约定与索引

读取现有 `AGENTS.md`、`CLAUDE.md`、远端、文档、包文件、锁文件和脚本。代码与实际行为说明现状，已确认需求决定目标；记录文档差异与处理。已有约定够用就沿用，只问调查后仍无法决定且影响配置的选择。

## 一处维护项目约定

在项目已有 Agent 入口原位维护；确需独立文件时用 `docs/agents/project.md` 并从入口引用。按实际需要记录下列内容，省略无关或未确定项：

| 可配置内容 | 记录什么 |
| --- | --- |
| 开发 | 前端、后端、数据存储的技术栈，实际目录、包管理器与启动方式。 |
| 设计 | 用户参考、组件库、原型、Token 和共享组件源；已有定制优先复用。 |
| 任务 | 跟踪平台及目标仓库，或本地任务目录；需求、Spec 与唯一状态入口的位置。 |
| 交付 | 本地修改、提交推送或 PR，目标分支与必要的协作、成果保留和清理分工。 |
| 验证 | 已有命令和强制 CI，以及本次授权目标或明确交付阶段的收尾安排。查到命令不代表运行通过。 |

当前用户要求优先；项目已确认约定覆盖个人全局偏好和技能默认，未确定部分再沿用偏好。用户可直接修改这段约定，不必重写各个技能；临时选择不自动固化为长期规则。新增框架或专业 Skill 只补用途和入口，按需读取，不把可选助手变成前置门槛；助手缺失时完成同等必要工作。

保留一段开发约定：集中实现，必要测试和构建由负责人在收尾统一安排；中途 Issue、提交和内部批次不自动触发，既有强制检查保留。完整设计直接交付 HTML 与实际 Token 文档；仅要草图按范围交付，完整授权不在草图后默认停等批准。配置本身不新建测试工程、构建流水线或业务任务，除按授权建立状态入口外，不额外创建远端标签、提交或发布。

## 项目索引

在 `AGENTS.md` 或 `CLAUDE.md` 维护一份 `## 项目索引`。只有一个就用它；都有则按既有分工选一个，另一入口引用；都没有则建 `AGENTS.md`。

用“事实｜位置或命令｜用途”短表指向真实文档、设计、源码、任务和状态。命令来自实际脚本，写明必要目录与包管理器；未建立的位置不假装存在，也不为填索引补空文件。

索引建议不超过 40 行，只存位置、命令与用途，不复制正文、数值或进度。更新时原位替换本节并保留其它内容，合并重复索引；约定相关工作先读入口，路径或命令变化时更新。

## 唯一状态入口

沿用现有入口。无约定时，有 GitHub 用固定“项目当前状态”Issue，没有则用根目录 `STATUS.md`，只选一个；README 和项目索引指向同处。远端写入核对目标与授权，结果不明先读回，不可用就标记待建立。

状态保存核对时间、阶段与范围，以及当前目标、已完成与目前可用、下一步及阻碍、需用户决定事项；详细证据引用原文档或任务。

将维护约定写入项目入口：主 Agent 汇总，执行者提供事实；接手时读回核实，在关键变化与暂停或结束前更新，无变化不反复写。写入前读最新正文并保留其它信息，区分设计、实现、待验证、分支试用、主线可用与用户验收；不为更新状态额外测试，不承诺后台实时刷新，缺证据或写入失败如实说明。

交付写入位置、已建立内容及未确定项。
