# 配置项目技能

只配置当前项目实际需要的约定。已有配置足够时沿用；其他技能可独立使用，不要求每个项目或每次任务都先运行本技能。

## 配置方法

1. 读取项目现有 `AGENTS.md`、`CLAUDE.md`、仓库远端、文档布局与运行脚本，找出已有约定。
2. 从现有材料和用户要求确定下列必要信息。缺失信息先调查；只有无法推断且会影响配置的选择才提问，给出推荐项。
3. 优先原位更新已有配置。没有合适位置时使用 `docs/agents/project.md`，只记录当前有用的内容；不创建空的规格、任务或领域文档。
4. 在项目现有的 Agent 入口文件中添加简短引用，两个入口都存在时沿用其分工；都没有时使用 `AGENTS.md`。保留原有内容，已存在的引用原位更新。
5. 核对配置与实际仓库、目录和命令一致，说明写入位置及尚未确定的部分。本技能的配置范围不包含创建远端标签、Issue、提交或执行发布。

## 需要时记录

- **文档位置与职责**：术语或领域记录保存业务定义与规则，Spec 引用领域及界面设计依据并保存整体技术设计与共同约束，Issue 保存局部设计、任务细节和具体验收；每个决定只维护一份有效正文。沿用现状；新项目可用 `docs/specs/`、`GLOSSARY.md` 和 `docs/domain/`。
- **领域模型衔接**：Spec 整体设计前检查本次业务定义，已有模型直接复用，不足时主动衔接 `domain-modeling` 或等价梳理。拆任务与实施沿用这些定义，业务变化同步领域记录、受影响的 Spec、Issue、验收与实现，不要求为小修增加文档阶段。
- **界面设计衔接**：需求与核心领域定义清楚后，`design-ui` 与 Spec 配合；拆具体 UI Issue 前具备本次足够的设计依据，已有设计系统和小改动直接复用。记录项目设计规范（缺省 `DESIGN.md`）、共享 Token 源码、组件及 registry 清单和样板入口；实际 Token 值只在源码维护，由样板与业务组件共用。设计变化同步权威依据及受影响任务，不增加阶段批准或独立展示站。
- **前端默认搭配**：通用 SaaS、工作台与 Agent 界面尚无约定时，读取可用 `design-ui` 的前端默认搭配，记录本项目采用的能力、统一方案与必要例外。已有项目方案优先，按页面需要引入依赖；配置约定本身不安装整套依赖或迁移技术栈。
- **任务跟踪**：跟踪平台、已核实的仓库或项目，以及必要状态规则。无约定时优先已确定的 GitHub 仓库，没有 GitHub 时用 `docs/issues/`；多个远端有歧义时先确认目标。
- **验证方式**：测试和审查分别采用什么方式、是否启用，以及已有运行入口和真实操作验收方式。UI 通过项目实际浏览器或桌面入口核对流程与交互，有视觉参考时核对布局几何。按可观察结果与改动风险选择，只写查到的命令，不要求每次运行全部检查或生成构建产物。
- **交付与关联**：目标分支、Issue 与 PR 的关联方式、合并及关闭条件。沿用已有授权；只请求 PR 的任务不自动合并或关闭。
- **清理位置**：本项目临时构建目录、需要保留的交付位置和临时工作树归属。提交推送及 PR 建立后，先保存交付结果再清理，保留 PR 远端分支。
- **协作约定**：项目已有的工作区及共享修改方式，只补确实需要的部分。

配置说明应让 Agent 找到现有材料和正确的操作位置。没有术语表、Spec 或固定任务系统本身不阻止开发；缺少发布目的地等必要信息时只补当前缺项。
