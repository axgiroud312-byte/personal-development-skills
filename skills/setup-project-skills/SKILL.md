# 配置项目约定与索引

负责让 Agent 找到项目事实和正确入口。已有约定足够时直接沿用，不要求每个项目或每次任务都先配置；本技能不安装技能或组件，也不代替需求、设计和开发。

## 核对并记录必要事实

读取现有 `AGENTS.md`、`CLAUDE.md`、远端、文档布局、包文件、锁文件与项目脚本，确认实际文档、设计资源、任务跟踪、命令和交付位置。缺项先调查，只有无法推断且影响配置的选择才提问。

项目专属约定优先原位更新；确需独立文档时可用 `docs/agents/project.md`。只记录会影响工作的必要事实和长期约定：

- 领域、Spec、设计与任务的权威位置和职责；变化更新对应来源，其他位置引用。
- 当前技术栈、共享 Token 与组件源、已有设计入口；完整设计按可用 `design-ui` 约定，业务实现复用成果。保留先完成本次整体设计再进入业务开发的顺序，已有设计与小改动直接复用，不增加批准。
- 任务平台、验证与审查要求、交付分支及本地修改、推送或 PR 规则，必要的协作、清理归属和成果保存位置。

不抄写各技能的完整流程；没有术语表、Spec 或正式任务系统本身不阻止工作，不创建占位文档或设计项目。除按授权建立固定状态入口外，配置本身不创建任务 Issue、远端标签、提交或发布。

## 项目索引

在项目 Agent 入口维护一份固定的 `## 项目索引`：只有 `AGENTS.md` 或 `CLAUDE.md` 时写入该文件；两者都有时按既有分工选择一个，另一入口引用；两者都没有时新建 `AGENTS.md`。

用“项目事实｜位置或命令｜一句用途”短表指向实际存在的领域记录、Spec、Token 说明、设计板、实际样式与组件源码、任务与状态入口，以及必要项目约定。尚未建立的位置留在约定中，不列作已有成果，不填空项。

开发、测试与预览命令必须来自包文件或实际脚本，注明必要目录与已核实包管理器；查到不等于运行通过，未查到不凭惯例补齐。表旁约定：“涉及上述内容时先读对应入口；路径或命令变化时同步更新索引。”

索引只存路径、真实命令与用途，不复制正文、数值或进度，建议整个段落不超过 40 行。再次执行在下一同级或更高标题前原位更新并保留其他内容，已有重复索引合并为一份。

## 唯一项目状态入口

已有入口直接沿用。没有约定时，有 GitHub 默认复用或建立固定“项目当前状态”Issue，没有 GitHub 用根目录 `STATUS.md`；两者只选一个。建立远端入口核对目标与授权，结果不明先读回；不可用或未获授权时标明待建立，不虚构链接或另建第二份状态。

README 与项目索引指向同一入口。状态只保存最近核对时间、阶段与范围，以及“当前目标、已完成与目前可用、下一步及阻碍、需用户决定的事项”四项短摘要，详细证据链接到原文档、任务或 PR。

将以下维护约定写入项目入口或其引用文档，由索引指向：

- 当前主 Agent 负责项目级摘要，执行者提供各自任务事实；多会话协作明确一个汇总负责人。
- 开始或接手时读取状态并核对事实；关键结论、阶段、阻碍或交付变化，以及暂停或结束本轮前更新，无实质变化不反复改写。
- 写入前读取最新正文并保留其他内容，区分设计完成、代码修改、分支试用、主线可用与用户验收，不把分支结果写成主线可用。
- 状态依赖工作中的 Agent，不承诺后台实时刷新；中断或缺少新证据时标明待核实，写入失败如实说明，下次接手再核对。

最后核对索引、命令与状态链接，报告写入位置、实际建立内容及未确定项。
