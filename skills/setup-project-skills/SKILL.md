# 配置项目约定与索引

本次调用只处理项目约定，不自动开始规格、任务拆分、设计或开发。后续维护已建立的命令和入口无需重新调用。

读取现有 Agent 入口、远端、包文件、锁文件、脚本和必要源码，核实当前技术栈与目录。已有约定够用就沿用，只问调查后仍无法确定且会改变配置的选择；代码与文档不一致时说明差异与处理。

## 集中在 AGENTS.md

在项目根目录 `AGENTS.md` 原位维护必要内容，缺失才创建。已有其他客户端入口按实际需要引用该文件，保留无关内容；不复制两套项目规则，不另建开发规范、项目配置或状态文档。

| 内容 | 只记录已核实的信息 |
| --- | --- |
| 开发 | 技术栈、真实目录、包管理器、启动方式与必要开发约定 |
| 设计 | 指定参考、已有原型与 Token 位置、正式主题与组件入口 |
| 任务 | 目标仓库及可用任务平台；没有远程任务平台时才指定本地 Issue 目录 |
| 交付 | 本地修改、提交推送或 PR，目标分支与必要分工 |
| 验证 | 现有检查命令、强制 CI 和收尾要求；发现命令不代表已经运行通过 |

当前用户要求优先，未确定部分再沿用项目约定和技能默认。临时决定不自动固化；专业技能只补必要用途和入口，不把可选助手变成前置门槛。

保留四个手动入口的真实边界：`setup-project-skills`、`to-spec`、`to-tickets`、`design-ui` 只由用户主动调用；其他技能可以读取已有材料，继续正常实现和维护，不代为启动专项流程。

开发约定保持简短：集中实现，收尾统一安排必要验证与构建，已有强制检查保留。设计先交 HTML 原型，用户满意后再提取 Token；原型不等于正式实现。

## 文档范围

项目指令归 `AGENTS.md`。`docs` 只按需保存 Spec、本地 Issue、HTML 设计原型和 Design Token；远程 Issue 可用时只维护远程任务。已配置远程但暂时不可用，在聊天说明，不擅自建立本地副本。

Spec 只承接本规格，Issue 只承接本任务。不新增术语表、领域文档、讨论记录、状态文档、总览任务或报告，也不将这些内容改名合并进去；不为配置完整而创建空文件。该规则约束资料产出，不授权清理其他既有项目文件。

## 必要索引与交付

在 `AGENTS.md` 中用简短的“位置或命令／用途”表指向真实源码、规格、任务和设计。只列当前需要的入口，不复制正文或项目进度；路径与命令变化时原位更新，不另建索引文件。

实际进展在对应 Issue 或聊天中交接，不另建状态文件或状态总览 Issue。交付本次写入位置、约定变化和未确定项；配置任务不额外创建远端标签、提交、发布或测试工程。
