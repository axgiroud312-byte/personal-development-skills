# 配置项目约定与索引

以代码和实际行为判断现状，以用户已确认需求确定目标；文档不一致时沿用现有实现惯例，说明差异与处理。已有约定足够时直接沿用，不要求每次任务重新配置。

## 记录必要事实

读取项目的 `AGENTS.md`、`CLAUDE.md`、远端、文档、包文件、锁文件与脚本，核对文档入口、技术栈、设计与组件源、任务平台、已有强制检查、交付分支和协作职责。缺项先调查，只问确实影响配置且无法推断的选择。

原位更新项目约定，确需独立文件时可用 `docs/agents/project.md`。只写会影响工作的事实，引用需求、领域、Spec、原型、Token 和任务的真实位置，不复制正文或补空文件。

保留一段开发约定：以集中开发为主，必要测试和构建由整体负责人在授权目标或明确交付阶段收尾统一安排，中途 Issue、提交不自动触发；设计原型做好即交付，现有测试与强制 CI 保留。配置本身不新建测试工程、任务、提交或发布；固定状态入口按当前授权建立。

## 维护项目索引

在项目的 `AGENTS.md` 或 `CLAUDE.md` 中维护一个 `## 项目索引`；两者都有则按已有分工选一个，另一文件引用；都没有时新建 `AGENTS.md`。

用“事实｜实际位置或命令｜用途”短表列必要入口，建议整个段落不超过 40 行。命令来自实际脚本，注明目录与包管理器；查到不等于运行通过，不凭惯例补命令。索引不保存进度，重复执行时原位更新本节并保留其他内容。

写明：“涉及上述内容时先读对应入口；路径或命令变化时同步更新索引。”

## 配置唯一状态入口

已有入口直接沿用；没有时，有 GitHub 默认复用或建立固定“项目当前状态”Issue，没有 GitHub 用根目录 `STATUS.md`，两者只选一个。创建远端入口核对授权，结果不明先读回；不可用就标明待建立，不虚构链接或另建第二份状态。README 与项目索引指向同一入口。

状态记录核对时间、阶段与范围，以及当前目标、已完成与可用内容、下一步及阻碍、需用户决定的事项；证据链接到原文档或任务。把下列维护约定写入项目入口：

- 主 Agent 汇总状态，执行者提供事实；多会话明确一个汇总负责人。
- 接手时核对，关键变化及暂停或结束前更新；先读最新正文，保留其他内容，无变化不反复改写。
- 区分设计完成、实现待验证、分支可用、主线可用与用户验收，不为更新状态额外测试。
- 状态由正在工作的 Agent 维护，不承诺后台实时刷新；缺少证据或写入失败时说明。

最后核对索引与状态入口，报告实际写入位置和未确定项。
