# 配置项目约定与索引

读取 `AGENTS.md`、`CLAUDE.md`、远端、文档、包文件、锁文件和实际脚本，核实项目现状。代码与行为优先，已确认的新需求决定配置目标；文档冲突时沿用现有惯例并说明差异。已有约定足够就沿用，不把本技能作为开发前置门槛。

## 记录必要约定

原位维护项目入口，确需独立文档时可用 `docs/agents/project.md`。只记录会影响工作的事实：现有需求/领域/Spec/任务的位置，原型、Token 与组件源，技术栈、任务平台、交付分支及协作归属；每项定义只保留一份正文，不为凑齐目录补文档。

约定以集中开发为主，必要测试与构建由负责人在授权目标或明确交付阶段收尾统一安排；Issue、提交和内部批次不自动触发。已有测试与强制 CI 保留，设计原型直接交付 HTML 与 Token，不套用功能验收。具体执行复用可用的 `implement`，不在项目入口抄完整流程。

配置本身不新建测试工程、构建流水线或业务任务；除按授权建立状态入口外，不额外创建远端标签、提交或发布。

## 项目索引

在 `AGENTS.md` 或 `CLAUDE.md` 维护一份 `## 项目索引`。只有一个就用它；都有则按既有分工选一个，另一入口引用；都没有则建 `AGENTS.md`。

用“事实｜位置或命令｜用途”短表指向真实存在的文档、设计、源码、任务和状态入口。命令来自包文件或脚本，写明必要目录与包管理器；查到不等于运行通过，也不意味着现在执行。未建立入口不假装存在。

索引建议不超过 40 行，只存位置、命令与用途，不复制正文、数值或进度。更新时在下一同级或更高标题前原位替换并保留其它内容，合并重复索引；约定相关工作先读入口，路径或命令变更时更新。

## 唯一状态入口

沿用现有入口。无约定时，有 GitHub 用固定“项目当前状态”Issue，没有则用根目录 `STATUS.md`，只选一个；README 和项目索引指向同处。远端写入核对目标与授权，结果不明先读回，不可用就标记待建立。

状态保存最近核对时间、阶段与范围，以及当前目标、已完成与目前可用、下一步及阻碍、需用户决定事项；详细证据用链接引用。

将维护约定写入项目入口：主 Agent 汇总，执行者提供事实；接手时读回核实，在关键变化与暂停/结束前更新，无变化不反复写。写入前读最新内容并保留其它信息，区分设计、实现、待验证、分支试用、主线可用与用户验收；不为更新状态额外测试，不承诺后台实时刷新，缺证据或写入失败如实标明。

交付写入位置、已建立内容及未确定项。
