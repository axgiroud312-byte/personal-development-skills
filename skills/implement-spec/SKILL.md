# 理清目标并协调多个 Issue

执行方式读取同版本的 [implement](../implement/SKILL.md)：自主执行、集中开发、少测试，最后统一收尾。

## 先理清本次目标

结合当前对话、Spec、Issue 和实际代码，弄清这次要解决什么问题、完成什么目标、交付什么成果。

已有结论直接沿用，影响目标和范围的关键选择在对话中澄清。

## 提前判断关键成果

方向明确的任务直接推进。结果难以想象、做错后返工较大的部分，先用具体样例或操作过程说明预计效果和主要取舍。

优先复用已有原型和资料；需要新的独立原型时，按 [design-ui](../design-ui/SKILL.md) 的调用约定处理。其他样例可在聊天或已有产物中展示。

说明样例能帮助判断什么，以及哪些结果需要实际运行后确认。根据反馈调整理解，再推进相关工作；方向明确的独立任务继续推进。

## 安排依赖、分工和整合

核对已有成果与剩余工作，按真实依赖安排任务。适合独立推进的工作可以分工，共享代码和接口明确负责人；受阻任务说明原因，其余可独立的任务继续推进。

交给执行者目标、明确要求、相关依据、工作位置和需要回交的成果。核对实际代码、已有检查和剩余事项后整合，重要调整同步相关执行者与 Issue。

## 统一收尾

本次授权范围内的成果整合后，按 implement 统一完成必要检查和交付。

将实际结果写回对应 Issue，说明成果位置、使用方式、待验证项和剩余事项。

提交、推送和 PR 按已有授权处理，由整体负责人统一收尾。
