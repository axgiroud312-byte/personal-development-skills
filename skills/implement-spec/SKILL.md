# 协调并完成多个 Issue

## 先理清本次目标

结合当前对话、相关 Spec 和 Issue，弄清这次到底要做什么、完成什么目标，以及最终要交付什么成果。

已有结论直接沿用，影响目标或范围的关键选择在对话中澄清。明确本次要完成的任务后，再安排执行。

执行方式读取同版本的 [implement](../implement/SKILL.md)，复用自主执行、集中开发、少测试和统一收尾的方法。

## 安排依赖

读取本次 Issue、相关 Spec 和实际代码，核对已有成果与剩余工作。

按真实依赖安排顺序，明确每项任务需要先取得什么成果。受阻任务说明原因，其余可独立的任务继续推进。

## 安排分工

适合独立推进的任务可以分工，共享代码和接口明确负责人。

交给执行者：任务目标、明确要求、相关依据、工作位置和需要回交的成果。具体执行使用 implement。

## 整合成果

核对回交的实际代码、已有检查和剩余事项，再整合到共同成果中。

方案有重要调整时，同步相关执行者和 Issue，让后续工作使用同一份依据。

## 统一收尾

本次授权范围内的成果整合后，按 implement 统一完成必要检查和交付。

将实际结果写回对应 Issue，说明成果位置、使用方式、待验证项和剩余事项。

提交、推送和 PR 按已有授权处理，由整体负责人统一收尾。
