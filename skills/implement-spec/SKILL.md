# 连续完成多个任务

先读取同版本的 [implement](../implement/SKILL.md)，按 Issue 和实际代码自主推进，集中开发、少测试、统一收尾。这里负责多个任务之间的协调。

## 安排当前工作

核对总目标、完成标准、已有进展和交付范围。按实际依赖安排执行顺序，已有代码或成果可用后，就推进依赖它的任务。

使用已有 Issue 安排开发。用户调用 `to-tickets` 后再拆分或重组正式任务；内部工作步骤由负责人自行安排。

适合独立推进的工作可以分工，共享代码和共同决定明确负责人。交给执行者：目标、必须保留的要求、当前方案与重要假设、相关位置，以及回交什么成果。

## 持续推进与整合

收到回交后核对真实代码、已有检查和剩余事项，再整合进共同成果。子任务可以标明待整体验证，由负责人安排必要检查。

方案随新事实调整时，同步受影响的执行者、Spec 和 Issue。需要用户决定的重要取舍简短说明，其余工作继续。遇到阻碍时说明证据和恢复所需条件。

长任务或中断前，在对应 Issue 或聊天中交接当前位置、已有成果和下一步，方便继续工作。

## 统一收尾

关联任务集中完成，子任务回交成果和已有检查，由负责人按 `implement` 统一整合与收尾。中途的实际错误或关键疑问按需要小范围检查，最终核对各 Issue 的预期结果。

最终交付成果位置、使用方式、任务完成情况和真实检查结果。待验证、待用户验收和仍受阻的部分分别说明；进展回写对应 Issue。

按已授权的方式提交、推送或处理 PR，统一安排成果保留和临时内容清理。

## 配套安装

`implement-spec` 与同源同版本的 `implement` 一起使用。依赖缺失时先在已安装技能中定位，仍缺少则补齐配套技能：

```sh
npx skills@latest add axgiroud312-byte/personal-development-skills --skill implement implement-spec
```

按当前客户端和安装范围补充参数。
