# 连续完成整套开发

主 Agent 负责多个任务的依赖、整合和整体交付。直接使用已有需求、Spec 或 Issue，只补执行所需的信息，不要求先跑完整套技能。

## 建立任务与工作位置

1. 明确总目标、完成标准、已有进度和交付目标分支。已有 Issue 直接复用；Issue 驱动项目按当前方案补足可执行任务，每项写清目标、范围、验收、依据及阻塞关系，可结合 `to-tickets` 或自行整理。
2. 区分总目标与可独立执行的子任务。父子关系用于汇总，真实阻塞关系决定执行顺序；检查循环依赖和共享修改边界。
3. 保护原工作区。需要共同集成时选择集成分支；独立任务确有并行收益且环境支持时使用隔离工作树并委派，否则顺序完成。公共设计和共享源码明确维护者。

## 持续开发

4. 领取前置条件已满足的任务，给执行者 Issue、必要上下文、实际工作位置和验收目标，按 `implement` 的方法或等价步骤实施。测试、审查分别按项目设置选择，不强加额外步骤。
5. 核对返回的代码、验证证据和未完成项，再整合到约定位置。依赖公共改动的任务取得对应代码后继续，不能只靠“已完成”的消息解除阻塞。
6. 更新 Issue 的当前结果、阻碍及分支/PR 关联。只同步受影响的现有文档；关键变更保留简短说明，不另建逐操作日志。
7. 继续所有已可执行任务，不在每项结束后询问是否继续。真实阻碍只暂停受影响部分；重复失败却没有新证据时明确报告阻碍，不无休止重试同一步。

## 整体 PR 与收尾

8. 按授权提交、推送集成结果并创建或更新整体 PR，列出覆盖的总目标、子 Issue、关键改动、逐项验证结果和未完成内容。可在有首批可提交结果时先建 Draft PR，后续持续更新；不要求每个子任务额外创建 PR。
9. 核对跨任务的接口、数据和真实使用流程，保存可试用结果与必要说明。只请求 PR 时保持待评审或待合并，不自动合并或关闭相关子 Issue 及总目标；按项目约定区分开发、验证和用户验收。
10. 确认各临时工作树的改动已整合、推送，并被实际建立的 PR 覆盖；把需要保留的交付物保存到待清理目录以外，确认保存成功且可访问。核对路径与归属、停止本任务占用进程，再清理本次无关构建产物及临时工作树，保留主工作区、他人修改和 PR 远端分支。
11. 核对清理后的实际残留。尚未交付的内容或失败任务的必要恢复材料保留并说明，不能为了收尾丢弃工作。只授权本地交付时保留承载未推送代码的工作树。

最终提供 Issue 与 PR 对应关系、整体试用入口、已验证结果、剩余阻碍，以及实际清理和保留内容。

用户要求“做完后解释”时，在完成整体交付后使用可用的 `explain-work` 讲清整体结果、主要变化及原因、关键流程和验证范围。该技能不可用时依据实际证据自行说明，不阻塞交付；讲解不能替代尚未完成的实施，也不在每个子任务后打断持续开发。
