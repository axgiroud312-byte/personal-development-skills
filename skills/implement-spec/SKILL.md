# 连续完成整套开发

**先读取同版本的 [implement](../implement/SKILL.md)**，复用开发节奏、工作保护、收尾验证、交付与清理方法。这里仅补充整体负责人职责；两者需配套安装。

以代码和实际行为核实现状，以已确认的新需求确定目标。直接接手已有材料与进度，不要求先跑整套技能。

## 组织当前范围

1. 核对总目标、完成标准、当前进度、交付分支和授权。按规模使用原始需求、PRD、单份或多份 Spec，只补当前交付必要的业务、方案和设计；远期保留范围与依赖。
2. 按需使用 `to-tickets` 或等价方法补足近期任务。按真实依赖安排可观察的完整流程，允许先列调查、设计和环境任务；父子关系只表示归属，不等于阻塞关系。
3. 明确公共设计、共享源码与环境准备的维护者，把同一份原型、Token、配置和组件源交给各执行者。检查循环依赖与共享修改冲突。
4. 任务可独立推进且有并行收益时隔离分工，否则顺序完成。给执行者目标、必要依据、实际目录、预期结果、提交/回交位置及职责；单项实施使用 `implement`。

## 持续实施与整合

核对回交的真实代码、提交或工作树、已有检查与未完成项后整合。依赖取得对应代码或成果才解除，不能仅凭“已完成”的消息继续；子任务未验证可标为待整体收尾，不据此要求逐项补测试。

发现变化时更新所属依据、相关 Spec 与任务，公共决定由明确负责人维护。只暂停真正受阻的部分，持续推进已授权范围，不逐项询问是否继续；重复失败且没有新证据时报告阻碍。

按有界批次工作，任务过长或中断时留下当前位置、已有成果、未完成项和下一步；接手时据此恢复，不一次载入整个项目，也不把内部批次结束当作交付。

## 整体收尾

在授权目标或明确的独立交付阶段收尾时，统一按 `implement` 选择必要验证并处理发现的问题，重点核对跨规格一致性和模块衔接。不能删掉未实现需求来宣称完成。

主 Agent 统一交付、维护唯一项目状态和安排清理。按可审查范围维护一个或多个 PR，Spec、Issue、PR 不必一一对应；交付任务与成果的对应关系、试用入口、实际验证状态和剩余阻碍。区分设计完成、代码已回交、待验证、分支可用、主线可用与用户验收。

## 引用缺失时

先在已安装技能中定位同源同版本的 `implement`；仍缺失则说明依赖，补齐两者后再执行，不凭猜测省略规则。安装命令如下，按当前 Agent 和全局/项目范围补充参数：

```sh
npx skills@latest add axgiroud312-byte/personal-development-skills --skill implement implement-spec
```
