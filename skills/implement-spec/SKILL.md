# 连续完成整套开发

开始时直接读取 [开发与交付的共同约定](../implement/references/development.md)；单项实施交给 [implement](../implement/SKILL.md)。本技能与 `implement` 配套安装，缺少引用时先恢复依赖，不能跳过共用规则。这里仅补充整体负责人的工作。

以代码和实际行为判断现状，以用户已确认需求确定目标；文档不一致时沿用现有实现惯例，交付时说明差异与处理。

## 组织当前工作

1. 核对总目标、完成标准、进度、目标分支与交付授权。复用已有需求和规格，只细化近期范围；依据不足时按需衔接 `domain-modeling`、`to-spec` 或 `design-ui`，不要求先走完整套流程。
2. 复用已有 Issue，必要时用 `to-tickets` 补齐任务。按真实依赖安排顺序，区分父子归属与阻塞关系，检查循环依赖、共享修改冲突及跨规格的接口与数据约定。
3. 明确公共设计、共享组件、环境和整合分支的维护者；把可取得的原型、Token、配置或代码交给执行者，避免各自初始化。独立任务确有收益且工具支持时并行，否则顺序推进。

## 连续实施与整合

选择前置条件已满足的任务，交接目标、范围、相关规格、实际目录、预期结果和回交位置，不要求执行者读完整项目。收到实际代码、提交或工作树后再整合；依赖任务取得对应成果才解除阻塞，不能只凭“已完成”的消息继续。

持续推进已授权范围，阶段衔接后继续后续工作，不逐项询问是否继续。变化先维护对应来源，再同步相关规格、任务与状态；只暂停真正受阻的部分，重复失败且没有新证据时报告阻碍。任务过长时保存现状、证据、未完成项和下一步，后续从记录恢复。

## 统一收尾与交付

达到共同约定中的收尾节点后，合并任务留下的必要检查，核对整体关键流程、跨模块衔接和具体风险，修复后收敛到实际交付范围。PR、状态与临时工作树清理由主 Agent 统一处理，不让各子任务重复执行。

按共同约定完成交付，说明任务与成果的对应关系、试用入口、实际验证和未完成部分；不能把一个阶段实现完成写成整个目标完成。
