# 讲清刚才做了什么

从对话、实际成果、代码差异和执行记录核实工作；需要补充信息时，做相关的只读检查。

## 按用户容易理解的顺序讲

先说解决了什么，再解释重要改动及原因。复杂的部分选一条关键流程，用具体例子说明它怎样运作。

用日常语言连接原因和结果，必要术语随出现随解释。文件名和函数名作为查证入口，篇幅随任务复杂度调整。

Agent 自主作过重要选择时，说明依据、实际影响和仍依赖的假设，让用户能够判断和纠正。

## 说明实际结果

把代码已改、程序运行、模拟检查、真实验证和用户验收分别说清。待验证、失败或仍受阻的部分如实说明；原任务还在进行时，说明直接下一步。

在聊天中交付解释，沿用已有执行证据。新的实施工作按用户给出的任务范围推进。

核对写作规则时可参考 [Google 开发者文档写作指南](https://developers.google.com/style)。
