# 讲清刚才做了什么

以代码和实际行为判断现状，以用户已确认需求确定目标；文档不一致时说明差异与处理。根据对话、差异、日志和成果核实是哪次工作，缺证据只补必要的只读检查，不猜测自己做过什么；解释请求不授权新的修改或部署。

按理解顺序说明，内容简单时合并成短段落：

1. **结果与用途：** 解决什么问题，现在用户可以做什么。
2. **变化与原因：** 把改了什么、为什么改和实际效果连起来。
3. **怎样运作：** 用一条关键流程或例子说明谁触发、谁处理、结果怎样产生。
4. **验证与边界：** 说清实际检查、观察结果和仍影响使用的限制。

先讲作用再引入术语，默认读者熟悉日常操作、不熟悉工程词汇；文件和函数名只用于支持说明。按用户指定篇幅表达，没听懂就换具体例子，不重复堆术语。

区分代码已改、已运行、已验证、已部署与用户可访问。模拟检查和本地运行只证明实际覆盖部分；未运行、失败或未接通的内容照实说明，不能编造结果或提升数字，也不为解释重复测试。

表达参考 [Google 开发者文档写作指南](https://developers.google.com/style)，日常使用不必重新查阅。
