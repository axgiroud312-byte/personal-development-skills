# Issue 编写模板

写到没读过聊天的人也能接手。按任务大小合并或删除段落，沿用已有模板，不虚构编号、负责人、链接或完成状态；小修可直接用一段目标加预期结果。

结果描述用于指导实现；“测试通过”“构建通过”不能代替功能目标。必要测试、验证与构建由整体负责人在授权目标或明确交付阶段收尾合并安排，不逐 Issue 铺测试或打包步骤。

## 交接（有实际信息时填写）

- **状态与位置：** <待开始／受阻／实现已交回、待整体验证等；真实目录、分支与分工>
- **交付：** <实际改动、提交或 PR；本地交付不强行建远端记录>
- **验证与待办：** <实际做过的检查、待收尾核对的具体风险、已知强制检查及剩余问题；不为填写而额外运行命令>

正文保持当前要求，评论记录关键取舍、阻碍和交付事实；提交不等于验收，子任务结束不等于总目标完成。

---

调查任务交证据与结论；设计任务先交 HTML 原型、再提取 Token，不附验收报告；环境任务只准备本次确需配置；功能与修复交约定行为及具体收尾事项。

**小任务示例：允许分页选择 100 条。** 想实现：允许值从 20、50 扩展为 20、50、100；想要：省略参数仍用代码当前默认值 50，无效值沿用原错误处理；不想要：改变默认值或返回类型。预期返回条数不超过所选页大小，数据不足不要求满页。README 与代码不符时说明差异，必要核对留到本次开发目标收尾。
