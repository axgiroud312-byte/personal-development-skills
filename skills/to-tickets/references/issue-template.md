# Issue 编写模板

只记录本任务的要求、方案、依赖、结果与进展，不附术语表、领域文档或项目总览。远程 Issue 与本地任务正文只维护一处。三问保留，其他部分只填本任务需要的信息，现有平台模板可映射。已有 Spec 时引用具体章节与场景，只补局部差异；没有可用规格时补到没读过聊天的人也能接手。不为凑齐标题复制正文、编造链接或预填交付记录；执行节奏沿用 `to-tickets`。

## 具体实施方案（已有完整依据时引用）

写到下一位执行者能开始实施：本任务涉及的变更、连接方式与必要约束，已有完整方案就引用，不重复正文。公共输入输出、字段、状态与错误含义缺失才补齐；分清样例与真实接入。引用已有原型与对应 Token，缺失只记所需结果，不自动启动制作。

在容易混淆处说明哪些是明确要求、哪些是当前工程选择或待核实假设。执行时可依据新事实调整非强制细节，并原位更新实质变化及依据；不能擅自改变目标、明确约束、关键体验或授权范围。

任务产出按需选择：调查交证据与结论；设计由用户主动调用 `design-ui` 后先交一个 HTML 展示版，确认该版后续接输出一份 Token，交接注明是否已确认；仅要草图不追加 Token，不另交报告或组件清单。环境准备交必要配置和启动方式；功能/修复交约定行为与代码。只为需要独立交接的成果单列任务。

**小任务示例：允许分页选择 100 条。** 本次想实现：在现有 20、50 中增加 100。想要：省略参数仍默认 50，20、50 仍可用，无效值沿用原错误处理。不要：改变默认值、返回类型或其它分页逻辑。实际条数取决于匹配数据；引用现有接口，必要核对交由所属目标收尾。
