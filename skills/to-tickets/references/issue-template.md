# Issue 编写模板

写到没读过聊天的人也能接手并理解预期结果。按任务大小删减或合并；明确的小修用短正文即可，已有平台模板直接映射。删除无关占位项，不虚构编号、负责人、链接或完成状态。

默认把测试与构建留到本次授权开发目标的收尾，不为每项实现附带测试代码、覆盖率或打包步骤。以下预期结果用于指导开发，不代表必须在本 Issue 中执行一轮验收。

## 收尾事项（有具体需要才填写）

- <仍需在本次开发目标收尾核对的关键流程或具体风险；没有则省略>
- <实际交付需要的构建或已有强制检查；未明确时不自行添加>

连续开发由主 Agent 合并这些事项，不为每个 Issue 重跑；一个 Issue 是完整独立请求时，其实现结束可以是本次收尾。不自行创建测试框架、覆盖率目标或打包流水线；设计预览不套用收尾测试要求。

## 执行与交接（有实际信息时填写）

- **当前状态：** <待开始／受阻／执行中／实现已交回、待整体验证等，以项目约定为准>
- **执行位置与分工：** <真实目录、分支、负责人或主 Agent 的交接要求>
- **交付：** <实际改动、提交或 PR；本地交付不强行创建远端记录>
- **验证状态：** <确实做过的检查与结果；未做时写待收尾验证，不为填此项额外运行命令>
- **剩余问题：** <尚未完成或需接手的内容>

正文保持当前要求；需求变化先更新目标，不让过时测试反过来限定新需求。评论按平台习惯记录取舍、阻碍和交付事实；代码提交不等于验证通过，子任务结束不等于总目标完成。

## 按任务类型调整

| 类型 | 主要产出 |
| --- | --- |
| 调查 | 明确问题、证据、结论及尚不能确定的部分，说明会影响什么决定 |
| 设计 | 先完成 HTML 预览，再提取对应 Token；做好直接交付，不附验收流程 |
| 环境准备 | 本次确需的配置与启动方法，不默认搭建测试或构建流水线 |
| 功能／修复 | 完成约定的行为变化，交回代码、已知问题和具体收尾事项；中途不强制附测试 |

## 小任务示例

**标题：允许分页选择 100 条**

依据当前代码，默认仍为 50 条，只将允许值从 20、50 扩展为 20、50、100，返回类型和错误处理沿用现有实现。README 的默认值与代码不符时同步说明。

预期：省略参数仍采用 50，允许指定 100，原有 20、50 仍合法，无效值按原约定拒绝；实际返回条数取决于匹配数据，不要求每页必满。开发时直接改实现，不额外加测试子任务或反复打包；必要核对留到所属开发目标收尾，独立小修则在本次末尾按需确认。
