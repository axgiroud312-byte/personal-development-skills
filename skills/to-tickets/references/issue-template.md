# Issue 编写模板

写到下一位执行者能够接手。已有 Spec 或方案引用具体章节，再补本任务的做法和差异。按任务大小选择栏目。

---

# <要达成的结果>

## 目标与范围

- **目标：** <本任务解决什么问题，交付什么>
- **范围与要求：** <本次涉及的功能、必须保留的行为和用户明确选择>
- **依据：** <对应 Spec 章节、原始需求或设计位置>

## 具体做法

<说明要改哪里、各部分怎样连接、需要处理哪些状态。已有完整方案就引用；把信息写到能开始实施。>

用户明确要求作为执行依据，工程细节可以根据实际情况调整。重要假设与变化写明依据和影响，需要用户决定的取舍交回用户。

## 依赖与协作（按需）

<需要先取得的代码、设计或决定及其位置；可先推进的部分，以及共享修改的负责人。>

## 预期结果

<引用本任务负责的 Spec 标准，补充本项独有结果。直接从需求开始时，写清关键操作和可观察结果。必要检查由授权目标的负责人统一安排。>

## 实施记录（实施后填写）

- **成果：** <实际代码或产物位置，当前可用情况>
- **检查：** <实际做过什么、结果如何；待整体收尾的内容如实标明>
- **重要调整：** <确有的方案变化、原因和影响，以及文档与实际情况的差异>
- **下一步：** <剩余事项、阻碍或接手内容>

远程 Issue 用正文维护当前要求、评论记录进展；本地任务在同一文件原位更新。

**小任务示例：分页增加 100 条选项。**

在已有 20、50 条选项中加入 100。默认仍为 50，沿用现有返回格式和错误处理，实际返回数量取决于匹配数据。接口引用现有定义，相关检查放到所属目标收尾。
