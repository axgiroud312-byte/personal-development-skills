# 有依赖或交接时拆工单

从原需求、现有规格或已有工单开始。一人能连续做完、也没有需要单独交付的中间成果时，省去工单，即使改动跨界面、接口和数据库。已获开发授权就直接做，只要求规划时说明判断即可。用户明确要留票跟踪时，沿用或建立一张。

只有能说出哪项后续工作依赖什么成果、谁要接手哪段工作，或任务过长需要按可独立验证的里程碑分段落盘时，才沿这条边界拆票。例如，定时调度要交给另一人接入，上游先交付能按指定版本运行的执行器，下游拿这个入口验证定时触发。

票里写本票要交付什么、下游用什么，以及涉及交接或并行时的改动边界与先冻结的接口契约。验收已在需求或规格里写清的，指到具体场景；接手者无法访问原讨论时，把必要决定放到一处可访问的正文。只有本票新增的验收才在票里写一次，跨票场景归接通整条流程的那张票。

沿用项目的任务入口和已有工单。获准发布时，按实际依赖建立阻塞关系，有规格工单时关联其子任务。发布结果不明时先查回，避免重复建票。本地工单默认放在 `docs/issues/<feature>/<NN>-<slug>.md`。返回工单及依赖关系；若只要求讨论，就在对话中交付。
