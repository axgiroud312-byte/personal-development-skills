# 有依赖或交接时拆工单

从原需求、现有规格或已有工单开始。一人能一次交付的改动可以直接做，跨界面、接口和数据库也一样。只请你判断是否要拆时，说明结论即可；用户明确要一张跟踪票时沿用或建立一张。

拆之前先回答：谁或哪项后续工作要接手什么成果？例如，同一人做完发布和自动触发，可以一起交付；若执行器要先交给负责定时调度的人，上游交付“按指定版本运行”，下游据此接入定时触发。按这种真实边界拆，每张票尽量交付一项能用的行为。

票里写本票要交付什么、下游用什么。验收已在需求或规格里写清的，指到具体场景；接手者无法访问原讨论时，把必要决定放到一处可访问的正文。只有本票新增的验收才在票里写一次，跨票场景归接通整条流程的那张票。

沿用项目的任务入口和已有工单。获准发布时，按实际依赖建立阻塞关系，有规格工单时关联其子任务。发布结果不明时先查回，避免重复建票。本地工单默认放在 `docs/issues/<feature>/<NN>-<slug>.md`。返回工单及依赖关系；若只要求讨论，就在对话中交付。
