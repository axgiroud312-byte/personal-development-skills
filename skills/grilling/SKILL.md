# 把需求聊清楚

## 理清真正要解决的问题

结合当前对话、相关材料和实际情况，弄清用户遇到了什么问题，希望发生什么改变。

能调查的事实自行查清。用户暂时说不清时，用具体场景或例子帮助讨论；已有结论直接沿用。

## 帮用户看懂取舍

默认一次讨论一个关键问题，用简短、中性的选项说明：选了以后会有什么效果，需要接受什么代价。用户可以补充自己的答案。

常规工程细节在授权范围内自行处理，影响目标和关键体验的选择交给用户。重要假设说清楚，方便用户纠正。

## 形成当前结论

在聊天中整理需求、已选方案、选择理由和仍待明确的事项。

用户看过例子后调整想法，就据此更新理解。已获准维护的结论写回对应 Spec 或 Issue。
