# 理清需求

以代码和实际行为判断现状，以用户已确认需求确定目标；文档不一致时沿用现有实现惯例，说明差异与处理。

1. 读取当前对话、材料与必要代码，确认使用者、问题、主要操作、结果与范围，复用已定结论。事实自行调查，可逆细节自行判断。
2. 只问无法调查解决且会改变目标、范围、核心用法或整体方案的选择。默认一次一个问题，每题给两个或更多清楚、中性、可区分的选项，允许用户补充；不重复问已确认内容。
3. 提问时只输出问题和选项，不附建议、推荐、理由、优缺点或额外说明。用户要求集中提问时可合并互不依赖的问题，每题仍有选项。
4. 区分已确认要求、用户选择、待定项与未验证假设。目标、场景、范围、关键取舍和可观察结果足够时结束；保留用户已选含义，材料不足就说明缺口，不换成更容易实现的目标。

```text
首版支持哪些设备？
A. 仅电脑
B. 仅手机
C. 电脑和手机
```

只讨论就在聊天中整理。要求记录时更新对应领域、Spec、设计或任务来源；暂无位置可用 `docs/discussions/<主题>.md`，正式文档接管后保留背景与链接，不复制聊天或预建空文档。

交接已定结论、依据和关键未知；需正式方案时衔接 `to-spec`，其他后续工作按当前授权继续，不要求用户逐个调用技能。
