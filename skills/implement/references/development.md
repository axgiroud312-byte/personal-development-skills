# 开发与交付的共同约定

供 `implement` 和 `implement-spec` 开始工作时读取；单项执行和整体负责人共用这份正文。

## 集中开发，收尾验证

以集中实现和调整需求为主。必要测试、验证与构建，由整体负责人在本次授权开发目标或用户明确要求单独交付的阶段收尾时统一安排；内部 Issue、提交或批次结束不自动成为验证节点。完成标准描述应有的行为，不默认逐项写测试、补覆盖率、搭测试框架或反复打包。

开发中按需做定位当前阻碍、启动预览所必需的最小运行或编译。保留已有测试和强制 CI；不可逆的数据删除、迁移等操作，执行前仍须核对对象与恢复办法。需求变化先更新目标，不能为维持过时断言扭曲新需求。

收尾按最终改动选择必要检查，优先复用现有结果；有具体风险才补少量稳定测试，有交付包、部署或编译确认需要才构建。修复后只复查受影响部分，没有新变化不重复运行，不额外生成验证报告。设计原型按 `design-ui` 交付 HTML 与 Token，不自动套用开发收尾流程。

## 职责与事实

单项独立请求由执行者收尾；分配的子任务先交回实现、已有检查记录、阻碍和待收尾事项，由主 Agent 负责整合、集中验证、PR、整体状态与清理，另有明确分工时照分工执行。未经验证仍记为待验证，不把代码完成、提交或构建成功当成业务验收。前后端共用接口与状态的同一来源，交接区分原型、本地模拟与真实接入，不能把模拟成功说成联调完成。

需求、领域定义、技术方案、设计与任务各保留一份有效正文，变化先更新对应来源，再同步受影响内容；路径或命令变化时同步项目索引。只问无法调查解决且会改变目标、业务规则或整体方案的选择，其余部分继续推进。

## 交付与清理

沿用用户授权和项目约定，区分本地修改、提交推送与 PR；保护原工作区和他人修改，只交付本次范围。推送后核对远端提交；PR 按可审查范围创建或更新，不要求与 Spec、Issue 一一对应。只要求推送不追加 PR，只要求 PR 不自动合并或关闭 Issue。

清理前把试用成果和恢复材料保存到清理范围外。移除临时工作树前，确认需保留改动已整合并推送，PR 交付还须确认实际 PR 覆盖；本地交付或尚未推送的代码继续保留。核对路径、归属与本任务进程，只清理可丢弃产物，保留主工作区、他人工作和 PR 远端分支，报告真实残留。

最终说明交付位置、完成范围、实际验证状态、试用入口与剩余问题；维护项目已有的唯一状态入口，区分设计完成、实现待验证、分支可用、主线可用和用户验收。用户要求讲解时，再使用可用的 `explain-work` 或按实际证据说明。
