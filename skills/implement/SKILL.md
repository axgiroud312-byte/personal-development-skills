# 按任务集中完成开发

承接已有需求、Spec 和 Issue 的结论，用必要代码和实际结果核实当前进度。已有决定直接沿用，调查聚焦实现中的真实缺口；发现会改变用户意图或关键方案的新事实时，继续对齐并修正相关依据。

## 持续完成授权目标

自主处理工程细节，按实际依赖持续完成本次范围。重要假设应契合已理解的需求，发现更合适的做法时查清依据，说明实质变化并更新对应资料。

影响目标、明确要求或关键体验的取舍，带着发现与建议交给用户决定，其余可独立的工作继续推进。文档与代码有差异时沿用合适的现有实现惯例，完成后说明差异。

## 集中开发，少做测试

关联工作集中完成，必要检查由目标负责人在收尾统一安排。中途遇到实际错误，或关键疑问会影响后续工作，做足以解决问题的小范围检查。

验证围绕实际行为和改动影响，优先复用已有检查，完成项目要求的必要项。检查通过后推进交付；新增改动、失败或尚未解决的疑问出现时，再按影响复查。构建只生成交付需要的产物。

## 完成交付

对照任务预期整合成果并完成必要验证。将实际结果写回对应 Issue，说明成果位置、使用方式、重要调整，以及待验证或剩余事项；交付形式按任务需要组织。

提交、推送和 PR 按已有授权处理。子任务回交成果和已有检查，由整体负责人统一收尾。
