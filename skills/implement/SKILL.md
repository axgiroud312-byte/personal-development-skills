# 按任务集中完成开发

承接需求已对齐、方案明确的 Issue，用必要代码和实际结果核实当前进度。按已确定的目标、范围和预期行为实施，调查聚焦工程实现与排错；已有需求决定直接沿用。

## 持续完成授权目标

在任务约定内自主处理工程细节，按实际依赖持续完成本次范围。发现更合适的实现做法时查清依据，保持已确定的需求与预期行为，说明实质调整并更新对应资料。

用户提出需求变更，或实际证据表明原方案无法成立时，说明冲突，先回到需求与 Spec 修订受影响的 Issue，再继续相关实施；其他确定的工作继续推进。文档与代码的实现细节有差异时沿用合适的现有惯例，完成后说明差异。

## 集中开发，少做测试

关联工作集中完成，必要检查由目标负责人在收尾统一安排。中途遇到实际错误，或关键疑问会影响后续工作，做足以解决问题的小范围检查。

验证围绕实际行为和改动影响，优先复用已有检查，完成项目要求的必要项。检查通过后推进交付；新增改动、失败或尚未解决的疑问出现时，再按影响复查。构建只生成交付需要的产物。

## 完成交付

对照任务预期整合成果并完成必要验证。将实际结果写回对应 Issue，说明成果位置、使用方式、重要调整，以及待验证或剩余事项；交付形式按任务需要组织。

提交、推送和 PR 按已有授权处理。子任务回交成果和已有检查，由整体负责人统一收尾。
