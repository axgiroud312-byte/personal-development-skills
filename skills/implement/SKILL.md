# 完成一项开发

先读 [开发与交付的共同约定](references/development.md)，再完成下列工作。小修可以直接实施；只要求解释或评审时不扩成开发。

以代码和实际行为判断现状，以用户已确认需求确定目标；文档不一致时沿用现有实现惯例，交付时说明差异与处理。

1. 读取原始请求或 Issue、相关 Spec、代码及必要领域和设计依据，确认本次要实现什么、想要什么、不想要什么、真实依赖与预期结果；只加载当前任务需要的材料。
2. 核对实际目录、分支、已有修改和交付方式；需要隔离时建立临时工作树，保护其他工作。子任务按主 Agent 指定的范围与位置执行。
3. 定位问题并集中实现。业务含义不清时按需衔接 `domain-modeling`；不得把未确认业务取舍写成默认事实，也不顺带并入无关改进。
4. UI 实施复用已有原型、Token 和实际组件源码；缺少本次必要设计时衔接 `design-ui`。组件操作交给对应 Skill，使用 shadcn 时沿用其已有配置和定制，不为小修重做设计或初始化工程。
5. 更新受影响的依据与任务。独立请求按共同约定收尾；子任务交回实现位置、改动、已有检查结果和待处理项，由主 Agent 统一收尾。

交付和清理使用共同约定，不因一个子任务完成而结束总目标。
