# 完成一项开发

负责一项任务的理解、实施与验证。明确的小修直接处理，不为流程补齐讨论、Spec 或领域文档；只要求评审或解释时交付意见。

**以代码实际为主。** 核实现状时以代码和实际行为为依据；文档不一致就沿用现有实现的惯例，完成后列出发现的差异与处理。用户明确提出或已确认的新需求决定本次目标，不能因为尚未实现而忽略。

## 确定交付职责

依据用户当前请求和项目约定，确定本地修改、提交推送或 PR 交付，沿用已有授权，不重复确认常规步骤。只要求提交推送时不追加 PR，明确要求本地修改时在本地交付。

**作为 `implement-spec` 或其他主 Agent 分配的子任务时，只完成分配范围，按约定提交并交回代码、验证结果和阻碍。** PR、跨任务整合、整体状态与临时工作树清理由主 Agent 统一安排；仅在明确分配这些职责时处理，不自行结束总目标。

## 实施与验证

1. 读取任务或原始请求、所属 Spec 与适用共同约定、最新相关讨论、必要代码与领域和设计依据，确认目标、范围、依赖及可观察的验收方法；只读当前任务需要的材料。Issue 驱动项目按需补足任务记录，单纯小修或本地修改不强行补文档。
2. 核对工作目录、分支、已有修改和交付目标，保护其他工作；需要隔离时建立临时工作树并关联实际分支。
3. 复现问题或核对期望，定位原因后实施。业务含义存在缺口时按需使用 `domain-modeling` 或等价梳理；只澄清无法调查解决且影响目标、业务规则或整体方案的选择，其他部分继续推进。具体代码写法自行判断，不并入无关改进。
4. UI 实施复用已有设计板中的页面和交互、对应 Token 说明，以及实际样式与组件源码；缺口按需衔接可用的 `design-ui` 或补齐等价设计，保留其唯一源码。使用 shadcn 时按其 Skill 完成必要操作，沿用已有配置和定制，不为小改动重做整套设计。
5. 对照实际行为完成必要检查，测试和审查按项目设置及风险选择，不机械运行全套测试或生成构建产物。针对关键状态不变量及失败后数据不被破坏，选做必要边界或重启恢复测试。UI 在真实浏览器或目标桌面入口操作，核对关键流程、状态、参考几何及与实际业务行为的一致性。无新改动、失败或未解决问题时不扩大或重复验证；区分实际操作、模拟和未验证部分。

变化更新对应权威依据与受影响任务，路径或命令变化时同步项目索引；引用已有定义与设计，不复制第二套正文或 Token 数值。

## 按约定交付

仅提交本次改动。提交推送交付时核对推送成功和远端包含本次提交；PR 交付再创建或更新正确目标分支的 PR，说明解决后的行为、关联任务、必要改动、验证与剩余问题，并回链任务。

只请求 PR 时保持待评审或待合并，不自动合并或关闭 Issue；其他关闭条件沿用项目约定，单项交付不代表总目标或用户验收完成。子任务按主 Agent 指定的位置交回结果。

## 清理与说明

独立交付或被明确分配清理职责时，先保存试用程序、必要成果和说明到待清理目录以外，确认可访问。移除临时工作树前，确认需保留的改动已整合并推送；PR 交付还须确认实际 PR 覆盖这些改动。只在本地交付或仍有未推送代码时保留承载代码的工作树。

核对真实路径与归属，停止本任务占用临时目录的进程，再清理本次可丢弃的产物和工作树；保留主工作区、他人修改、未交付内容及 PR 使用的远端分支。核对实际残留，失败时如实说明，不为了收尾丢弃恢复材料。

最终提供本地位置、提交或 PR、实际验证、试用入口及清理结果。用户要求“做完后解释”时再按可用 `explain-work` 或等价方式说明结果与原理；该技能不可用不阻塞交付。
