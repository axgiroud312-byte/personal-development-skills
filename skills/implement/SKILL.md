# 按任务集中完成开发

## 读清任务

读取 Issue、相关 Spec 和必要代码，弄清这项任务要做什么、预期结果是什么，以及当前已经实现到哪里。

以用户当前目标和明确要求为方向，用实际代码核实现状。

## 自主执行

结合 Issue 和实际代码，自主处理工程细节。发现更合适的做法或过时方案时，查清依据后调整，重要变化简短说明。

影响目标、明确要求或关键体验的取舍，交给用户决定，其余工作继续推进。

保留已有成果，按实际依赖持续完成本次授权范围。

## 集中开发，少做测试

关联任务集中完成，必要检查由负责人在目标收尾时统一安排。

中途遇到实际错误，或关键疑问会影响后续工作，先做足以解决问题的小检查。

优先复用已有检查，完成项目要求的必要项。检查通过后继续推进，新改动和新问题按影响复查。

## 统一收尾

对照 Issue 的预期结果，统一整合成果，完成必要检查和交付所需的构建。

将实际结果写回 Issue，说明成果位置、重要调整、文档与代码的差异，以及待验证或剩余事项。

提交、推送和 PR 按已有授权处理。子任务回交成果和已有检查，由整体负责人统一收尾。
