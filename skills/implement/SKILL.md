# 完成一项开发

本技能负责单项实施，也是 `implement-spec` 复用的执行方法。先读当前项目入口中已有的技术、任务、设计和交付约定；缺少配置不阻止明确的小修。只要求评审或解释时完成该范围。

`setup-project-skills`、`to-spec`、`to-tickets`、`design-ui` 仅由用户主动调用。读取或维护已有资料不启动这些流程，也不以等价工作另建正式规格、任务或设计版；必要的内部安排和正常 UI 实施继续完成。

以代码和实际行为核实现状，已确认的新需求决定目标。遇到文档与代码不一致时，沿用现有实现的惯例，并在完成后列出发现的差异。

## 开发节奏

以集中开发为主，不默认采用 TDD；必要测试、验证和构建放到本次授权目标或用户明确要求单独交付的阶段收尾，由整体负责人合并安排。Issue、提交和内部批次结束不自动成为收尾。优先复用已有检查，按最终改动和交付需要选择必要项，不默认补覆盖率、建测试框架或反复全量构建。为定位当前阻碍、启动预览所需的最小运行或编译可随时做；保留已有测试和强制 CI，执行不可逆操作前先核对对象与恢复办法。

## 读取依据并实施

1. 读取请求或 Issue、相关 Spec、代码、业务和设计依据，确认本次想实现什么、想要的结果、不想要的扩展及真实依赖。复用已有结论，不强制补建文档。
2. 核对实际目录、分支、已有修改和交付方式，保护其他工作；需要隔离时使用临时工作树。沿用已有授权，区分本地修改、提交推送和 PR。
3. 先形成一条最小可用流程，再补本次其余要求。已有工程沿用真实技术栈与目录；新项目按已定方案建立必需的运行骨架，不为准备工作扩展范围。
4. 前后端沿同一份接口约定贯通请求、校验、数据保存、响应与错误显示。区分原型、本地模拟和真实接入，不能把模拟成功当作联调完成；纯前端、纯后端或准备任务只完成自身范围。
5. UI 实施复用已有设计展示版、确认后的 Token 和实际组件源码，核对设计版与 Token 是否对应，旧 Token 不当作未确认新版的依据；普通实现细节自行补齐。HTML 仅作设计参考，不要求共用原型源码，原型完成也不等于正式前端完成。可按需使用 `design-quality` 指导视觉取舍，不因此生成设计版。指定组件的操作交给可用的专业 Skill，遵守其触发方式并沿用既有配置与定制。
6. 规格变化更新对应 Spec，任务变化更新对应 Issue；路径、命令和开发约定变化更新 `AGENTS.md`。设计变化按原型与 Token 的确认约定同步，工程内部重构不要求重做原型。每项信息只在所属位置维护，不新增术语、领域、状态、讨论或总结文档，也不把它们塞进 Spec 或 Issue。

只询问无法调查解决且影响本次目标、行为或整体方案的选择，不受影响的部分继续，不另设概念梳理阶段。

## 收尾与交接

作为整体开发的子任务，只回交代码位置、已有检查结果、阻碍和待收尾事项；主 Agent 负责整合、验证、PR、任务进度及清理，另有明确分工时照做。

独立任务完成实现后，按本页开发节奏选择最小充分验证：核对关键行为、受影响接口与具体风险，涉及数据保存时按需确认真实写入后能重新读取；必要时补少量回归测试或查看真实 UI。只有交付程序、部署或确认编译结果确有需要时才构建。修复发现的问题后只复查受影响部分；需求变化先改目标，不用过时断言限制新需求。已由用户调用的 `design-ui` 先交设计版供确认，确认该版后再提取 Token，不套用生产验证流程。

## 按授权交付

仅提交本次改动，读回确认推送成功且远端包含成果。PR 交付时创建或更新正确目标分支的 PR，说明行为变化、关联任务、实际验证状态与剩余问题；只要求推送不追加 PR，只要求 PR 不自动合并或关闭 Issue。

清理由独立任务负责人或明确受托者处理：先确认临时工作树中的需保留改动已整合并推送；PR 交付还应确认被实际 PR 覆盖。核对路径、归属和占用进程后，仅清理本次可丢弃内容；保留主工作区、他人修改、未推送代码和 PR 远端分支。本地交付保留承载成果的工作树。修改不另存备份，无法确认可丢弃的内容保持原位。

交付实际位置或提交/PR、试用方式、验证状态、剩余事项和清理结果。区分实现、运行、验证、部署与用户验收，不编造通过结论或额外生成测试报告。有对应 Issue 时在该任务中记录真实结果与剩余事项；没有 Issue 就在聊天中交接，不为收尾新建状态文档或总览 Issue。用户要求讲解时再衔接 `explain-work` 或自行说明。
