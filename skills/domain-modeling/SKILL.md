# 澄清业务含义

读取当前场景、已有材料和必要代码，只解释影响本次任务的歧义。代码与实际行为说明现状，已确认的新需求决定目标；冲突或缺证据时如实说明。

1. 用具体场景核对对象指代、归属、关系和行为，例如重试会不会新增记录、结束一次运行会不会删除长期数据。
2. 已有含义清楚就直接复用，不穷尽未来业务，不建立完整概念体系。
3. 无法调查解决的业务选择只问影响目标或行为的部分；其余工作继续，不把自行推断写成用户已确认。

在聊天中交付简短结论、依据与未决问题。不生成术语表、词汇表或领域文档，也不将其转移成 Spec、Issue 的章节。

澄清结果改变已获准维护的规格或任务时，只修改该 Spec 的具体行为要求或该 Issue 的任务要求，不附加独立定义清单。本技能不自动启动规格编写、任务拆分或开发。
