# 中文开发技能

用中文说明要做什么，Agent 根据任务选择技能。共九个技能：六个开发技能、一个界面设计技能 `design-ui`、一个工作讲解技能 `explain-work` 和一个项目配置技能 `setup-project-skills`，可以分别使用、按需要组合。

设计参考 [Matt Pocock 的 Skills](https://github.com/mattpocock/skills)，内容由用户独立维护。

## 设计哲学

**以代码实际为主：遇到文档与代码不一致时，沿用现有实现的惯例，并在完成后列出发现的差异与处理。** 代码用于判断当前实际情况；用户明确提出或已确认的新需求决定本次目标，尚未实现不能成为忽略需求的理由。各技能都保留这条原则，单独使用也适用。

保持原有职责，按实际需要组合，以实际任务效果为首要验收标准。每个 `SKILL.md` 以 120 行以内为目标，包含文件头与空行；必要规则与示例可按实测结果保留，篇幅服从效果。设计技能详细说明好坏判断，简单技能保留必要说明，避免为了篇幅增删关键内容或堆固定流程。

## 安装

需要 Node.js 22.20 或更新的受支持版本（包含 npm / npx）和 Git，并能访问 npm 与 GitHub。

使用 [Skills CLI](https://github.com/vercel-labs/skills) 从本仓库默认分支安装，无需单独发布 npm 包。安装的是 Agent 的工作方法；React、shadcn 等项目依赖在实际开发时按需安装。

### 给 Codex 安装整套技能

希望各个项目都能使用时，在终端运行：

```sh
npx skills@latest add axgiroud312-byte/personal-development-skills --skill '*' --agent codex -g
```

`--skill '*'` 选择仓库内全部 9 个技能，`--agent codex` 指定 Codex，`-g` 表示安装到用户级技能目录，供多个项目使用。按安装器提示完成安装；安装后在目标项目中开启新会话。

需要建立项目约定时，可以说：“使用 setup-project-skills，为这个项目配置开发约定。”它核实文档、任务和运行入口，在项目的 Agent 入口文件中写入简短项目索引，并配置固定状态入口与维护约定；技能安装由上面的 CLI 完成。已有项目约定足够时，直接提出开发需求。

### 选择项目范围、部分技能或其他 Agent

仅在一个项目使用时，先进入该项目目录，再运行同一命令并去掉 `-g`。希望交互选择技能与 Agent 时运行：

```sh
npx skills@latest add axgiroud312-byte/personal-development-skills
```

交互安装默认针对当前项目；需要全局安装时追加 `-g`。其他 Agent 的标识见 [安装器支持列表](https://github.com/vercel-labs/skills/blob/main/docs/agents.md)。

先查看可安装的技能，不执行安装：

```sh
npx skills@latest add axgiroud312-byte/personal-development-skills --list
```

也可以明确指定技能和目标 Agent。例如，将 Issue、单项开发和整套开发三个技能安装到当前项目，供 Codex 使用：

```sh
npx skills@latest add axgiroud312-byte/personal-development-skills --skill to-tickets implement implement-spec --agent codex
```

### 更新已有安装

从旧版升级到整套新版时，在原来的安装范围重新运行全部技能安装命令。下面以 Codex 全局安装为例，它会取得当前仓库内容，并包含新增的 `design-ui`；已有同名技能会被更新，自己改过安装副本的内容应先保存：

```sh
npx skills@latest add axgiroud312-byte/personal-development-skills --skill '*' --agent codex -g
```

新版已将 `grill-with-docs` 的讨论与记录能力合并到 `grilling`。重新安装不会自动移除已退役的旧技能；曾安装过旧版时，再移除旧入口：

```sh
npx skills@latest remove grill-with-docs --agent codex -g
```

如果旧版安装在项目中，在那个项目目录执行上述两条命令并去掉 `-g`；如果安装给其他 Agent，替换 `--agent` 的值。如果多个 Agent 共用旧技能，还需检查其他安装，安装器可能保留仍被使用的共享副本。移除前核对安装器列出的目标，完成后开启新会话。新安装无需执行移除命令。

## 技能一览

| 你可以这样说 | 对应技能 |
| --- | --- |
| 帮我把这个想法问清楚／边聊边记录 | `grilling`：每题只给问题与两个或更多选项，不附建议或说明，按需记录结论 |
| 统一一下业务术语和关系 | `domain-modeling`：检查并补齐业务定义、关系和规则 |
| 设计一下界面／制作设计板 | `design-ui`：统一负责设计板与 Token，先做页面和交互，再整理实际采用的设计规则 |
| 把需求或 PRD 写成 Spec | `to-spec`：按范围组织一份或多份规格，补齐技术方案、协作与完成标准 |
| 根据这段计划直接拆任务 | `to-tickets`：依据当前目标与相关规格拆分设计、准备和实施任务，细化交付、依赖和验收 |
| 把这个问题修好／完成这项任务 | `implement`：完成单项实施与验证，按授权或主 Agent 分工交付 |
| 按方案把整套功能连续做完 | `implement-spec`：连续推进单份或多份规格下的任务，统一依赖、整合和整体交付 |
| 讲讲刚才做了什么／做完后解释一下 | `explain-work`：解释工作结果、原理与验证范围 |
| 为这个项目配置开发约定／更新项目索引 | `setup-project-skills`：维护 Agent 入口文件里的项目索引，配置固定状态入口与开发约定 |

## 按需要组合

根据已有材料选择需要的工作：需求讨论、业务定义检查、方案与界面设计、任务拆分、实施与验收。各技能按需组合；明确的小修直接实施，不要求完整运行一遍，也不强制每次都建立 PRD、Spec 和 Issue。

`grilling` 负责开放讨论与关键选择，默认一次一个问题，每题只给问题和两个或更多清楚、可区分的选项，不附推荐、理由或额外说明；`to-spec` 直接复用已定需求，只补当前范围内阻止方案定稿的缺口。技术模块设计前核对业务定义，已有领域模型足够时直接引用，不足时按需使用 `domain-modeling` 或等价梳理。事实由 Agent 调查，可逆细节自行判断，只有无法调查解决且影响目标或整体方案的用户选择才提问。

涉及 UI 时，统一由 `design-ui` 与 Spec 往返配合。先在 **`docs/design/design-board.html`** 展示配色、排版、组件、完整页面与必要交互，检查效果后，再把实际采用的颜色、字体、尺寸等整理进 **`docs/design/design-token.md`**。两份成果由同一技能完成；已有设计与项目定制优先沿用，后续开发复用实际样式和组件。具体要求见 [design-ui 主文件](skills/design-ui/SKILL.md)。个人的技术栈、组件与视觉偏好统一维护在全局 `AGENTS.md`，当前任务的明确要求优先。

设计判断单独放在[设计质量参考](skills/design-ui/references/design-quality.md)：说明好设计的依据、坏设计的具体表现，以及哪些必要信息应当保留。`design-ui` 在开始设计和交付检查时读取它。Token 从采用的设计与源码提取，已有变量可先用于制作设计板；shadcn 的初始化、搜索、配置和安装等具体操作交给它自己的 Skill。

**设计任务可以在成果产生前拆分。** `to-tickets` 可先建立设计、调查和环境准备任务，再为依赖它们的页面开发标明阻塞条件。拆页面开发任务时需要足够的设计依据；只要求写 Spec 或拆任务，不自动扩大成整套设计或业务开发。

## 按项目规模组织

| 当前工作 | 组织方式 |
| --- | --- |
| 明确的小改动 | 直接实施，或用一个 Issue 说明范围与验收 |
| 一项较完整的功能、简单项目 | 通常一份 Spec，再按需要拆任务 |
| 包含多项能力的大项目 | 以 PRD 或已有计划为整体依据，划分多份合适的 Spec，再分别拆 Issue |

Spec 按能力、连贯目标与验收边界划分，结合真实依赖和耦合关系决定，不按页面、前后端或字数机械切割。保留当前范围的技术方案、模块协作和完成标准，共同约定只定义一次，相关规格引用；不要求每份 Spec 独立部署。

复用已有 PRD，先细化近期要交付的范围，远期保留概要与依赖；整体计划或已有总览简要标明各 Spec 的位置与关系。当前交付所需方案与设计足够后即可实施，阶段完成后继续已授权范围。小改动保持轻量，不为目录完整建空文档。

## 决定放在哪里

| 记录 | 负责的决定 |
| --- | --- |
| PRD／产品计划 | 整体目标、用户、范围、优先级与阶段安排 |
| 领域记录 | 业务对象、关系、归属、生命周期与规则 |
| Spec／已有整体方案 | 当前范围的技术方案、模块协作与完成标准，以及供相关规格引用的共同接口与约定 |
| 设计说明与设计板 | 设计方向、Token 约定、页面与交互效果、组件复用和查看方法 |
| 共享源码 | 实际 Token 值和共用组件实现；已有源沿用，新设计项目按需建立 |
| Issue | 单项交付、局部接口与状态、依赖、具体验收及任务进展 |

每项决定只维护一份有效正文，其他位置引用；这不限制整个项目只有一份 Spec，也不要求上表每行对应一个文件。发生变化时更新对应来源与受影响规格和任务；业务对象与技术模块不要求一一对应。已有材料够用时不补建重复文档。

## 项目入口与状态

`setup-project-skills` 核实当前项目的文件、命令与必要约定，在 `AGENTS.md` 或 `CLAUDE.md` 中维护一份简短的 `## 项目索引`，只列实际存在的入口和查到的命令。索引指向 PRD、领域、Spec 或规格索引、设计板、Token、组件、任务与状态，不复制正文或进度；路径或命令变化时更新。

项目状态沿用已有入口；没有约定时，有 GitHub 默认使用固定“项目当前状态”Issue，没有 GitHub 用根目录 `STATUS.md`，二者只选一个。README 与项目索引指向同一入口；建立远端入口遵守当前授权，不可用时如实标明待建立。

状态保存核对时间、阶段与范围，以及当前目标、已完成与目前可用、下一步及阻碍、需用户决定的事项。当前主 Agent 汇总，执行者提供任务事实；接手时核对，在关键变化及暂停或结束本轮前更新。区分设计完成、分支可用、主线可用与用户验收；状态依赖正在工作的 Agent，不承诺后台实时刷新。维护约定写入目标项目，配置技能本身不反复承担日常更新。

## 实施与交付

`implement` 负责单项实施与必要验证；独立使用时按当前请求和项目约定选择本地修改、提交推送或 PR 交付。作为整体开发的子任务时，按主 Agent 约定交回代码、提交与验证结果，不自行承担整体 PR 或清理。

`implement-spec` 负责跨任务、跨规格的依赖、分工与整合，持续推进已授权目标，不逐项或逐阶段询问是否继续。主 Agent 统一安排 PR、整体状态与临时工作树清理；PR 按可审查的交付范围维护一个或多个，沿用项目约定，Spec、Issue 与 PR 不要求一一对应。只要求推送时不追加 PR，只要求 PR 时不自动合并或关闭目标。

验收关注具体操作与可观察结果，UI 使用真实浏览器或目标桌面入口，测试与审查按项目设置及风险选择。构建通过、模拟检查、分支试用和用户验收分别说明，不为流程重复测试或生成产物。

清理前保存必要成果与恢复材料；移除临时工作树须确认需保留改动已整合并推送，PR 交付还须核对实际 PR 覆盖。只在本地交付或仍有未推送代码时保留承载代码的工作树，保留主工作区、他人修改和 PR 远端分支，并报告实际残留。

## 工作完成后的讲解

用户要求“做完后解释”或追问刚才的结果时，使用 [explain-work](skills/explain-work/SKILL.md) 说明结果、变化原因、关键运作流程和实际验证范围。讲解可用于开发、设计、配置、文档和研究等工作；只要求解释时依据已有证据说明，必要时补只读检查，不启动新的修改或发布。

## 维护

每个技能的 `SKILL.md` 说明职责、流程和配套文件的读取时机，篇幅遵循上述原则；`agents/openai.yaml` 只保存显示信息与调用策略。需要展开的内容在所属技能内单独维护：

| 技能 | 配套文件 | 用途 |
| --- | --- | --- |
| `to-spec` | [Spec 编写模板](skills/to-spec/references/spec-template.md) | 组织范围、技术方案、规则、依赖与验收，按需附多份规格索引 |
| `to-tickets` | [Issue 编写模板](skills/to-tickets/references/issue-template.md) | 写出可接手的目标、局部设计、依赖、验收与交接信息 |
| `design-ui` | [设计质量参考](skills/design-ui/references/design-quality.md) | 判断好坏设计，指导实际页面与交互检查 |

编写前读取对应模板，设计前与交付检查时读取质量参考。模板提供完整起点，按任务删减或合并，不为填满标题编造内容或创建空文档。用真实任务检查效果，修复可复现的问题，保留原有职责与有效细节。

本轮实际任务、发现的问题、修正与验证边界见[技能验收记录](EVALUATION.md)。

本仓库 `AGENTS.md` 约束技能源文件维护；使用者项目的事实与约定写入对应项目入口。发布主文件、配套参考与显示信息，不上传备份、缓存或目录链接；安装入口可链接到同一份源码，迁移时核对链接。已打开的会话可能仍持有旧上下文，实际行为需在新会话与真实任务中确认。
